<objective>
Check whether openspout/openspout (locked v4.32.0) and chillerlan/php-qrcode (locked 5.0.5) can and should move to their
new majors (openspout v5.13.0, php-qrcode 6.0.1), and upgrade a library only when Composer can resolve it without forcing.

Planning-time evidence (2026-10-30, run in DDEV and on Packagist):
- v4.32.0 and 5.0.5 are the newest releases inside their current majors. `ddev exec composer update openspout/openspout chillerlan/php-qrcode --dry-run` changes nothing.
- `ddev exec composer why-not openspout/openspout 5.13.0` exits 1 and names `filament/actions v5.11.0 requires openspout/openspout (^4.23)`.
- `ddev exec composer why-not chillerlan/php-qrcode 6.0.1` exits 1 and names `filament/filament v5.11.0 requires chillerlan/php-qrcode (^5.0)`.
- Filament v5.11.0 is the newest stable release, and the `5.x-dev` branch keeps the same two constraints.
- Filament is a fixed part of the stack (project brief), so neither upgrade can be done today without forcing, and the
  orchestrator ruled out forcing. The expected outcome is therefore "both stay; documented; no code commit". Task 2 holds the
  upgrade path, which runs only if Task 1's gate finds a library unblocked at execution time.

Purpose: keep dependencies current without breaking Filament's own export/import actions and MFA QR, which are built on
the old majors, and without regressing the formula-injection guard of report exports (RE-03, D-09) or the payment QR (IN-04, D-21).
Output: a per-library decision backed by quoted resolver output. Constraint bumps, a lock update, adapted code and one atomic
commit happen only if the gate passes.
