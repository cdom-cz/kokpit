Facts the planner verified (do not re-research):
- Laravel framework v13.35.0. `Illuminate\Console\Scheduling\Event` has a public bool `onOneServer` (trait
  ManagesAttributes). `CallbackEvent::onOneServer()` throws a LogicException unless the event already has a name, so
  for `Schedule::call(...)` the `->name(...)` call must come BEFORE `->onOneServer()`. `Schedule::job()` names the event
  after the job class itself; a later `->name()` overrides it. Command events need no name.
- The scheduler takes its onOneServer lock in the store returned by `Kernel::scheduleCache()`: config
  `cache.schedule_store`, else the environment variables SCHEDULE_CACHE_DRIVER / SCHEDULE_CACHE_STORE, else the default
  cache store. config/cache.php does not define `schedule_store`; `cache.default` is `env('CACHE_STORE', 'redis')`.
- Existing tests read the schedule with `app(Schedule::class)->events()` (HealthIndicatorsTest helper
  `scheduleEventNamed`, HorizonConfigTest helper `horizonScheduleEventNamed`, NoPruningTest helper `scheduleRuns`).
  HealthIndicatorsTest calls `$event->run(app())` directly on kokpit-heartbeat and kokpit-worker-heartbeat; a direct
  run ignores onOneServer, so those tests keep passing. Heartbeats live in the cache (Cache::forever).

  putenv, so a child `artisan` process started by a test inherits CACHE_STORE=array unless the test passes it.
