<objective>
Prune activity log records older than one year with a nightly scheduled task, using the package's built-in
`activitylog:clean` command with a 365-day retention from `config/activitylog.php`.

This reverses an earlier decision on the owner's explicit request. Phase 03 locked D-09 ("activity records are
kept, no pruning") and plan 03-11 enforced it with a refusing clean action and a test asserting that nothing
schedules the clean command. This quick task supersedes D-09 and the 03-11 decision, and its mitigation T-03-27.
The plan removes that enforcement and replaces it with a working, tested prune. Phase 03 artifacts stay as
history; the supersession goes into STATE.md.

One existing behaviour makes the naive swap silently do nothing. The package action deletes through the Eloquent
`Activity` model, which uses `DeniesPartners`/`PartnerScope`. In a console run with no signed-in user and no system
flag, the scope adds `WHERE 1 = 0`. The delete then removes nothing and still reports success (phase 02 review
WR-04, 02-SECURITY W-3). The new action therefore wraps the package delete in `PartnerContext::runAsSystem()`.

Purpose: keep the audit table bounded and stop keeping personal data in old diffs forever (research Pitfalls 25
and 27), without a silent no-op.
Output: `KokpitCleanActivityLogAction`, config wiring, a nightly one-server schedule entry, `ActivityLogPruningTest`,
the old refusing action and its test removed, and docs plus STATE.md updated.
</objective>

Facts established during planning (do not re-derive):
- spatie/laravel-activitylog 5.1.1. `activitylog:clean {log?} {--days=} {--force}` uses ConfirmableTrait. In
  production, without `--force` and with no interactive input, it returns 1 and deletes nothing. `--days` falls
  back to `config('activitylog.clean_after_days')`. `Config::cleanActivityLogAction()` resolves
  `activitylog.actions.clean_log`, and a custom class must extend `Spatie\Activitylog\Actions\CleanActivityLogAction`.
- The package's `CleanActivityLogAction::execute(int $maxAgeInDays, ?string $logName = null): int` computes the
  cutoff as `Carbon::now()->subDays($maxAgeInDays)` and deletes with `created_at < cutoff` through
  `Config::activityModelInstance()::query()`. That model is `App\Domain\Shared\Models\Activity`, which uses
  `DeniesPartners` and `HasUuids` (UUID v7).
- `activity_log.created_at` is `timestamptz` (`timestampsTz`), app timezone UTC, no FK points at `activity_log`.
- `ActivityLogger::createdAt(DateTimeInterface)` exists in v5, so a test can backdate a row with
  `activity()->createdAt(...)->log(...)` or `activity('some-log')->createdAt(...)->log(...)`.
- `tests/Arch/QueryEscapeHatchTest.php` forbids `DB::table(`, bare `withoutGlobalScopes()` and removal of the Partner
  scope anywhere in `app/` (allowlist intentionally empty). `PartnerContext::runAsSystem()` is the sanctioned escape,
  the same one `RunsAsSystem` job middleware uses. Tests under `tests/` may use `DB::table`.
- Every scheduled event in `routes/console.php` must carry `->onOneServer()` (`ScheduleOnOneServerTest`). Existing
  events use a `kokpit-` name.
- Pest helper functions are global across test files (`scheduleEventNamed` exists in HealthIndicatorsTest,
  `horizonScheduleEventNamed` in HorizonConfigTest). New helpers must use a unique `activityPrune` prefix.
- Fictional data only: log descriptions like "Fictional old entry", log names like `fictional-archive`, no real
  names, e-mails or IDs. Never hand-write UUIDs; let `HasUuids` generate them.
- PHP tooling runs in DDEV: `ddev exec vendor/bin/pest`, `ddev exec vendor/bin/pint`, `ddev composer ci`.
</context>
