<objective>
Contacts get a birth date whose year is optional. The Admin dashboard lists who has a birthday today, with the age they turn when the year is known, and a click on a row opens the contact in a modal. The same list of today's birthdays, with the whole contact, is available over the Sanctum API.

Purpose: the Admin should not miss a client contact's birthday. Contacts are personal data (D-06 of phase 4: Admin-only, closed to Partners by DeniesPartners and AdminOnlyPolicy). Every new surface must therefore stay Admin-only: the card by its AccessRule, the reader by an explicit Admin or system check, and the API by a new, separate `contacts:read` ability.

Output: one migration on contacts, one migration widening the dashboard widget key CHECK, the birthday fields in the contact form and table, a shared reader `ContactBirthdays`, the dashboard card `BirthdaysToday`, the API endpoint `GET /api/v1/contacts/birthdays`, and Pest coverage for each of these.

Design choices made by the planner (record them in the SUMMARY):
- Storage is three nullable `smallint` columns, `birth_day`, `birth_month` and `birth_year`, with CHECK constraints. A `date` column with a dummy year would need a fake leap year and a "year known" flag. Day and month are always set together, and the year needs both.
- "Today" is the Europe/Prague day, the same as in every other dashboard card, taken from `TimerClock::now()`.
- In a non-leap year, a 29 February birthday is listed on 28 February.
- Contacts of archived (soft-deleted) clients are left out, the same as in the client lookups.
- The card is always on the Admin dashboard and is collapsible, with an empty state on days without a birthday. It is full width, right under "Plán na dnešek", so it shows next to the other "today" cards.
- The API uses a new `contacts:read` ability rather than `time:read`. The lookups deliberately reveal only a client's id and name (T-07-36), and time-tracking importers must not gain personal data.
- The endpoint takes an optional `date` (`YYYY-MM-DD`, default today in Prague). It answers that whole day at once without pagination, because one day is a naturally bounded set. The parameter is also the endpoint's real 422 case, which the docs rules (`ApiDocs::statusCodes`) require of every list GET.
</objective>
