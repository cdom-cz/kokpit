<objective>
Make every search a person types ignore diacritics and letter case, and back it with GIN trigram indexes. Today, typing "skola" does not find "Škola", and every search is a sequential scan.

Interpretation of the request (Claude's discretion, since this quick task has no CONTEXT.md):
- Mechanism: one PostgreSQL function, `kokpit_search_text(text)` = `lower(public.unaccent('public.unaccent'::regdictionary, $1))`. It is declared IMMUTABLE, and it is used both by the index expressions and by the queries.
  - `unaccent()` is only STABLE, because the one-argument form finds its dictionary through search_path. The wrapper uses the two-argument form with a schema-qualified function and dictionary, in a SQL-standard body (`RETURN ...`, parsed when the function is created). Its result then depends on the input alone, so IMMUTABLE is honest. Dump and restore also work with an empty search_path.
  - PostgreSQL never inlines an IMMUTABLE SQL function whose body is not immutable. So the call stays exactly as written, and the planner matches it against the index expression.
  - lower() runs after unaccent(), because then the Czech letters are already ASCII and lowering works in any database locale.
- Query shape: `kokpit_search_text(col) like kokpit_search_text(?) escape '!'`. The pattern `%term%` is escaped in PHP, the same way Filament escapes it (`!`, `%`, `_` each get a `!` prefix). Applying the same SQL function to the pattern guarantees that the term and the column are normalised identically.
- Central hooks, so no `->searchable()` call site is edited:
  1. Tables: Filament `Column::make()` resolves the column through the container (`app($columnClass, ['name' => $name])`), so AppServiceProvider binds `TextColumn` to a final subclass. The subclass overrides only `applySearchConstraint()`, and every searchable table column in both panels gets the behaviour.
  2. Global search: Filament calls `static::applyGlobalSearchAttributeConstraint()`, so one trait overrides it. It is used on the three resources that can be searched globally (Client, Project, Task), and a guard test forces any future one to use it.
  3. LinkableTasks calls the shared builder directly.
- Indexes: one GIN index per searched column. A search ORs all the searchable columns of a table, so every one of them needs an index, or the planner falls back to a sequential scan. The verified inventory has 12 columns (see context).
- Rollback: down() drops the indexes and the function but keeps the extensions. `CREATE EXTENSION IF NOT EXISTS` cannot tell whether this migration or an operator installed them. Dropping an extension the migration did not create could destroy objects that are not ours, and a leftover extension changes nothing.
- No CONCURRENTLY: Laravel runs a PostgreSQL migration inside a transaction, where CREATE INDEX CONCURRENTLY is not allowed. The tables of a single-company instance are small.
- Out of scope, with the reason verified while planning:
  - Every searchable Select in app/ is preloaded or built from options(), so its search runs in the browser and never queries the database.
  - The REST API has no text-search parameter.
  - Filament's forceSearchCaseInsensitive() is not used anywhere, and the new mechanism always folds case.

Purpose: the Admin, and a Partner on the Partner's own records, find "Škola" by typing "skola". Search stays fast as the data grows. The Partner boundary stays exactly where it is.
Output: one migration, one shared builder class, one TextColumn subclass with its container binding, one global-search trait used by three resources, the LinkableTasks change, one new Feature test file, one new Isolation case, and two documentation updates.
</objective>
