# Phase quick-261030-l02 Plan 01: Accent-insensitive search with GIN trigram indexes Summary

Typing `skola` now finds `Škola` (and the reverse, in any case) in the Signal task type-ahead, in every searchable Filament table column of both panels and in the admin global search, through one shared SQL expression that 12 GIN trigram indexes cover.

## What was built

- **Task 1** (845f90c): migration `2026_10_30_000100_add_accent_insensitive_search.php` (CREATE EXTENSION IF NOT EXISTS pg_trgm and unaccent WITH SCHEMA public, the IMMUTABLE STRICT PARALLEL SAFE SQL-standard function `kokpit_search_text(text)`, 12 indexes `{table}_{column}_search_index`; `down()` drops indexes and function, keeps the extensions). `AccentInsensitiveSearch` (`where()`, `pattern()`, escape `!`, boolean whitelisted). `LinkableTasks::search()` uses it for the reference, title, project key and project name. README lists the extensions as a requirement. New test file with the database proofs, EXPLAIN index use, rollback and roll-forward, and the guard that no string token in `app/` contains `ilike`.
- **Task 2** (be5fb7d): trait `SearchesGloballyWithoutAccents` overriding `applyGlobalSearchAttributeConstraint()`, used by `ClientResource`, `ProjectResource` and `TaskResource`. Tests for the three groups, the index expression in the logged SQL, the empty Partner answer and a guard that pins the trait to exactly the globally searchable resources.
- **Task 3** (ee8ef98): `AccentInsensitiveTextColumn` (overrides only `applySearchConstraint()`; a call-site search closure, a `->` path or a dotted non-table column go back to Filament), bound to `TextColumn` in `AppServiceProvider::register()`. Tests for the binding, the task, project and client lists, the index use of the filtered task query, and a relationship column without a table context. New Isolation case in `PartnerTaskVisibilityTest`. CONTRIBUTING documents the rule and adds the deploy checklist line for the extensions.

## Deviations from Plan

- **[Rule 3 - Blocking] Function created with `DB::unprepared`** instead of `DB::statement`, to avoid any chance of the `$1` in the body being read as a bound parameter; the project's existing function migrations do the same.
- **[Rule 2 - Correctness] Column delegation is stricter than the plan.** `AccentInsensitiveTextColumn` also hands back to Filament a dotted search column that does not start with the table name (Filament reads it as a JSON path), and any dotted column of a relationship, so the override never changes JSON handling.
- **EXPLAIN in the test uses `toRawSql()`** (the plan's allowed fallback) so no bound parameter reaches the `EXPLAIN` statement.
- The new Isolation case is inside the existing `what a Partner can open` describe, as planned. Each task is one commit (tests and implementation together), because the tests cannot be run in a worktree to show a RED state.
- `actuals.tokens` is recorded as 0: not measured in this run (the plan had `estimate`; no diff-size measurement was taken).

## Production prerequisite

Before the first deploy that carries this migration, the Zerops application role must be allowed to run `CREATE EXTENSION` for `pg_trgm` and `unaccent`, or the service superuser must have created both in the service database. Otherwise the migration fails and the deploy stops before traffic switches (documented in README and the CONTRIBUTING deploy checklist).
