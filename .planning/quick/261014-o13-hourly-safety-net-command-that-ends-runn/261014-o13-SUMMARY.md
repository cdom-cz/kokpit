# Quick 261014-o13: Hourly overrun safety net Summary

**Hourly `kokpit:time:end-overrun` ends every running entry older than 48 h at its start plus 48 h, under the timer lock and a FOR UPDATE re-read, with one console activity row per ended entry.**

## What was built

- `EndOverrunTimers` Action: refuses to run outside a system run (LogicException), selects running entries with `started_at < now - 48 h`, then per entry opens a transaction, takes the owner's `TimerLock` first, re-reads the row `FOR UPDATE` with `ended_at IS NULL`, `billing_state = unbilled` and the start still before the cutoff, and saves `ended_at = started_at + 48 h` through the model (so one `updated` activity row is written, source `console`). No StopTimer, no query-builder update, no raw query.
- `EndOverrunTimersCommand` (`kokpit:time:end-overrun`) wraps the Action in `runAsSystem` and prints one Czech line with the limit and the count only.
- `routes/console.php`: `Schedule::command('kokpit:time:end-overrun')->hourly()->name('kokpit-end-overrun-timers')->onOneServer()`.
- `config/kokpit.php`: `time.max_running_hours = 48` (no env), block comment extended.
- README, CONTRIBUTING and `RepositoryFilesTest` describe and pin the safety net; STATE.md decision added.
