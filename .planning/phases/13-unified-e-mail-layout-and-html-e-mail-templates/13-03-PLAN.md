Decisions carried in (locked): D-05 (a confirmation to the client after every credited payment, card or manual). With `QUEUE_CONNECTION=sync` and `MAIL_MAILER=array` (phpunit.xml) the confirmation of plan 13-06 will leave inside every test that records a payment, so a test that counts all messages of the transport would fail although nothing it checks changed.

Rulings made in this plan (recorded):
- R-13-03-1 (selection, not suppression): a test selects the messages it asserts on by recipient and subject: the document e-mail by the address it was queued to and the subject passed to `QueueInvoiceEmail::handle()` (for example `$defaults['subject']`); an alert by the Admin addresses of the test and the alert subject (the files already keep helpers such as `paMailsTitled()` and `rfMailsTitled()`). The count of the selected messages stays exact (`toHaveCount(1)` stays 1). Selections are positive (keep what the test means); no filter names or excludes the future confirmation, so the files do not depend on plan 13-06.
- R-13-03-2 (scope): every read of the array transport in the seven files is reviewed, not only the reads after a payment, so a later e-mail of any kind cannot change a count. A transport read whose result is not counted or indexed (for example a `flush()`) stays as it is. Per-file helpers stay per file (no shared fixture: plan 13-01 creates `Tests\Support\MailFixtures` in the same wave).
- R-13-03-3 (no bending): no assertion is deleted, no expected count is raised, no fixture drops the client's invoice e-mail, and no test fakes the queue or the mailer to hide an e-mail. Each changed assertion is listed in the SUMMARY with file and line.
