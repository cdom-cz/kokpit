- R-13-01-3 (MailBrand): `App\Domain\Notifications\Mail\MailBrand` is a `final readonly` value class with `name` (string), `street`, `postalCode`, `city`, `companyId`, `vatId`, `email`, `phone`, `website`, `registrationNote` (each `?string`, null when blank), `logoPng` (`?string`), `logoWidth` and `logoHeight` (`?int`, the display size; declared here and left null, plan 13-04 fills them per R-13-04-1), the constant `LOGO_NAME = 'kokpit-logo.png'`, `addressLine(): ?string` (street, then postal code and city, comma-separated, blanks skipped), `hasLogo(): bool`, `static current(): self` (resolves the scoped container binding), `static read(): self` (reads exactly the whitelisted fields of `SupplierSettings` inside `app(PartnerContext::class)->runAsSystem(...)`; `name` is the trimmed `company_name` when not blank, otherwise `config('app.name')`; any `Throwable` gives `fallback()`), `static fallback(): self` (the application name and nothing else). It holds raw values only; labels are translated by the views at render time (R-13-01-4). Bound with `$this->app->scoped(MailBrand::class, ...)` in `AppServiceProvider::register()`, so one read serves one request, console run or queue job and the next job reads again (the scope `PartnerContext` uses).
- R-13-01-4 (labels follow the e-mail): the views print labels through `__('mail_layout.<key>')` when they render, so the locale of each Mailable or notification decides them, not the locale at read time.
- R-13-01-5 (header and footer markup): the header cell shows the name as text (plan 13-04 adds the logo image branch, R-13-04-1), and wraps it in a link only when `website` is set (the `url` prop defaults to null; the stock special case for the word Laravel is removed). The footer prints up to five lines, each only when it has content: the name; `addressLine()`; the company ID and the VAT ID with their `mail_layout` labels; the contacts (e-mail, phone, website joined with a middle dot); the registration note. Every value goes through `{{ }}` (escaped). The published footer component prints its slot as it is, without the Markdown parse of the stock footer, so an asterisk or underscore in a company name stays literal. The `<title>` of the layout is the brand name.
- R-13-01-6 (logo): moved to plan 13-04 as R-13-04-1.
- R-13-01-7 (theme): `kokpit.css` starts from the framework `default.css`: primary button background and border amber `#f59e0b` with dark text `#18181b` (the Filament panel primary is Amber; white on amber fails contrast), success and error buttons kept for the `level` mapping, the system font stack, zinc text colours, the 570 px column, no CSS custom properties, no web fonts, no external URL.
- R-13-01-8 (notification view): the published `notifications::email` uses `mail_layout.greeting` as the default greeting for every level, prints a salutation only when the notification sets one (no default, so a second sign-off under the footer never appears), each line of that salutation escaped and the lines joined with `<br>` (so "regards" and the supplier name can stand on two lines), and its subcopy is `mail_layout.button_fallback` followed by the link, instead of the cs.json sentences of the stock view.
