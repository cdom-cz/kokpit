# Phase 10.1 Plan 08: Currency of an open issued document Summary

**The Admin can now change the currency of an open issued invoice or proforma: time lines are re-priced at the issue date with one rounding, the CNB figures, the bank account, the PDF and the card link follow, and a document with a payment or a credit note keeps its currency (Action and database).**

## Performance

- **Duration:** about 60 min
- **Tasks:** 3 (one tracer, two auto)
- **Files modified:** 10 (1 new)

## Accomplishments

- `TimeLineConversion::freezeAt(Invoice $locked, string $day, bool $again = false, bool $persistTotals = true): bool` is the body of the former `DocumentIssuer::convertTimeLines()` moved without a change of behaviour for `$again = false`; with `$again = true` it also converts lines that carry a snapshot and restores a line whose rate is in the document currency to the exact rate price (`price_converted` false, snapshot null). `DocumentIssuer::issue()` delegates to it and no longer holds a `DraftPreview`.
- `UpdateIssuedDocument` takes `currency`. Before any write, in order: the code must be in the editor's list, then `currency_has_payments`, `currency_has_credit_notes`, `bank_missing` and `cnb_missing` (date of the issue date), all under `currency`. Then the items (if sent) are written in the new currency with placeholder prices, `freezeAt($locked, $issueDate, true)` prices the time lines, the row gets `currency` and `bank_snapshot`, and the Admin-only row gets the trio and CZK total of the issue date (all four empty for CZK). The finisher then reconciles the link as before.
- `PaymentLinks::staleReason()` answers `amount_changed` also when the link's currency differs from the document's, so a number that happens to be equal does not keep a link in the old currency alive.
- Editor: the currency select is editable in issued mode with the existing confirmation dialog (own copy for an issued document), the preview prices a changed currency and the CZK summary with the lists of the stored issue date, the pending bank account is shown, and the refusals of the Action show under the select.
- Tests: new `IssuedCurrencyChangeTest.php` (12 cases) and four editor cases in `IssuedEditorTest.php`; the old assertion that the currency is read-only was reversed.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing handling] `freezeAt()` gained a `persistTotals` parameter**
- **Found during:** Task 1
- **Issue:** the ruling gives `freezeAt($locked, $day, $again)`, which saves the row with the new totals. In the Action that would be an extra save of the invoice row before the final one, producing a second model-history row for a never-sent document and splitting the changed attributes between the two saves.
- **Fix:** a fourth parameter `bool $persistTotals = true`; the issue and plan 10.1-09 call it with the default and behave as the ruling says, the currency change passes `false` and the Action saves the row once.
- **Files modified:** `TimeLineConversion.php`, `UpdateIssuedDocument.php`
- **Commit:** 9826d1d

**2. [Rule 2 - Missing copy] The confirmation dialog of a draft says "konceptu"**
- **Found during:** Task 3
- **Issue:** the existing dialog text is about a draft and does not say that the figures of the issue date, the account and the card link are taken again.
- **Fix:** `invoices.edit_issued.currency_change` copy used in issued mode; the draft copy is unchanged.
- **Files modified:** `lang/cs/invoices.php`, `EditInvoice.php`
- **Commit:** d116292

**3. [Rule 1 - Stale assertion] An older test asserted the currency is read-only in the issued editor**
- **Found during:** Task 3
- **Issue:** `IssuedEditorTest` "offers the dates, the language and the customer lines for editing while the currency stays read-only" contradicts R-10.1-08-4.
- **Fix:** renamed and reversed the currency assertion.
- **Files modified:** `tests/Feature/Invoicing/IssuedEditorTest.php`
- **Commit:** d116292

**4. [Rule 2 - Missing handling] The currency choices were duplicated in the page**
- **Found during:** Task 1
- **Issue:** the Action must accept only a currency of the editor's list (T-10.1-31), and the list was a private method of the page.
- **Fix:** moved to `IssuedDocumentRules::currencyChoices()`; the page calls it, so the list is identical for draft and issued mode.
- **Files modified:** `IssuedDocumentRules.php`, `EditInvoice.php`
- **Commit:** 9826d1d, d116292

**Total deviations:** 4 auto-fixed (1 Rule 1, 3 Rule 2). **Impact:** none on scope; one extra parameter, two copy keys and one shared helper. Task 2 is a tests-only commit because the refusals were part of the tracer implementation.
