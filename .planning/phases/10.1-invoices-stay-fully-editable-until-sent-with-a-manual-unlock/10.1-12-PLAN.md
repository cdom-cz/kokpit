Decisions carried in (locked): D-01 (only a successfully sent e-mail locks; a queued or sending one does not, so the document stays open and A8 decides that an edit waits for it), D-04 (edits with payments or credit notes allowed, a warning when totals fall below paid or credited, no hard block), D-13 (every change to an issued document after its first send audited with who, when, before and after; never-sent documents behave like drafts).

Assumptions adopted as the planned default (owner to confirm before execution; moved here from plan 10.1-04 unchanged):
- A8: an edit is refused while an e-mail of the document is `queued` or `sending` and younger than `kokpit.health.unsent_invoice_email_stale_after` seconds (by `updated_at`); an older row counts as failed, so it never blocks forever; if such a stale row is still sent later, it attaches the PDF linked at that moment (the edited one) and locks the document.
- A12: the explicit edit rows carry item texts and party data in the Admin-only log (values cut to 80 characters by `ActivityPresenter`), an owner-approved exception to the T-10-30 "free text is never logged" precedent; the bank snapshot, the pay token and the internal note are never in the payload.

Rulings carried from plan 10.1-04 and implemented here (ids unchanged, recorded):
- R-10.1-04-2 (completion): `IssuedDocumentRules::editBlocker()` appends `email_in_flight` (A8) as the last reason after those of plan 10.1-04: an `invoice_emails` row of the document in state `queued`, or in state `sending` with `updated_at` younger than `config('kokpit.health.unsent_invoice_email_stale_after')` seconds. `warnings(Invoice $invoice): array<string, Money>` returns `total_below_paid` (the paid amount) when paid exceeds the total and `total_below_credited` (the credited amount) when credited exceeds it, both read through `InvoiceBalances::for()`; it never throws.
- R-10.1-04-3 (audit part): in `UpdateIssuedDocument::handle()`, `$before = InvoiceAudit::snapshot($locked)` right after `IssuedDocumentRules::assertEditable()`; the row is saved after `disableLogging()` when `InvoiceAudit::everSent($locked)`; `IssuedEditFinisher::finish($actor, $locked, $before)` is called with the snapshot.
- R-10.1-04-4 (step 4): `IssuedEditFinisher::finish(User $actor, Invoice $locked, array $before): void`; order (1) CZK total, (2) the card link step (plan 10.1-05), (3) `ReplaceIssuedPdf::handle()`, (4) `InvoiceAudit::edited($locked, $actor, $before)`. The one caller of the two-argument form (`UpdateIssuedDocument`) is updated in the same commit.
- R-10.1-04-7 (queue lock, A8): `QueueInvoiceEmail::handle()` reads the document with `lockForUpdate()` before writing the queued row. Plan 10.1-10 later moves that read into a protected seam without changing behaviour.
- R-10.1-04-8 (audit, D-13): `InvoiceAudit::snapshot(Invoice $invoice): array<string, string|int|null>` flattens `currency`, `language`, `issue_date`, `taxable_supply_date`, `due_date`, `note`, `total_minor`, `customer.<name|street|city|postal_code|country|company_id|vat_id>`, `supplier.<name|street|city|postal_code|country|company_id|vat_id|email|phone|website|registration_note>`, `items.<position>.<description|quantity|unit|unit_price_minor|line_total_minor>` and `entries` (the number of linked time entries); `everSent(Invoice $invoice): bool` (an `invoice_emails` row in state `sent` exists); `edited(Invoice $invoice, User $actor, array $before): void` writes one row `activity('invoice')`, event `invoice_edited`, `withChanges` holding only the keys whose value changed, and nothing when nothing changed or the document was never sent.

The copy `invoices.errors.email_in_flight`, `invoices.warnings.total_below_paid` and `invoices.warnings.total_below_credited` is already written by plan 10.1-04 (R-10.1-04-9); this plan does not touch `lang/cs/invoices.php`.
