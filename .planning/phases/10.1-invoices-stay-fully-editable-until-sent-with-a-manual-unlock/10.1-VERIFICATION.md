# Phase 10.1: Invoices stay fully editable until sent, with a manual unlock - Verification Report

**Phase Goal:** Admin can correct an issued invoice or proforma (items, dates, customer and supplier data, bank account, currency, language and linked time) until a successfully sent e-mail locks it, and can unlock a sent document with a recorded reason; number and kind never change, credit notes stay locked, the database enforces the lock, and every post-send change, lock and unlock is audited
**Verified:** 2026-10-23T18:00:00Z
**Status:** gaps_found
**Re-verification:** No - initial verification

## Summary of the verdict

The five roadmap success criteria are met in the code and are proven by green tests (full suite run in DDEV: 6603 passed, 3 skipped, 0 failed). The phase goal as written is achieved except for the clause "every post-send change ... is audited": one class of change (bank account only) is not audited (IN-15 partial). In addition the open code review finding CR-01 (critical) is confirmed by reading the code: relaxing the payment-link currency key, which the phase did on purpose, exposed a pre-existing webhook comparison that no longer protects the booked currency. CR-01 is a money-handling defect created by a phase change at a seam the phase did not edit; it is recorded as a gap and should be closed before the milestone relies on the card flow. The two gaps are small and local (a one-line condition plus a test; a bank marker plus a test).
