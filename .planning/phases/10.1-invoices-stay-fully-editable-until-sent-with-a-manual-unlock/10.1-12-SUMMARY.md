# Phase 10.1 Plan 12: Edit audit, in-flight e-mail rule and warnings Summary

**Every edit of an issued invoice after its first send leaves one Admin-only `invoice_edited` row with the values before and after, an edit waits for a queued or live sending e-mail while the queue takes the same invoice row lock, and a total below what was paid or credited warns instead of blocking.**

## Performance

- **Duration:** about 35 min
- **Tasks:** 3
- **Files modified:** 7

## Accomplishments

- `InvoiceAudit::snapshot()` flattens currency, language, the three dates, the printed note, the total, the customer and supplier lines, every item by position (`items.<position>.<field>`) and the entry count into `key => scalar`. `edited()` writes one `activity('invoice')` row, event `invoice_edited`, with only the keys whose value changed, and nothing for a never-sent document or an edit that changes nothing. `everSent()` is an `invoice_emails` row in state `sent`.
- `UpdateIssuedDocument` takes the snapshot right after `assertEditable()` and saves the row with `disableLogging()` once the document was ever sent (re-enabled afterwards), so the explicit row is the only history of that edit. `IssuedEditFinisher::finish($actor, $locked, $before)` runs the audit as step 4, after the PDF replacement; the only caller was updated in the same commit.
- `IssuedDocumentRules::editBlocker()` appends `email_in_flight` as the last reason (queued, or sending with `updated_at` younger than `kokpit.health.unsent_invoice_email_stale_after`); older sending rows and failed rows do not block. `warnings()` returns `total_below_paid` and `total_below_credited` as `Money` through `InvoiceBalances`, never throwing.
- `QueueInvoiceEmail::handle()` reads the document with `lockForUpdate()` before writing the queued row, the same lock `SendInvoiceEmail` and every edit take.
- Tests: new `InvoiceEditAuditTest.php` (6 tests) and 7 new cases in `UpdateIssuedDocumentTest.php`.
