Assumptions adopted as the planned default (owner to confirm before execution):
- A3: a cancelled invoice and a proforma that already has its invoice take no time changes even when open (the helper below says so in the database too).
- A7: a currency change stays impossible once a payment exists (the payments key is kept); a link row records the currency it offered and never changes.

Rulings made in this plan (recorded):
- R-10.1-03-1 (helper): `kokpit_invoice_accepts_time_changes(document uuid) RETURNS boolean LANGUAGE plpgsql` (volatile, because it reads `FOR SHARE`): true when the document is a draft, or when it is `issued`, `lock_state = 'open'`, of kind `invoice` or `proforma`, no issued credit note with `cancels_invoice` names it, and no invoice names it as `proforma_id`; false for a missing document.
- R-10.1-03-2 (link guard): `CREATE OR REPLACE FUNCTION kokpit_guard_time_entry_link()` keeps every branch of `2026_10_17_000500_link_time_entries_to_invoices.php` except two. Reservation (unbilled -> unbilled with a new link): refused unless `kokpit_invoice_accepts_time_changes(NEW.invoice_id)`, message 'a time entry is reserved only by a draft or by an issued document open for changes'. Unbilling (billed -> unbilled): the link must go (unchanged), and the release of a document link is accepted when an issued storno credit note cancels the document (unchanged) or when `kokpit_invoice_accepts_time_changes(OLD.invoice_id)`, message 'time billed by a document is released only while the document is open for changes or after an issued storno credit note cancels it'. The INSERT branch stays draft only; billing still needs the document issued; the proforma-to-invoice move and the frozen snapshot are unchanged. The trigger `time_entries_link_guard` is not re-created. `down()` restores the Phase 10 function body verbatim and drops the helper.
- R-10.1-03-3 (payment links): drop `payment_links_invoice_currency_fk`, add `payment_links_invoice_fk FOREIGN KEY (invoice_id) REFERENCES invoices (id)`; `CREATE OR REPLACE FUNCTION kokpit_guard_payment_link()` with the body of `2026_10_18_000400_create_payment_links_table.php` plus, in the INSERT branch, the document currency read `FOR SHARE` with the state and kind and `RAISE ... 'a payment link is created in the currency of its document' USING ERRCODE = 'KP001'` when they differ. `down()` refuses with a RuntimeException while any link names a currency its document no longer has (the composite key could not be restored), otherwise restores the composite key and the previous body. `invoice_payments_invoice_currency_fk` is not touched.
