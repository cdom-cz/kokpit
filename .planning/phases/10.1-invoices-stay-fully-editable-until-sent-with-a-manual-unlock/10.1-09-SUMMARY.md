# Phase 10.1 Plan 09: Linked time on an open issued document Summary

**Time moves on and off an open issued invoice or proforma exactly as on a draft: new time is claimed, billed at once and priced at the issue date, released time returns to unbilled, a fixed amount brings its fixed-price hours, and every move ends with the CZK total, card link, PDF and audit steps.**

## Performance

- **Duration:** about 75 min
- **Tasks:** 3 (one tracer, two auto)
- **Files modified:** 15 (1 new)

## Accomplishments

- `AddEntriesToDraft`, `ReleaseEntries` and `AddFixedAmount` keep their names and signatures and decide the lifecycle on the locked row (R-10.1-09-1): a draft follows the existing path, an issued document runs `IssuedDocumentRules::assertEditable()` and the issued path, anything else keeps `not_draft`.
- Add time (R-10.1-09-2): claim through `EntryReservation::claim()`, lines built by `TimeItemGrouping::lines()` for the stored issue date, appended by `DraftLines::appendTime()`, new foreign-rate lines frozen by `TimeLineConversion::freezeAt($locked, $issueDate, false, false)`, the claimed rows billed in id order with `EntryBilling::bill()`, totals refreshed, `IssuedEditFinisher::finish()`.
- Release (R-10.1-09-3): the requested entries of this document are locked in id order and freed with `EntryBilling::release()`; the lines are untouched; the finisher records the drop of `entries` in the audit row after the first send.
- Fixed amount (R-10.1-09-4): the line is appended, with `link_time` the fixed-price entries are claimed and billed at once (no rate snapshot).
- UI (R-10.1-09-5): `InvoiceEntriesRelationManager::isReadOnly()` is true unless the document is a draft or `isEditable()`; the toast of an issued add or release carries "Změny jsou uložené. PDF bylo vytvořeno znovu, doklad nebyl odeslán." and the detail page renders again; the issued editor shows both buttons and keeps the time tab as its only tab; `time.errors.invoice_locked` points at the invoice.
- Tests: new `IssuedTimeEditTest.php` (12 cases); five older tests that assumed an open issued document is read-only for time were moved to a locked document.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] The detail page showed stale lines and totals after a time change**
- **Found during:** Task 1
- **Issue:** `ViewInvoice::reloadAdminHalf()` (the listener of `invoice-payment-saved`) reloaded only the Admin-only half, so after an add or release on the open document the page kept the old totals and lines. The plan names the existing event but not this reload.
- **Fix:** `reloadAdminHalf()` also re-reads the three total columns and the `items` relation.
- **Files modified:** `app/Filament/Resources/InvoiceResource/Pages/ViewInvoice.php` (not in the plan's file list)
- **Commit:** 38fc88c

**2. [Rule 3 - Blocking] The issued editor had no component to receive "Přidat nový čas"**
- **Found during:** Task 2
- **Issue:** the editor button dispatches `draft-add-time` to the time tab, but an issued editor mounted no relation manager at all.
- **Fix:** `EditInvoice::getRelationManagers()` keeps only `InvoiceEntriesRelationManager` in issued mode (payments, e-mails and history stay on the detail).
- **Files modified:** `EditInvoice.php`
- **Commit:** 7923de3

**3. [Rule 1 - Stale assertions] Tests assumed an open issued document is read-only for time**
- **Found during:** Tasks 1 and 2
- **Issue:** `InvoiceDetailTest`, `DraftEditorTest`, `DraftTimeAdditionsTest` (two) and `ReleaseEntriesTest` asserted `not_draft` or a read-only tab for a document that is open.
- **Fix:** they now use a locked document (`InvoiceFixtures::lock()`), expect the `document` field error, and the open case is proved in `IssuedTimeEditTest.php`.
- **Commit:** 38fc88c, 7923de3

**4. [Rule 2 - Consistency] The unused key `invoices.unlock_refusal` carried the old text**
- **Found during:** Task 3
- **Fix:** same new copy as `time.errors.invoice_locked`; the key has no caller.
- **Files modified:** `lang/cs/invoices.php`
- **Commit:** e9b177b
