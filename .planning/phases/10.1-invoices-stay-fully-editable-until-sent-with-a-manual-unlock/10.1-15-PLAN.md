<objective>
Close review finding WR-01 (recommended by the verifier for this round): a `queued` document e-mail row whose job was lost keeps `editBlocker()` at `email_in_flight` forever, the editor and the four issued write paths refuse, nothing in the UI recovers it, and unlocking does not help because the block is independent of the lock.

Purpose: success criterion 4 says an edit never interleaves with a queued or sending e-mail; it must not turn into "an edit is never possible again". The fix applies the existing stale rule of a `sending` row (ruling R-37-1, the threshold of the System page) to a `queued` row, and makes the job honour what the screens say: a row read as failed is never sent late.
Output: `InvoiceEmail::staleBefore()`; the aged queued rule in `IssuedDocumentRules::emailInFlight()`; the claim under the invoice row lock and the stale give-up in `SendInvoiceEmail`; the stale queued reading of the Odeslání tab; tests.

Decisions carried in (locked): D-01 (only a successfully sent document e-mail locks; a queued, sending or failed one does not), D-10 (after an edit nothing is sent automatically; the Admin re-sends by hand). Assumption A8 of plans 10.1-04/10.1-12 (an edit waits for a queued or live sending e-mail; the queue and the edit share the invoice row lock) is refined here, not reversed: the wait ends for a queued row at the same threshold as for a sending row.

Design choice made by this plan (Claude's discretion, flagged in the planning return): a queued row older than the threshold is given up by the job (failed, class `stale`, one bell notice) instead of being sent late. Reason: once the row reads as failed, the Admin is offered "Odeslat znovu" and may edit the document; a late send of the old request would then be an automatic send after an edit (against D-10) or a second copy of a resend. The threshold is `kokpit.health.unsent_invoice_email_stale_after` (3600 s); a normal queue sends within seconds and a retry puts the row back to queued with a fresh `updated_at`, so only a lost job or a worker that was down longer than the threshold reaches it. Reversibility: reversible (code and one config value); a row given up this way is resent by the Admin.

Left unchanged on purpose: `UnsentInvoiceEmailsIndicator` (System page) and the e-mail filter of the invoice list. The list filter reads the stored state only (a stale `sending` row already shows under "queued" there today), and the System page link must open a list that contains the row: a stale queued row keeps showing as waiting (Warning, link to the queued list) until the Admin resends it from the document, where the Odeslání tab reads it as failed. Changing the grade to Error would point to the failed list, which does not contain the row.

No new probe predicates were generated for this gap-closure run (spec-less probe fallback skipped visibly). Assumption-delta and API-coverage checkpoints: scanned, not detected.
