Decisions carried in (locked): D-08 (ZIP kept 7 days on private storage, deleted by the scheduled prune, idempotent job); plan 09-18 decision (prune deletes object first, then the record; a missing object is fine); plan 09-19 decision (permanent failures fail the record with a bell, read errors throw and `failed()` gives up after the retries).

Decisions made in this plan (recorded):
- The object path of an archive is `DocumentArchive::storagePath()`, a pure function of the record id and the exact shape the database pins for `path` (`document-archives/<uuid>.zip`). The prune deletes it for every expired record whatever the status (09-REVIEW.md WR-02 fix sketch).
- The build job removes the ZIP of a record that is gone or failed through `DB::afterCommit()` registered inside the deciding transaction, so the object goes only once the failed state (or the absence of the record) is committed; this is the same "database first, object after commit" order plan 09-27 introduces for document deletion (WR-01).
- A record found `Ready` in the final transaction of a run keeps its object: the path is shared by every run of the same id, so that object is the finished archive of the concurrent run. A record still `Pending` is the normal case and is marked ready.
- A failing removal in the job is reported without the path and swallowed; `failed()` and the mark-failed transaction must complete, and the prune removes the object later.
