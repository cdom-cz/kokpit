Decisions made in this plan (recorded):
- The CZK rule uses `ExchangeRateConverter::rateFor()` once and `Money::convert($rate, 'CZK', $unitAmount)`, the arithmetic of `toCzk()`, so the exact rate, unit amount and list date used are stored (research Pattern 7). The CONTRIBUTING hand-over note that named `toCzk()` is updated in plan 09-20.
- A future date converts at the newest stored list (the converter's "not after the day" rule) and counts as `cnb` (research A15).
- Currency options are CZK plus every currency with at least one stored CNB row; validation re-checks the same rule.
- Manual stays manual (research Pitfall 13): the input flag `czk_manual` is the only way back to computed; while manual, a change of date, currency or amount keeps `czk_minor`.
- Transactions are hard-deleted; there is no archive state for them (research Open Question 6, D-14 "deletable", D-21).
- `CzkSource` and its Czech labels live here (`lang/cs/enums.php`); the table and model came from plan 09-09, which kept `czk_source` a string until now.
- Error messages come from the `finance.transactions.errors.*` contract written by plan 09-06; this plan does not edit `lang/cs/finance.php`.
- New at plan check (scope): this plan takes the domain half of the former 16-file plan 09-09 and the update and delete Actions of the former 14-file plan 09-11, so both fit their budgets without a longer wave chain.
