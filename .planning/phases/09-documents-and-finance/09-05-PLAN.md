Decisions made in this plan (recorded):
- `#[AccessRule]` is not inherited, so the behaviour is a trait and every host has its own final class with its own attribute (research structure, PATTERNS).
- The client tab lists every file of the client through `Client::documents()` (by `client_id`) with an owner column (research A10); uploads there are client-owned and always hidden.
- Download and preview are actions that compute `DocumentUrl` on click and redirect (same tab); nothing is rendered into a link with a TTL (plan 09-03 decision).
- Rename, the visibility toggle and delete are plan 09-07; the transaction tab is plan 09-13.
- `kokpit.tasks.attachments.*` keys stay until plan 09-20 removes unused copy; this plan only removes the section that used them.
- Copy contract: this plan writes every tab key that the Partner tabs of plan 09-08 read (`relation_title`, `columns.*`, `actions.download`, `actions.preview`, `partner_empty.*`), so plan 09-08 does not edit `lang/cs/documents.php`.
- Archived owners on the Admin tabs (D-21): D-21 governs the Partner view and the default central listing; an Admin who opens an archived project, task or client still sees its files on that owner's own Soubory tab, and the client tab keeps listing files of the client's archived projects and tasks with their owner. Uploads to an archived owner stay refused (plan 09-02).
- Tests fill the `files` field per file through Filament's action data, which uploads each file on its own like the browser; under the production temporary-disk setting pinned by plan 09-24, Livewire refuses one call with a list of files (`S3DoesntSupportMultipleFileUploads`).
- Not split at plan check (warning, optional): every split of this plan's 14 files puts a file into the same wave as another plan that edits it (`DocumentColumns` with plan 09-08, `DocumentsRelationManagerTest` with plan 09-07, `lang/cs/enums.php` with plan 09-22 in wave 4) or adds a wave; 14 files stay under the 15-file limit.
