Decisions carried in (locked): D-01 (one `documents` row per file with exactly one media; name, description, flag, optional owner morph, denormalized `client_id`, uploader; queries go over `documents`; reversibility costly), D-03 (flag defaults true on project and task files; client, transaction and unattached files never visible; the DB rule is scope plus policy), D-04 (Partner sees a file only on an accessible project or its task, flagged visible, not of an internal comment, never another client's), D-06 (10 MB, value in `config/kokpit.php`), D-08 / D-10 (archive retention and short TTL values in `config/kokpit.php`).

Decisions made in this plan (recorded):
- Owner aliases are the morph aliases `client`, `project`, `task`, `task_comment` (Phase 9 plan 09-13 adds `transaction`, Phase 10 `invoice`); the owner type list is NOT a CHECK list, rule R9 already checks stored morph types against `MorphMap` (research Pattern 1).
- A denormalized `project_id` sits next to `client_id`, tied by the composite FK `(project_id, client_id) -> projects (id, client_id)`, which needs the new `projects_id_client_unique` (research A12). Transactions (09-09) reuse that unique key.
- Comment files default to visible on a non-internal comment and are forced hidden on an internal one; the Admin can toggle a non-internal comment's file later (D-20, owner decision at plan check).
- Archived owners (D-21): the Partner scope delegates to the Partner-scoped Project, Task and TaskComment queries without `withTrashed()`, so archived projects, archived tasks and projects of archived clients drop out on their own; the Admin-side archived-owner scopes and the archive and restore proof are plan 09-21.
- The owner of a document is immutable after upload (research A11); only a transaction's client can change, handled in 09-13.
- `Media` stays `DeniesPartners`; every media write and read runs inside `PartnerContext::runAsSystem()` after the policy check (research Pitfall 3).
- Assumption-delta checkpoint (advisory, detector fired on "another client's files" and "also removes its stored object"): primary noun = the `documents` row; decision `promote` - the document is the identity of a file and the media row is demoted to a storage detail of that one variant (D-01 owner decision). No second identity is added alongside.

Fictional data only: file names and contents in tests are assembled at runtime from fragments (`DocumentFixtures`). Run `scripts/check-sensitive.sh` before every commit; never bypass the hook.
