Decisions carried in (locked): D-21 (archiving a client, project or task hides its files from the Partner view and from the default Admin listing, which shows them under an "archived owners" filter; restore brings them back; archiving never deletes stored objects; real deletion only by explicit file delete and by deleting a transaction; amends D-09), D-01 (one documents row per file with one media), D-03 (client, transaction and unattached files never visible; the DB rule is scope plus policy), D-04 (Partner rule).

Decisions made in this plan (recorded):
- A document is a file of an archived owner when its owner type is `client`, `project`, `task` or `task_comment` and at least one of these holds: its `client_id` names an archived client; its `project_id` names an archived project; it is a task file whose task is archived; it is a comment file whose comment's task is archived. Unattached files and (from plan 09-13) transaction receipts never are: D-21 names clients, projects and tasks, transactions are never archived, and receipts are finance records that must stay findable.
- Both scopes are plain `EXISTS` subqueries on `deleted_at` of `clients`, `projects`, `tasks` and `task_comments` joined to `tasks`, in the style of `Project::constrainForPartner()` and `Project::scopeSelectable()`. They do not go through the `Client` model (closed to Partners) or the SoftDeletes scopes, which would hide the archived rows the check looks for. `QueryEscapeHatchTest` must stay green.
- The Partner scope of plan 09-01 needs no change: it delegates to the Partner-scoped Project, Task and TaskComment queries, which leave out archived rows; this plan proves it per owner kind and proves the restore.
- Owners are archived and restored the way the application does it: `ArchiveClient` / `RestoreClient`, the project archive and restore of `ProjectResource` (a soft delete and `restore()` of the project), `ArchiveTask` / `RestoreTask` as the Admin.
- Not here: the Admin Soubory tabs of plan 09-05 keep listing an archived owner's files on that owner's own page; the central listing hides them by default and shows them under the "archived owners" filter (plan 09-14); storage totals count them with a label (plan 09-16); `DocumentOwnerDeletionTest` (plan 09-13) asserts again that archive and restore leave rows, media and objects intact.
