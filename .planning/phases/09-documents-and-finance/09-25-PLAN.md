<objective>
Close the only verification gap of Phase 9 (09-VERIFICATION.md, ROADMAP success criterion 3, DO-02; code review finding CR-01): `ArchiveEntryNames::unique()` reads an unset counter when a later document is named like a number it handed out before (`a.pdf`, `a.pdf`, `a (2).pdf`), the queue worker turns the warning into an `ErrorException`, and the background ZIP of such a selection fails on every attempt with only the failure bell.

Purpose: make "Admin downloads single files or a ZIP built in the background" true for every selection, with a regression net that covers every order of names, not only the orders that happened to work.
Output: the two-line fix in `ArchiveEntryNames::unique()` from 09-REVIEW.md CR-01, a queued end-to-end feature test of the CR-01 file set in both orders, and unit regressions including an all-permutations invariant.

The DDEV browser pass (human verification item 1 of 09-VERIFICATION.md) builds a ZIP from the central listing and downloads it from the bell link; it should be run after this plan has landed. It stays a human item and is not a task here.
</objective>

Decisions made in this plan (recorded):
- The fix is the one sketched in 09-REVIEW.md CR-01: the counter of a taken key is read with a default of 1, and every name `unique()` hands out, a numbered candidate included, is registered in `$taken` and gets its own counter of 1. - `BuildDocumentArchive` is not changed: a total `unique()` needs no guard, and a try/catch around it would turn a later regression into a silent rename or a skipped file.
