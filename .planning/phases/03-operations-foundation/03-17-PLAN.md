<objective>
Prove that private S3-compatible storage works from configuration alone: harden the `s3` disk, add the `kokpit:storage:check` command (upload, fetch through a temporary URL, refuse an unsigned read, delete) for servers, and run the same check as tests against RustFS locally and in CI (D-17).

Purpose: FND-16. Documents, invoice PDFs and receipts (Phases 9 and 10) live on this storage; a silent write failure or a public bucket would lose or leak them.
Output: the S3 driver package, the storage check service and command, a test disk helper, s3-group tests, the RustFS CI service and its parity test.
</objective>

Verified before planning: `.env.example` already documents `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` (the public RustFS development default), `AWS_DEFAULT_REGION`, `AWS_BUCKET`, `AWS_USE_PATH_STYLE_ENDPOINT=true`, `AWS_ENDPOINT=http://rustfs:9000`; `config/filesystems.php` reads them for the `s3` disk with `'throw' => false`; DDEV runs `rustfs/rustfs:1.0.1` with a bucket-creating init container; the CI `tests` job copies `.env.example` to `.env` (`scripts/boot-from-env-example.sh`), so only `AWS_ENDPOINT` needs a job-level override to `http://127.0.0.1:9000`; `ci-passed.needs` lists every job and `scripts/tests/test-workflow.sh` enforces it, so the service goes into the existing `tests` job.

Tests use their own bucket `kokpit-test` (created by the helper with the S3 client if missing), never the development bucket. The research run against RustFS 1.0.1 observed: put about 110 ms, temporary URL fetch with exact bytes, expired URL 403, anonymous GET 403, delete works; the default checksum behaviour of the SDK worked.

Supply chain: `league/flysystem-aws-s3-v3` (and the transitive `aws/aws-sdk-php`) are Approved in the research Package Legitimacy Audit; MIT and Apache-2.0 pass the licence allowlist.

Hygiene: the scanners flag hosting and S3-provider endpoint hostnames; use only `rustfs`, `127.0.0.1` and `localhost` endpoints in code, tests and the workflow. Never bypass the hook.
