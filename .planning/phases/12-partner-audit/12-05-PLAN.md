Draft cell rules for the declaration (the executor writes all 38 rows literally, following these rules; every deviation goes into the SUMMARY with its reason):
- Partner-readable set P = Project, Task, TaskComment, Document, Invoice, InvoiceItem, Tag, CanaryRecord. Every other entity is Admin-only.
- ui: `foreign` for P, `none` for every other entity.
- search: `foreign` for CanaryRecord (its test resource is searchable for the own rows), `none` for every other entity (only the Admin-only Client, Project and Task resources opt in to global search).
- selects: `foreign` for Project (the Partner task form offers the own visible projects), `none` for every other entity.
- api: `none` for every entity (the API is Admin-only; a Partner token gets 401).
- notifications: `foreign` for Project, Task and TaskComment, `none` for every other entity.
- activity: `none` for every model in `AuditDeclaration::loggingModels()` and for Activity; not applicable otherwise, reason "writes no activity rows: not in AuditDeclaration::loggingModels()".
- downloads: `foreign` for Document, Invoice and InvoiceItem; `none` for DocumentArchive, ReportExport, Media and TimeEntry; not applicable otherwise, reason "no file is stored for or generated from this model; files leave only through the document, archive, invoice PDF and report export routes".
- exports: `none` for TimeEntry, ReportExport, DocumentArchive, Document, Client, Project, ProjectBilling, Task, TaskBilling, Invoice, InvoiceItem, Transaction and TransactionCategory; not applicable otherwise, reason "no export reads this model".
- When unsure whether a channel can reach an entity, declare it applicable: the check is cheap and a wrong not-applicable cell hides a leak.

Rulings made in this plan (recorded):
- R-12-05-1 (shape): `const array CHANNELS = ['ui', 'search', 'selects', 'exports', 'notifications', 'activity', 'downloads', 'api']`; `entities()` returns `model class => [channel => 'foreign' | 'none' | ['na' => reason]]`; `cells(list<string> $channels)` returns the applicable cells of those channels as `"{ShortModel} x {channel}" => [model, channel]` (plain arrays for the Pest dataset, research Pitfall 4); `problemsIn(array $entities)` and `problems()` return `list<string>`.
- R-12-05-2 (probe): `ChannelProbe::seed()` sets the admin panel, calls `CanaryRegistry::prepare()`, creates two clients and two canaries, `seedAll` for both, creates Partner A (`Canary::partnerFor($clientA)`) and the Admin, and returns the instance; the test calls `CanaryRegistry::cleanup()` in afterEach. `blob($channel, $model)` returns everything Partner A can obtain through the channel for that entity as one string and throws a LogicException for a channel outside `DRIVEN`; `needles($model, 'a'|'b')` returns `CanaryRegistry::needles($model, $canary)`; `clientId('a'|'b')`. `const array DRIVEN` lists the channels with a driver (this plan: search, api, activity, selects).
- R-12-05-3 (assertion): for a cell, the blob must contain no client B needle and not the client B id; for a `none` cell it must contain no client A needle either. If a needle is not distinctive in a channel (a bare date or id that also occurs legitimately), report it in the SUMMARY and use a channel-specific needle with a written reason in ChannelProbe; never drop the assertion.
