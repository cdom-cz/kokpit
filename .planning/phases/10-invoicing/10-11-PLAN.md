Rulings made in this plan (recorded):
- R-11-1 A null `issue_date` on a draft means "today (Europe/Prague) at issue"; a null `due_date` means "issue date plus the client's payment terms at issue". The editor shows the derived values; only a value the Admin types is stored (D-11 "defaults to today" holds even for a draft issued days later).
- R-11-2 The draft currency must be a known ISO 4217 code; a missing bank account for it is a pre-issue blocker (plan 10-12), not a draft error (UI-SPEC Surface B).
- R-11-3 Items are upserted by id so a time-generated line keeps its source row across saves; an id that does not belong to the draft is a field error, never a write.
- R-11-4 The complete domain error contract below is written now; UI copy follows in plan 10-21.
- R-11-5 (research Open Question 12, adopted): the internal note, the one writable field of D-13 that lives with the document, is edited only through `UpdateInternalNote` (Admin only, row lock on the invoice, writes `invoice_admin.internal_note` and `internal_note_updated_at`); the activity allowlist records the marker and never the text, because free text is never logged in this codebase (the `Document` and `Transaction` allowlists).
