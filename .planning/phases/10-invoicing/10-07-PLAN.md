<objective>
Number series that can serve as variable symbols: the digits-only and length rule extended from invoices to proformas, a proforma default that cannot collide with the invoice default, and one helper that derives the variable symbol.

Purpose: IN-01 (separate series), D-10, UI-SPEC F-15, research Pitfalls 12 and 13, Open Question 8 (STATE blocker "proforma series and variable symbol").
Output: the extended `NumberPattern` rule, the new proforma default and its settings migration, `VariableSymbol`, Czech errors, updated numbering tests.

Owner acknowledgement point (Phase 3 D-05, editable number patterns per document kind): this plan narrows what the Admin may type as the proforma pattern to digits only and at most 10 characters, the rule Phase 3 already applies to invoices. The reason is that the proforma number is printed as the variable symbol of its SPAYD QR payment (D-21), and SPAYD allows only 1 to 10 digits there. The credit-note pattern stays free. The narrowing is kept in this plan (ruling R-07-1) and is listed in the planning return for the owner to acknowledge; if the owner prefers separators in the proforma pattern, the alternative is a variable symbol derived by stripping them, which changes `VariableSymbol::fromNumber()` and ruling R-07-2 only.

Split note (file count 10, above the 5-8 band): four of the ten files are existing numbering tests that must move their proforma cases when the rule changes; splitting them from the rule would leave the suite red between plans.

File-count rationale (10 files, at the warning threshold of 10, not above it): the only seam is between the proforma pattern rule (seven files) and `VariableSymbol` with its unit test (two files plus the shared `lang/cs/kokpit.php`); the variable symbol derives from the narrowed pattern (ruling R-07-2), so a separate plan would depend on this one and add a wave in front of plan 10-12 for three files.
</objective>
