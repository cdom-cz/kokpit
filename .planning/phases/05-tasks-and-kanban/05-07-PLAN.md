Decision carried in: D-13 (`task_billing` is a separate Admin-only 1:1 table) is rated `costly` in CONTEXT.md and was chosen by the user, so it is recorded on the task and not re-asked.

Assumptions adopted:
- The money currency of a task override equals the client's currency (Action-enforced through `ProjectInput::money($text, $client, $field)`, as for projects).
- The estimate is stored as `estimate_seconds` (whole seconds, the project's duration unit) and entered in hours with at most two decimals through `ProjectInput::estimateSeconds` (`EstimateHours`).
- `ProjectInput::requireFixedPrice` compares the type value `fixed_price`, which is the same string in `TaskBillingType`; it is reused unchanged.
- Own decision (reason, deviates from the pattern map note "do not copy internal_note"): `task_billing` carries a nullable `internal_note` like `project_billing`, because D-13 asks for the same pattern and the canary harness needs a text column in which the Admin sees each client's canary and a Partner sees none; without it the registry test could not prove the table non-vacuously. The note is Admin-only, never activity-logged, and is offered as a textarea in the billing section.

Fictional data only. Run `scripts/check-sensitive.sh` before every commit; never bypass the hook.
</context>
