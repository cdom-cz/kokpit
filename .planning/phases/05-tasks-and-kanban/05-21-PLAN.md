Gap closure of G-05-5, second part. Plan 05-20 built the policy ability `editDescription` (a Partner, an own client-visible task, status "Plánovaný" or "K upřesnění" only: owner decision D-16 in 05-CONTEXT.md, listed in `TaskPolicy::DESCRIPTION_EDITABLE_STATUSES`), the Action `UpdateTaskDescription::handle(User $actor, Task $task, ?string $description, string $basedOn): Task` (no constructor dependency yet; it re-checks the ability on the locked row, writes only after the status, stale and unchanged checks, then records the `description_changed` history row) and the header action "Upravit popis". Read its SUMMARY for deviations before starting. Every test of this plan uses a task in one of the two editable statuses unless it tests a refusal.

Design (Claude's discretion within D-07 and D-15):
- Event: the existing `NotificationEvent::AssignmentChange` ("Změna úkolu"), whose label is neutral. It becomes receivable by the Admin as well, so the Admin gets a profile row for it (D-15: every delivery has a switch, and a switch exists only for a delivery the system makes). No new enum case, no new notification class. The helper under a row is per event today and the Partner's "Změna úkolu" helper names status, priority and assignee, which does not describe the Admin's case; so `NotificationEvent::helper()` takes the role and gives the Admin's "Změna úkolu" row its own key `notifications.profile.helpers.assignment_change_admin`, while the Partner key and its text stay exactly as they are (no Partner copy changes in this plan).
- Class: the existing `TaskChangedNotification` gains a last constructor parameter `bool $recipientIsPartner = true`, passed to the base. Existing callers (TaskNotifier::changed, the tests) stay valid unchanged.
- Recipients: the Partner comment rule of `TaskNotifier::commented` ("the Admin and the assignee when that is an eligible account other than the author"), because D-07 says "Admin or assignee is notified of a task, comment or escalation by a Partner". Only a Partner actor notifies; an Admin calling the Action tells nobody, which keeps the Admin's own edits silent as today.
- Content: one change line built by TaskNotifier from the translation `kokpit.tasks.notifications.changed.description` with the actor's name only. No excerpt and no description text, so nothing the Partner wrote can travel in a notification (the description is visible on the task page to everybody who may receive it anyway).

Out of scope: UAT test 7 items (CR-01, T-05-44, WR-02, G-1) were passed by the owner with no decision to fix and are not touched. `UpdateTask`, `TaskNotifier::changed()` and the Partner rows of the profile stay as they are. Do not edit 05-VALIDATION.md, 05-SECURITY.md, 05-VERIFICATION.md or 05-REVIEW-DISPOSITION.md. In 05-UI-SPEC.md change only the lines named in Task 3.

Serialized after 05-20 (shared `kokpit_test` database, and this plan edits files of 05-20).

Fictional data only (public AGPL repository): names from `Canary` and the factories, canary words assembled at runtime, e-mail addresses only under example.com. Run `scripts/check-sensitive.sh` before every commit; never bypass the lefthook hook. Everything written in `.planning/` stays in English; Czech appears only in `lang/cs` (and as quoted copy in the UI-SPEC copy tables, as today).
