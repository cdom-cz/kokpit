# Phase 05 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: Phase 5 ships the task surfaces for both roles. Admin: task list with quick create, task page at `/admin/tasks/KEY-N`, task edit page, subtasks, checklist, billing section, comments, global kanban board, per-project board, slide-over card preview. Partner: "Moje úkoly" (read-only list, create page, task page), comments, escalation. Both roles: notification preferences on the profile page, the bell, and notification e-mails.
>
> Written mid-phase (auto mode). Plans 05-01 to 05-10 are built and committed: this spec records them **as built**, read from `app/Filament/Resources/TaskResource*`, `app/Filament/Pages/TaskBoardPage.php`, `app/Filament/Concerns/ManagesTaskBoard.php`, `resources/views/filament/pages/task-board.blade.php` and `lang/cs/kokpit.php`. Plans 05-11 to 05-17 are **not built**: they are specified here from the plans so later waves can be checked against this contract. Each surface below is tagged BUILT or PLANNED (plan id). Where built work departs from the Phase 2 design system it is recorded as a FLAG in "Flags on Built Work", never as a rewrite.

Upstream decisions applied (not re-asked): `02-UI-SPEC.md` (the project design system, treated as locked and extended here), `05-CONTEXT.md` D-01 to D-15, `05-RESEARCH.md` (Filament SPA, custom `wire:sort` board, strict rich text, notification matrix), and the Czech wording already in `lang/cs/kokpit.php` and `lang/cs/enums.php`.

## Spacing Scale

Inherited from 02: declared values are multiples of 4, mapped to Filament's Tailwind 4 spacing (1 unit = 4px).

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between badges on a card, icon-to-text gap in card meta, padding inside the card icon buttons |
| sm | 8px | Gap between cards in a column, gap between the card header icons, gap between detail rows in the preview |
| md | 16px | Gap between board columns, board bottom padding, vertical gap between stacked controls in the filter bar and modals |
| lg | 24px | Gap between form sections and fields (Filament form grid), section inner padding |
| xl | 32px | Page content horizontal padding, gap between page header and content |
| 2xl | 48px | Not used by task surfaces (simple-page cards only) |
| 3xl | 64px | Minimum height of an empty board column (the drop target) |

Board geometry (BUILT 05-10, kept): column width 272px (17rem), columns separated by 16px, cards separated by 8px, the board is a horizontally scrolling flex row. Six columns need 1712px, more than the stock 7xl content width (1280px), so the row scrolls horizontally inside the page; the page itself never scrolls sideways.

Exceptions and rules:

- 12px (0.75rem) appears in the built board (column padding, card padding, filter bar gap). 02 accepts 12px only as Filament-internal control padding; see FLAG F-2. New code in plans 05-11 to 05-16 uses only the declared tokens, written in rem as 0.25, 0.5, 1, 1.5, 2, 4. It does not copy 0.75rem and introduces no fractional value such as 0.4rem.
- Interactive targets keep Filament's stock 36px height. Icon-only buttons added by this phase (card preview, card open link) must have a hit area of at least 24 x 24px (WCAG 2.2 AA 2.5.8) and at least 8px between two adjacent icon targets; see FLAG F-3.
- Board and preview markup may use inline `style` or a scoped `<style>` block (no Node/Vite in the repository, spike conclusion); it may not use values outside this scale.
- Everything else (forms, tables, infolists, relation managers, modals, profile) comes from Filament components with stock spacing and no hand-written spacing.

## Typography

Inherited from 02. Four sizes and two weights; application code introduces no other.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (table cells, inputs, card text, filter labels, helper text, menu items) | 14px (`text-sm`) | 400 regular | 1.43 (20px) |
| Label (field labels, button text, column titles, card title link, badge text) | 14px | 600 semibold | 1.43 (20px) |
| Heading (section and modal headings, slide-over heading) | 16px (`text-base`) | 600 semibold | 1.5 (24px) |
| Display (page heading: `KEY-N · title`, board title) | 24px below `sm`, 30px from `sm` up (`text-2xl` / `text-3xl`) | 600 semibold | 1.33 / 1.2 |

Contract notes:

- Declared sizes: 14, 16, 24, 30. Declared weights: 400, 600.
- The built board card uses 12px (0.75rem) for the reference line and the due/checklist/assignee meta row and 12.8px (0.8rem) for the filter labels. These are a fifth and sixth size: FLAG F-2. New markup in this phase (preview, Partner pages, profile section, notifications) uses 14px for all text and distinguishes secondary text by `opacity` no lower than 0.8 or by Filament's gray text colour, never by a new size.
- Muted text (opacity 0.7 on the card reference and icons, 0.8 on meta) must keep 4.5:1 contrast on the column and card background in both modes; verified at the phase gate.
- Czech diacritics render in Inter (02 gate applies; check the board column headers "K upřesnění", "K vypuštění" and "Dokončeno").

## Color

Inherited from 02: gray is Zinc; semantic roles come from the panel `colors()` roles; no colour value is hard-coded in application code (but see FLAG F-2 for the board's `rgba()` overlays).

| Role | Value | Usage in this phase |
|------|-------|---------------------|
| Dominant (60%) | Light `#fafafa` / dark `#09090b` | Page background around the board, list, task page |
| Secondary (30%) | Light `#ffffff` / dark `#18181b`, hairline ring | Sidebar, topbar, sections, tables, modals, slide-over, relation manager panels. On the board: the column background (gray overlay at 10%) and the card (white overlay at 6% with a 1px gray border at 30%) |
| Accent (10%) | the panel `primary` role (Indigo-600 `#4f46e5` light / indigo-500 dark per 02; as built Amber, FLAG F-1) | Reserved list below |
| Destructive | Red-600 `#dc2626` light / red-500 `#ef4444` dark (the `danger` role) | On controls and text: the "Archivovat úkol" action and its confirmation submit, validation error text, danger toasts for refused actions. A red button always means a data-affecting action |
| Alert state (same red hue, `danger` role on a badge) | same values as Destructive | Read-only state badges only, never a button or trigger: priority "Naléhavá", escalation "Eskalováno" and "Eskalace". Red on a badge means "needs attention now", not "destroys data" (U-6). Each badge carries its text label |

Accent reserved for (and nothing else):

1. The single primary submit button of each surface and modal: "Vytvořit úkol", "Uložit úkol" (task edit page, target label, F-9), "Přidat komentář", "Otevřít úkol" (preview footer); on the profile page the stock "Uložit" of the approved 02 baseline. The escalation submit "Eskalovat úkol" is deliberately **not** primary (see the semantic map below).
2. The active sidebar item.
3. Text links in tables, infolists and forms (project key link, parent reference link, card title link, "Otevřít úkol" icon link).
4. The keyboard focus ring on every focusable control including cards' links and icon buttons.
5. Checked state of toggles and checkboxes (checklist "Hotovo", notification switches, "Interní komentář").
6. The SPA progress bar.

Badges (status, priority, escalation, internal, tag) are never in this list: they use the semantic roles below and the neutral gray, and none of them may use `primary`.

Semantic colour map for this phase (every badge also carries its text label, so colour is never the only carrier):

| Meaning | Colour role | Where |
|---------|-------------|-------|
| Status | enum `getColor()`: Plánovaný gray, K upřesnění warning, V realizaci info, Ke kontrole **fuchsia** (Tailwind palette `Filament\Support\Colors\Color::Fuchsia`, passed as a colour array, not a panel role), K vypuštění success, Dokončeno success | List, task page, subtask list, preview, Partner list and page. `ReadyToRelease` and `Done` share success; the label distinguishes them. No status, priority or escalation badge uses the `primary` role (see FLAG F-8 for the built enum) |

| Escalation (state) | alert-state badge (`danger` role, see the Alert state row above; not a destructive action) "Eskalováno" on the card, the task page entry and the Partner page entry; the same for "Eskalace" on the escalation comment row | BUILT card badge, PLANNED 05-13 for the rest |
| Internal comment | warning badge "Interní", Admin side only | BUILT |
| Escalate action (trigger and modal submit) | `warning`, never the primary role and never danger (escalation is not destructive) | PLANNED 05-13 |

Contrast and mode requirements: 02 applies; additionally the board column and card overlays must remain distinguishable from the page and from each other in light mode (the card relies on its 1px border because its 6% white fill is nearly invisible on a light column). ## Screens and Interaction Contract

### Visual anchors

One primary visual anchor per screen: the element the eye lands on first and that the rest of the layout serves. Everything else on the screen stays at stock Filament weight.

| Screen | Primary anchor | Why |
|--------|----------------|-----|
| Admin task list (A) | The table, led by the bold Číslo (`KEY-N`) column; "Nový úkol" is the only accent element above it | The list is for finding a task; the number is the stable handle |
| Task page (B) | The 30px display heading `KEY-N · title` with the Stav and Priorita badges directly below it in the first infolist rows | Identity and state before detail; Popis and the tabs follow |
| Task edit page (C) | The "Úkol" section (Název, then Popis) at the top, with "Uložit úkol" (F-9) as the single accent button | Editing starts with what the task is; the other sections are secondary |
| Global and project board (D, E) | The six-column row; within a card, the bold title link | The columns are the whole point; the filter bar is a quiet strip above, not a second focus |
| Slide-over preview (F) | The heading `KEY-N · title`; "Otevřít úkol" is the only accent element | Quick identity check, then leave for the full page |
| Partner list (G) | The table, led by Číslo and Název; "Nový úkol" is the only accent element on screen | A read-only list; the one action is creating a task |
| Partner task page (G, H) | The 30px display heading `KEY-N · title` with the Stav badge below it; "Eskalovat úkol" is warning-coloured, never accent | Same hierarchy as Surface B, with escalation visibly distinct from the primary action |
| Profile notification section (I) | The "Upozornění" section heading with its rows | Sits below the stock sections; the page's "Uložit" is the only accent button |

### Surface A: Admin task list `/admin/tasks` — BUILT 05-03

- Heading "Úkoly". Header action: "Nový úkol" (primary, `OutlinedPlus`), the quick create modal below.
- Columns in order: Číslo (`KEY-N`, bold, searchable), Nadřazený úkol (placeholder `—`), Název (searchable, wrapped, limited to 80 characters), Projekt (key), Stav (badge, sortable), Priorita (badge, sortable), Řešitel, Hotovo v kontrolním seznamu (`done/total`, empty when the task has no item), Termín (Czech date, sortable), Štítky, Změněno (toggleable, hidden by default).
- The title column is searchable but not sortable (the Czech collation mechanism is not built).
- Filters (combine with AND, two-column filter form): Klient, Projekt, Stav, Priorita, Řešitel, Štítek, Termín (od, do, inclusive; a task without a due date matches neither bound; active range shown as indicator chips "Termín od: …"), plus the stock trashed filter. Default sort: `updated_at` descending, `id` descending as tie-break.
- Row: the whole row opens the task page. Row actions (the row itself is the object, so the single-word labels stay here): view, "Archivovat" (danger, confirmation) for an active task, "Obnovit" for an archived one. No bulk actions, no export in this phase.
- Quick create modal ("Nový úkol"): fields Projekt (searchable select of `KEY · name`, archived projects and projects of archived clients not offered; preset on a project board) and Název (required, max 255). Submit "Vytvořit úkol". On success the Admin lands on the new task's **edit** page (FLAG F-4). Errors appear under the field in the modal.
- Empty: stock empty state with "Zatím tu nejsou žádné úkoly" and "Vytvořte první úkol tlačítkem Nový úkol."

### Surface D: Global board `/admin/task-board` — BUILT 05-10, PLANNED 05-11 additions

- Heading "Nástěnka úkolů". Admin only (a Partner gets 403 at mount; the page and `moveCard` are not reachable by a Partner).
- Filter bar (BUILT): selects Klient, Řešitel, Štítek, Priorita, each with first option "Vše", laid out as a wrapping row; filter state lives in the URL query (`#[Url]`, invalid values are dropped); the gray small button "Zrušit filtry" is shown whenever any filter is set. **Planned 05-11:** a header action "Nový úkol" (the same quick create modal as Surface A, project unset).
- Columns: six, one per status in enum order (Plánovaný, K upřesnění, V realizaci, Ke kontrole, K vypuštění, Dokončeno). Column header = status label (semibold) and the card count at the right; when the column is capped the count reads `shown / total`. The Done column shows the most recent 20 cards (config value `kokpit.board.done_limit`) ordered by completion time; older done tasks are reached through the list.
- Card (BUILT, D-03): top row `KEY-N` and, for a subtask, `· Podúkol KEY-N` of the parent, with an open-task icon link at the right; below it the title as a bold plain link to the task page; a badge row with the priority badge, the danger badge "Eskalováno" when flagged, and one gray badge per task tag; a meta row with the Czech due date, the checklist progress `done/total` and the assignee name, each only when present. Optional parts are omitted, never replaced by placeholders. A subtask is a card of its own in its own status column.
- **Planned 05-11:** an eye icon button "Náhled úkolu" next to the open icon, both inside the card's `wire:sort:ignore` wrapper, opening the slide-over (Surface F). The title stays a link; clicking it never starts a drag.
- Drag: grab cursor on a card; dropping persists status, completion time and position synchronously (no `.async`). A card dropped inside the Done column snaps back (that column is ordered by completion time). A drop into an empty column works because every column container keeps at least 64px of height. On a filtered board, hidden cards keep their relative order.
- Empty column: header with count 0 and an empty drop zone, no placeholder text. When a filter is set and every column is empty, the "Zrušit filtry" button is the recovery path.
- Mobile (375px): the filter bar wraps to one control per line; the board scrolls horizontally with 272px columns. Touch dragging and scroll conflict is a recorded human check (05-11).
- Recommended for 05-11 (non-blocking, R-1): the two board pages return `Width::Full` from `getMaxContentWidth()` (verified in `vendor/filament/filament/src/Pages/BasePage.php:93`), so wide screens show more than four columns.
- Refused move (stale card archived or moved elsewhere, forged status): the unresolved error row of T5 in UI Considerations (E-5); default copy in the Copywriting Contract.

### Cross-cutting interaction rules (this phase)

- Keyboard: every list, form, modal, relation manager and the slide-over works by keyboard alone with the accent focus ring. The board's drag gesture has no keyboard equivalent; the Status select on the edit page is the documented alternative (F-5).
- Partner surfaces never contain a control that a policy would refuse. A hidden action is not rendered, not disabled.
- Dates: `j. n. Y`; date and time `j. n. Y H:i`; instants stored in UTC, shown in `Europe/Prague`. Empty values show `—`.
- Rich text: every rich text field (task description, comments, escalation reason) uses `fileAttachments(false)` and the explicit toolbars above, is sanitised by `RichText::clean` on write for every actor, and rendered through `RichText::render`. Filament's `->html()` is used only on already cleaned values.
- Destructive or hard-to-undo actions always use a confirmation modal with a heading phrased as a question, a one-sentence consequence, and a submit label equal to the action name.
- Enum labels always come from `lang/cs/enums.php`; status and priority labels are the project ones (D-01).
