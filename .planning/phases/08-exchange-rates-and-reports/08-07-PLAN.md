Decisions made in this plan (recorded):
- `ReportExport` uses `OwnedByUser` (DeniesPartners plus the owner scope): even a second Admin reads only the own exports.
- `summary` is the server-built "Zadání" text (client name or "Všichni klienti", project name or "Všechny projekty", the period); `filters` holds only validated ids and Prague days; no user text reaches `path` or the download name.
- `path` is `report-exports/<export uuid>.<csv|xlsx>` on the default (private) disk, pinned by a CHECK.
- Expiry: `expires_at` is set to creation plus the TTL and reset to completion plus the TTL by `markReady()`, so the prune of plan 08-12 also removes stale pending and failed records.
- `user_id` references `users` with the default NO ACTION (users are deactivated, never deleted).
- Why the exports copy and config land here: same reason as plan 08-04 (other areas edit `lang/cs/kokpit.php` and `config/kokpit.php` in waves 4 and 5); UI-SPEC requires the `kokpit.exports.*` namespace. Enum labels go to `lang/cs/enums.php` (UI-SPEC cross-cutting rule).
