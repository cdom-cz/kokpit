Output: `CzechPublicHolidays`, the `--final` option and working-day gating of `kokpit:rates:download`, two schedule entries, `kokpit.rates` config, tests.

Decisions carried in (locked): D-03 (publication after 14:30 Prague; scheduled after publication, hourly retries until about 18:00; values in `config/kokpit.php`), D-04 (final failure of the day triggers the Phase 3 alert: synchronous mail plus bell, throttled, queue-independent; the last known rate stays in use).

Decisions made in this plan (recorded, adopting the research recommendation for open question 2):
- The daily download is a synchronous scheduled command, not a queued job, so a dead worker cannot swallow the alert (roadmap success criterion 2). Backfill, export build and prune are `KokpitJob`s in later plans.
- Attempts at 15, 16 and 17 o'clock and the final run at 18 o'clock, Monday to Friday in `Europe/Prague` (`->timezone('Europe/Prague')`, because `config/app.php` runs in UTC; research Pitfall 13). Values: `kokpit.rates.attempt_hours` = [15, 16, 17], `kokpit.rates.final_hour` = 18.
- Own `CzechPublicHolidays` (11 fixed days, Good Friday since 2016, Easter Monday; Easter by the anonymous Gregorian algorithm), no `ext-calendar` dependency (research Alternatives). Assumption A5: CNB publishes on every Czech working day and on no public holiday (verified against 2023-2025 data by the researcher).
- Only the `--final` run alerts. Conditions: the run failed (`CnbDownloadFailed` or a database error), or the day is a Czech working day and no list dated that day is stored after the attempt. Throttle key `cnb-rates:<Y-m-d>`. The alert links to the System page (`filament.admin.pages.system`), which shows the last rate date from plan 08-06.
- A run without `--final` on a non-working day returns at once with a Czech note and exit 0; a manual run from the rates overview (plan 08-08) calls the Action directly and is never gated.

Fictional data only: CNB answers in tests come from `CnbFixtures` with invented rates. Run `scripts/check-sensitive.sh` before every commit; never bypass the hook.
