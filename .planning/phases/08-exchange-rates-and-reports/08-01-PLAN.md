Purpose: EX-01 (idempotent download, per-unit amounts) and D-02 (whole list stored). Every later rate plan (schedule and alert, conversion helper, health slot, overview and backfill) builds on this table, client and Action.
Output: migration, `ExchangeRate`, `CnbClient` with its value and failure types, `DownloadCnbRates`, `kokpit:rates:download`, invented CNB fixtures, registrations and tests.

Phase 2/3 conventions: UUID v7 default `uuidv7()`, `timestamptz`, named constraints, `numeric(20,10)` rates with a `decimal:10` cast, `DeniesPartners` plus `AdminOnlyPolicy`, `DB::table` banned in `app/` (use the Eloquent builder's insert-or-ignore).

Decisions made in this plan (recorded):
- The daily list is fetched from the JSON API endpoint `/exrates/daily` with `lang=EN`; the row is stored under the payload's `validFor`, never under the requested day (research Pattern 1, Pitfall 3). The CNB API coverage matrix is `COVERAGE.md` in this phase directory.
- `rate` values are quoted in the raw body before `json_decode`, so they stay decimal strings (research Pitfall 2).
- A stored list is never rewritten: CNB lists are immutable once published, so a conflict does nothing (research Pattern 2).
- `CNB_API_BASE_URL` has a default in `config/services.php` and, like `ARES_BASE_URL`, is not listed in `.env.example` (EnvExampleTest documents only keys read without a default).
- Command output names dates, counts and the Czech failure reason only.

Fictional data only: every CNB payload in tests is built at runtime by `Tests\Support\CnbFixtures` with invented rates; no real list is copied. Run `scripts/check-sensitive.sh` before every commit; never bypass the hook.
