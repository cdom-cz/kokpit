Phase 2 D-03 fail-closed `#[AccessRule]` on every widget; Phase 5 pinned Partner field sets (`TaskColumns::PARTNER_COLUMN_NAMES`, `ProjectColumns::PARTNER_COLUMN_NAMES`).

Decisions made in this plan (recorded):
- The dashboard widgets live in `app/Filament/Widgets/`, which the panel already discovers (`discoverWidgets`). Discovery registers them as Livewire components; the role filter is `Dashboard::getWidgets()` plus each widget's own `canView()`. The two tests that pinned an empty panel widget list are changed on purpose to pin the exact discovered set and the absence of the stock widgets.
- The Partner widgets are custom `Filament\Widgets\Widget` classes with Blade views (not table widgets), so the `in_review` highlight can be a Filament badge and a count heading; each widget exposes `public const array FIELDS` with the field names it renders, and a test requires them to be a subset of the pinned Partner constants.
- Open task = status other than `done`. Order: `in_review` first (a CASE over the enum constant), then `TaskColumns::orderByPriority`, then due date with nulls last, then reference. The task list is capped at `PartnerTasks::LIMIT` = 20 with a link to the full "Moje úkoly" list.
- Highlighting uses Filament components (`x-filament::badge` with the warning colour, `x-filament::section`) and inline styles, never Tailwind utility classes (research Pitfall 11; there is no Node build). No UI-SPEC exists for this phase; the layout follows the existing Filament pages (risk noted in the phase plan set).

Reversibility: D-12 is rated reversible in CONTEXT.md (a page and a query, no stored data).
