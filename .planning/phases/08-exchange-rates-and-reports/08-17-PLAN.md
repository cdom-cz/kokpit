Decisions carried in (locked): D-02 (whole list stored), D-03 (schedule, retries), D-04 (final failure alerts). COVERAGE.md request discipline: at most four daily requests on a working day, none on weekends and holidays, one request per affected year for history.

Decisions made in this plan (recorded):
- The heal is its own Action called only by the scheduled command after a successful daily step, so the manual download of plan 08-13 keeps its four outcomes unchanged.
- Window: working days from max(oldest stored `rate_date`, day minus `gap_lookback_days`) up to the previous working day of the run's day; one query reads the stored dates of the window; a heal claim `kokpit:cnb-gap-heal:<day>` in the cache allows one round per Prague day (a day the calendar wrongly expects, assumption A5, costs one request a day, not four).
- `daily-year` takes only `year`; its rows are validated like the daily rows and grouped by `validFor`; a list dated after the run's day is ignored; rows are stored with insert-or-ignore.
- A heal failure fails the run like a daily failure; the daily rows already stored stay.

Fictional data only: year payloads in tests are built at runtime with invented rates. Run `scripts/check-sensitive.sh` before every commit; never bypass the hook.
