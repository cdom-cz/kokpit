<objective>
Close the root cause of CR-01. The client currency lock in `UpdateClient` asks only `ProjectBilling::clientHoldsMoney()`. A task's own hourly rate or fixed price in `task_billing` is also stored in the client currency, so the Admin can change the currency and leave task money in the old currency behind. Extend the lock to task money, archived tasks included, and give the Admin a message that says where to look.

Purpose: 08-VERIFICATION.md gap 1, missing item "Extend the client currency lock to task_billing money (archived tasks included)". RE-02 (amounts in client currency and CZK rest on one client currency). The task_billing migration's own docblock already states the rule ("The currency of the money equals the client's currency; that cross-table rule is enforced by the domain Action and the client currency lock"); this plan makes the lock true to it.
Output: `TaskBilling::clientHoldsMoney()`, the extended check in `UpdateClient`, the updated Czech message, tests.
</objective>

Facts read while planning:
- `ProjectBilling::clientHoldsMoney()` (app/Domain/Projects/Models/ProjectBilling.php lines 72-89) is the pattern to mirror. It runs `self::query()->whereExists(...)` over the raw `projects` table, which is why archived projects count (a raw subquery has no soft-delete scope), and checks `hourly_rate_minor` or `fixed_price_minor` not null, so a zero counts. `DB::table(` is banned in `app/` (QueryEscapeHatchTest); a `->from('tasks')` inside a `whereExists` closure is the accepted shape.
- `TaskBilling` (app/Domain/Tasks/Models/TaskBilling.php) has the same `DeniesPartners` scope and the same money column pairs as `ProjectBilling`.
- Task rates and prices are written only by `UpdateTask::parseBilling()`, in the client's currency at the time of writing (`ProjectInput::money($value, $client, $field)`). Tasks never move between projects, and a project's client never changes (UpdateProject docblock). So the currency change in `UpdateClient` is the only way task money ends up in a foreign currency.
- `UpdateClient::handle()` line 43 is the single check; only `ClientRulesTest` pins its message, through the translation key.
- Test helpers in ClientRulesTest: `rulesInput(overrides)`, `rulesProject(client, overrides)` (void; a project without `hourly_rate` holds no project money), `rulesErrors(callback)`; the signed-in user is `Canary::admin()`. Tasks are created with `app(CreateTask::class)->handle($admin, $project, ['title' => ...])`. Billing is set with `app(UpdateTask::class)->handle($admin, $task, ['hourly_rate' => '900'])` (also `billing_type`, `fixed_price`, `estimate_hours`, `internal_note`). Archive with `app(ArchiveTask::class)` or the model delete in a system run, as ClientRulesTest archives a project.
- The plans of the same wave do not touch these files: 08-23 (report) and 08-24 (dashboard widget) make the consumers currency-safe for data written before this lock.

Fictional data only. Run `scripts/check-sensitive.sh` before every commit; never bypass the hook.
