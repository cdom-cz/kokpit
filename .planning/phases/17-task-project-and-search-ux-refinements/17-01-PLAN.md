Rulings made in this plan (recorded):
- R-17-01-1 (column): migration `2026_10_29_000100_add_hidden_on_board_to_tasks_table.php` adds, with `Schema::table('tasks', ...)`, `$table->boolean('hidden_on_board')->default(false)` (NOT NULL by default). The default shows every existing row; there is no UPDATE and no index (the board filters a few hundred rows inside an already narrowed query). `down()` drops the column. The header comment (style of `2026_10_28_000400_make_invoice_item_unit_optional.php`, `declare(strict_types=1)`, anonymous `return new class extends Migration`) names D-04 and D-05, says why no backfill is needed, and that the flag is a display preference every Partner of the client may read (no money, nothing internal), which is why it lives on `tasks` and the pinned Partner-safe list grows by it.
- R-17-01-2 (model): `Task` gains `@property bool $hidden_on_board`, the name `'hidden_on_board'` at the end of `#[Fillable([...])]` (a plain content column, like the dates), and the cast `'hidden_on_board' => 'boolean'`. It is NOT added to `#[LoggedAttributes([...])]`: a display preference writes no history row (research Pitfall 9). One sentence in the class docblock says so.
- R-17-01-3 (writer): `UpdateTask` gains `hidden_on_board?: bool|null` in the `TaskUpdateData` phpstan type; inside `handle()`, next to the description, `if (array_key_exists('hidden_on_board', $data) && $data['hidden_on_board'] !== null)` puts `(bool) $data['hidden_on_board']` into `$plain`, so it goes out in the same `fill()` and save as the other plain columns. A missing or null key leaves the stored value. One paragraph of the class docblock names D-04 and the absent-key rule. `CreateTask` is not touched: it builds an explicit attribute list, so a new task is always shown and a Partner payload carrying the key has no effect.
- R-17-01-4 (board): `TaskBoard::applyFilters()` adds `$query->where('tasks.hidden_on_board', false);` unconditionally, right after the `whereIn('tasks.project_id', $projects)` line; the method docblock gains "and not hidden from the board (D-04)". This is the only filter on the flag in the codebase: `columns()` (rendered cards and the Done `total`) and `move()` (the `$visible` neighbour list of a drop) both go through it.
- R-17-01-5 (form): in `TaskResource::form()`, at the end of the `kokpit.tasks.sections.status` Section after the priority Select, `Checkbox::make('hidden_on_board')` (import `Filament\Forms\Components\Checkbox`) with `->label(__('kokpit.tasks.fields.hidden_on_board'))`, `->helperText(__('kokpit.tasks.hints.hidden_on_board'))`, `->default(false)`, `->columnSpanFull()` (UI-SPEC Interaction 5; D-04 says checkbox). `TaskResource::actionData()` adds `'hidden_on_board' => array_key_exists('hidden_on_board', $data) && $data['hidden_on_board'] !== null ? (bool) $data['hidden_on_board'] : null`. `fillData()` is not changed: the edit page fills plain columns from the record. No infolist entry, no list column, no badge (UI-SPEC 5, D-04).
- R-17-01-6 (copy, lang/cs/kokpit.php): `tasks.fields.hidden_on_board` = "Skrýt na nástěnce"; `tasks.hints.hidden_on_board` = "Úkol se nezobrazí na kanbanové nástěnce. V seznamech, hledání a na detailu zůstává."
