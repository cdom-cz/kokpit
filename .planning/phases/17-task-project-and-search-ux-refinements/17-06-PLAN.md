Rulings made in this plan (recorded):
- R-17-06-1 (reader): `SignalDayReader::tasks()` adds `->with(['task' => static fn (BelongsTo $query) => $query->withoutGlobalScopes([SoftDeletingScope::class])->select(['tasks.id', 'tasks.reference', 'tasks.status', 'tasks.deleted_at'])])` so archived linked tasks load too, in one query for the whole day; never a bare `withoutGlobalScopes()` (QueryEscapeHatchTest). The class docblock notes the link.
- R-17-06-2 (row data): `SignalDay::day()` reads the running task id once per render, `app(TaskTimerToggle::class)->runningTaskId($this->actor())`, and every task entry gains `'link'`: null when `task_id` is null or the relation is null, otherwise `['url' => TaskResource::getUrl('view', ['record' => $linked]), 'can_time' => ! $linked->trashed() && $linked->status !== ProjectStatus::Done, 'running' => $running === $linked->getKey()]` (precedent: `ControlsTimer` builds `task_url` the same way). The `@return` array shape of `day()` and the `@property-read` docblock grow accordingly (PHPStan).
- R-17-06-3 (timer method): `public function toggleTaskTimer(string $signalTaskId): void` runs through `attempt()`: a non-UUID or a row not found with `SignalTask::query()->whereKey($signalTaskId)->where('for_date', $this->forDate)->first()` (owner scope: another Admin's row is not found) throws `ModelNotFoundException` (the existing "Záznam už neexistuje." notification); the task is read from the row's own `task_id` with `Task::query()->withTrashed()->whereKey(...)->first()` (null: not found); `Gate::forUser($actor)->authorize('view', $task)`; when the task is not the running one and is archived or Done, `SignalRuleViolation::because('task_unavailable')` (a start is refused, while a stale row can still stop its own running timer, as on the board, `ManagesTaskBoard::toggleTimer()`); otherwise `$event = app(TaskTimerToggle::class)->handle($actor, $task)`, `unset($this->day)`, and `$this->dispatch($event)` when the event is not null. It writes no signal row and dispatches no `signal-changed`.
- R-17-06-4 (sync): `#[On('timer-started')]`, `#[On('timer-stopped')]`, `#[On('time-entry-saved')]`, `#[On('time-entry-deleted')]` on one public method `timerChanged(): void` that runs `unset($this->day)` (the repeatable attribute pattern of `ControlsTimer::refreshState()`), so the today and tomorrow cards and the top bar agree (research Pitfall 6).
- R-17-06-5 (markup, UI-SPEC Interaction 9): in each task row of `resources/views/livewire/signal/day.blade.php`, after the recurring icon and before the existing `can_edit` edit/delete container, when `$task['link'] !== null`: a container `<div wire:sort:ignore style="display: flex; flex: 0 0 auto; gap: 0.25rem;">` rendered regardless of `can_edit` and outside the done styling (so full opacity), holding, when `can_time`, an `x-filament::icon-button` with `:icon` `heroicon-m-stop` when running else `heroicon-m-play`, `:color` `warning` when running else `gray`, `size="sm"`, `wire:click="toggleTaskTimer('{{ $task['id'] }}')"`, `aria-pressed` true or false, `:label` and `:tooltip` from `kokpit.time.timer.stop` or `kokpit.time.timer.start`; and always an `x-filament::icon-button` with `tag="a"`, `:href="$task['link']['url']"`, `icon="heroicon-m-arrow-top-right-on-square"`, `size="sm"`, `color="gray"`, `:label` and `:tooltip` from `kokpit.task_board.card.open` ("Otevřít úkol", an existing string). The title span stays plain text with `overflow-wrap: anywhere`. Inline styles only.
