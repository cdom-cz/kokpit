## Lock boundary

| Option | Description | Selected |
|--------|-------------|----------|
| Any payment or credit note | Locked once a payment or any credit note exists | |
| Only fully paid or cancelled | Partial payments still allow edits | |
| Fully paid or any credit note | Partial payment keeps editable | |
| (free text) | Lock after sending, manual unlock, not driven by states | ✓ |

**User's choice:** Change the decision: lock after sending, manually unlockable; states do not lock.
**Notes:** Follow-ups: "sent" = successfully sent e-mail (chosen over manual mark-as-sent and queueing); unlock = action with mandatory reason (over no reason, over one-edit unlock); payments and credit notes do not restrict, only the lock decides.

## What is editable

| Option | Description | Selected |
|--------|-------------|----------|
| Items | text, quantity, unit, price, add/delete | ✓ |
| Dates | issue, taxable supply, due | ✓ |
| Customer and supplier | snapshots and bank account | ✓ |
| Currency and language | currency incl. CNB rate, language | ✓ |

**User's choice:** All four. Number and kind stay fixed (over editable number). Linked time can be added and released (over staying billed).

## Number, PDF, e-mail

**User's choice:** PDF regenerated and replaces the old one (over keeping versions); Stripe link invalidated and re-created plus QR regenerated (over warning only); re-send manually (over automatic correction e-mail).

## Guards and audit trail

**User's choice:** Conditional DB trigger keyed on a lock column (over dropping triggers); audit record before/after of every change after first send (over logging only lock/unlock).
