External service: ARES public REST endpoint `GET https://ares.gov.cz/ekonomicke-subjekty-v-be/rest/ekonomicke-subjekty/{ico}`, no key, no account, no secret (research Pattern 5, live-verified shape). The base URL is a public government address and lives in `config/services.php` (`services.ares.base_url`, overridable by `ARES_BASE_URL` with the public URL as the default; `tests/Feature/Repo/EnvExampleTest.php` requires `.env.example` entries only for keys read without a default, so `.env.example` stays unchanged). API coverage decisions for ARES are recorded in `04-clients-and-projects/COVERAGE.md` (lookup by company number integrated; search, the per-register endpoints, address standardisation and code lists opted out with reasons).

Assumptions adopted from research (unattended run, recorded and easy to reverse):
- A5: when ARES returns no `dic`, the typed tax number is left alone and the hint says no tax number was returned (overwriting with empty would erase a value ARES simply does not publish).
- A10: 429, 5xx, maintenance pages, a missing street and an orientation-number letter were not observed live; they are handled generically and tested with invented fakes.
- Highlight without a CSS build: each ARES-sourced input gets a success-coloured hint while its name is in the hidden, non-dehydrated `ares_changed` state list (research Pattern 5).
- Per-user rate limit for the button: 10 lookups a minute (`RateLimiter` key `ares:` plus the user id); a hit is `RateLimited`.

Repository hygiene (public repository): never paste a recorded ARES response; fixtures are invented payloads with `Example` names; company numbers come from `FictionalCompanyId::valid()`; the placeholder `12345678` is checksum-invalid by design and is the "fails locally, no HTTP call" fixture. `scripts/check-sensitive.sh` before every commit; never bypass the hook.
</context>
