# Phase 19 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: the folder tree panel and the tag, folder and archived filters on General knowledge (ORG-01 to ORG-03), the
> classification fields in the article editor and the Knowledge tabs on client and project pages (ORG-04), and the
> Versions, version view, diff, restore and redaction screens (VER-02 to VER-05). All UI copy is Czech and lives in
> `lang/cs/knowledge.php` (new keys under `folders.*`, `tags.*`, `links.*`, `versions.*`, `diff.*`, `restore.*`,
> `redact.*`); code, routes, tests and this document are English. Every sample name below is fictional.
>
> Source legend used in the tables: **D-nn** = locked decision in `19-CONTEXT.md`; **P18** = pattern already shipped in
> Phase 18 (reuse, do not re-invent); **default** = chosen here because upstream did not answer.

## Design System

| Property | Value |
|----------|-------|

relation managers, resource sub-navigation). Only the folder tree, the diff table and the redaction line preview are

## Typography

Phase 19 adds chrome around Filament-native text; native elements (page heading, table cells, form labels, modal
heading, notifications) keep Filament's own sizes. The contract below covers the custom markup only. Rendered article
bodies on the version view keep the `kokpit-prose` scale of Phase 18 (28, 20, 16, 14; verified against
`resources/css/kokpit-prose.css`).

**Size budget (checker Dimension 4 fix).** The phase's complete set of sizes is exactly four: **14, 16, 20, 28**. The
mechanism is to fold the former 12px caption into 14px, so the custom chrome uses only 14 and 16, and 20 and 28 occur
only inside `.kokpit-prose` (the rendered version body, whose h1 and h2 are 28 and 20). No custom markup in this phase
declares 20 or 28, and nothing declares 12. The caption role is told apart from body text by muted colour
(`var(--gray-500)` light / `var(--gray-400)` dark, at least 4.5:1 on the panel surfaces), not by size.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (tree rows, diff text, table text, helper text) | 14px | 400 | 1.5 |
| Label (selected tree row, diff section labels, field labels) | 14px | 600 | 1.5 |
| Heading (tree panel heading "Složky", diff title block heading) | 16px | 600 | 1.25 |
| Caption (folder article counts, line numbers, "Nezměněných řádků" separators, meta line, diff summary), muted colour | 14px | 400 | 1.5 |
| Display | not used in this phase (page headings are Filament-native) | — | — |

Sizes declared for custom markup: 14, 16 (effective phase total with the prose body: 14, 16, 20, 28 = 4). Weights
declared: 400 and 600 only. Diff text, source preview and line numbers use the monospace stack at 14px/400 (line numbers
in the muted caption colour), `white-space: pre-wrap; overflow-wrap: anywhere` so a long line wraps
and never forces horizontal scrolling.

## Color

Filament custom properties carry both modes; approximate light-mode values in brackets.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--gray-50)` page surface light (`#f9fafb`), `var(--gray-950)` dark (`#030712`); cards and tables use Filament's white / `--gray-900` surface | Page background, the articles table, the version table, the version body |
| Secondary (30%) | `var(--gray-100)` light (`#f3f4f6`) / `var(--gray-800)` dark; borders `var(--gray-200)` / `var(--gray-700)` | Tree panel background, selected-row hover, diff gutters, source preview, folder chip, unchanged diff rows' separators |
| Accent (10%) | `var(--primary-600)` light (Amber, about `#d97706`) / `var(--primary-400)` dark | See reserved list below |
| Destructive | `var(--danger-600)` light (about `#dc2626`) / `var(--danger-400)` dark | Folder delete, redaction submit and its warning callout, removed diff lines |

Semantic (non-accent) colours, used only for state, never decoration:
- Added diff line: background `color-mix(in srgb, var(--success-500) 14%, transparent)`, `+` marker in `var(--success-700)` light / `var(--success-400)` dark.
- Removed diff line: background `color-mix(in srgb, var(--danger-500) 14%, transparent)`, `-` marker in `var(--danger-700)` light / `var(--danger-400)` dark.
- Text on both stays `var(--gray-950)` / `white`, so contrast is that of normal body text; the marker character and a visually hidden label make the meaning independent of colour.
- "Redigováno" badge and the redacted-version callout: `warning`. "Aktuální" badge: `success`. "Obnoveno z verze N" badge and tag chips: `gray`. Sensitive lock: `warning` (P18).

Accent reserved for (explicit list, nothing else):
1. The selected folder row in the tree (2px inline-start bar, label colour) and the keyboard focus ring of every tree control.
2. The primary action of each screen: "Nový článek" (header), "Nová složka" confirm submit, "Přidat článek" (Knowledge tab), "Obnovit jako novou verzi" (restore modal submit), "Obnovit tuto verzi" (version view header).
3. Links inside the version view and diff header ("Zobrazit verzi", "Zpět na verze").
4. The active tab of the article sub-navigation (Filament native).

Accent is never used for tag chips, diff lines, badges or row hover. Redaction is the only destructive action that
looks like an action button in a header; it is outlined `danger`, never filled, until the modal submit.

## Layout and Interaction Contract

### 1. General knowledge list with folder tree (ORG-01, ORG-02, ORG-03; D-01, D-02, D-03, D-05)

**Layout.** `ListKnowledgeArticles` keeps its Filament table. The page content becomes a flex row: tree panel (280px, `flex: 0 0 280px`) and the table (`flex: 1; min-width: 0`), 16px gap. Below 1024px the panel moves above the table inside a collapsed disclosure whose summary reads "Složky" plus the name of the current selection; choosing a folder closes it. The panel is a bordered 8px-radius surface (secondary colour) with 16px padding, sticky at the top of the content area on wide screens.

**Primary visual anchor:** the folder tree panel, the only bordered secondary-surface block, left of the table; the selected row with its 2px accent bar is the focal point inside it.

**Panel header.** Heading "Složky" (16/600) on the left; an icon button "Nová složka" (plus icon, tooltip and `aria-label` with the same text) on the right creates a root folder.

**Entries, in order.**
1. "Všechny články" (default selection, shows the existing list).
2. "Bez složky" (articles with no folder, D-02).
3. A 1px divider.
4. The folder tree, siblings sorted alphabetically (Czech collation); no manual order and no drag and drop (D-03).

**Row anatomy (36px min height).** [chevron button 32px, only if the folder has children, else a 32px spacer] [folder icon 16px] [name, 14px, single line, ellipsis, full name in `title`] [article count, 14px muted] [row action menu trigger, ellipsis icon button]. The count is the number of **non-archived** articles in the folder **including its subfolders** (it matches what clicking the folder lists). The action trigger is visible on hover, on keyboard focus within the row and always on touch devices and on the selected row; it is a real focusable button in every state (not `display: none`).

**Expansion.** Roots are expanded on first load, deeper levels collapsed; ancestors of the selected folder are always expanded. Expansion state is not persisted. Chevron buttons carry `aria-expanded` and `aria-label` "Rozbalit :name" / "Sbalit :name".

**Selection.** Clicking a name sets the page property `folder` (a UUID, the literal `none`, or empty for all) which is bound to the URL query string, so the selection survives reload and back/forward. The list then shows articles of that folder **and all its subfolders** (D-01). Selected row: aria-current, 600 weight, accent bar, `var(--gray-100)` / `var(--gray-800)` background. The tree is a `<nav aria-label="Složky">` with nested `<ul>`; every row control is reachable with Tab, Enter or Space activates it. Arrow-key tree navigation is not required.

**Folder chip.** When a real folder is selected, a removable chip sits above the table: "Složka: Provoz / Servery (včetně podsložek)" with a remove button (`aria-label` "Zrušit filtr složky"). It makes the include-subfolders rule visible without opening the tree.

**Row action menu** (Filament dropdown, each item a Livewire page action with a modal):

| Item | Modal | Notes |
|------|-------|-------|
| Nová podsložka | Single text input "Název složky" (required, trimmed, max 100 chars; default), autofocus | Hidden when the folder is already at `MAX_DEPTH` levels |
| Přejmenovat | Same input prefilled | Sibling names are unique case-insensitively (DB unique index): a duplicate shows the field error `folders.errors.name_taken` |
| Přesunout | Select "Nadřazená složka" (searchable). Options: "Kořen (bez nadřazené složky)" then every folder as an indented path label | Options that are the folder itself, its descendants, or would push the moved subtree past `MAX_DEPTH` are **disabled** (`disableOptionWhen`), and the helper text states the cap from `KnowledgeFolder::MAX_DEPTH`. A server-side refusal (race, forged request, KP003) still maps to a danger notification with the matching reason below |
| Smazat | Confirmation modal, `danger` | Disabled path: a non-empty folder is refused up front (see below), never after a confirmation |

**Refusals (D-03, ORG-02).** All are Filament notifications (`danger`, persistent until dismissed, role alert), never a bare exception page. Messages come from the database guard result, not from a generic fallback; the depth figure is `KnowledgeFolder::MAX_DEPTH`, never hard-coded.
- Cycle: "Složku nelze přesunout do sebe ani do její vlastní podsložky."
- Depth: "Složku nelze přesunout sem: strom by byl hlubší než :max úrovní. Složka s podsložkami se počítá i s nimi."
- Delete of a non-empty folder: counts include **archived** articles, because they still hold the folder (RESTRICT foreign key): "Složka není prázdná: obsahuje :contents. Přesuňte obsah jinam a zkuste to znovu." with `:contents` such as "3 články (včetně archivovaných) a 2 podsložky" (Czech plural forms via `trans_choice`).

**Selected folder deleted or moved.** If the selected folder is deleted the selection falls back to "Všechny články". After a move the selection stays and the tree expands to reveal it.

**Table additions** (existing columns stay): a "Složka" column (muted path, hidden below 768px, toggleable, default shown), a "Štítky" column (up to 3 gray chips, then "+N"), and the existing title, version, last edited and sensitive columns. Filters: existing "Zobrazit archivované" toggle plus a "Štítky" multi-select filter (searchable, only `knowledge` tags). Selecting several tags **narrows** the result: an article must carry **all** of them (D-05); the indicator reads "Všechny štítky: :tags". Folder, tags and archived combine (AND). A "Zrušit filtry" action resets tags and archived but not the folder (the folder chip has its own remove).

**Header action.** "Nový článek" stays. When a real folder is selected it opens the create screen with that folder prefilled (`?folder=<uuid>`); under "Bez složky" it opens with no folder.

### 2. Article editor and view: classification (ORG-03, ORG-04; D-04, D-06)

The existing single-column form gets one new `Section` "Zařazení" between the editor tabs and the sensitive toggle, a two-column grid from 768px up, single column below.

| Field | Control | Behaviour |
|-------|---------|-----------|
| Složka | Searchable Select, placeholder "Bez složky", options as path labels ("Provoz / Servery") | Optional, clearable |
| Štítky | Tag field limited to the `knowledge` type | Suggestions are existing knowledge tags only; Enter or comma creates a new tag on the fly (D-04); trimmed, 1 to 40 chars (default), duplicates merge case-insensitively; client tags never appear, and a knowledge tag never appears on a client form. Helper: "Štítky znalostí jsou oddělené od štítků klientů." No tag management screen |
| Klient | Searchable Select, placeholder "Bez klienta" | Live: changing or clearing it clears Projekt (D-06) |

A save that changes only classification (folder, tags, client, project) creates **no version** (versions snapshot title and body), shown with the existing no-new-version pattern: notification "Zařazení článku bylo uloženo, nová verze nevznikla." (same shape as `sensitivity_changed`).

**View screen.** Below the existing meta line add a second muted row (14px, wrap, 8px gap): folder path with folder icon as a link to the list filtered by that folder, client and project as links to their pages, then the tag chips. Items that are not set are omitted; the row is omitted when nothing is set.

### 4. Versions page (VER-02; D-08)

A new page `versions` on `KnowledgeArticleResource` (`/{record}/versions`) added to the record sub-navigation as **Zobrazit | Upravit | Verze**. The existing "Historie změn" activity relation manager is unchanged and distinct (it lists metadata events, the Versions page lists content snapshots). Page title: "Verze článku „:title“".

Table, default sort version number descending, 25 rows per page:

| Column | Content |
|--------|---------|
| Verze | "Verze :n"; row link to the version view; the newest row carries the `success` badge "Aktuální" |
| Autor | User name |
| Vytvořeno | `j. n. Y H:i` in Europe/Prague (`LocalisationServiceProvider::DATE_TIME_FORMAT`) |
| Značky | Gray badge "Obnoveno z verze :n" (arrow-uturn-left icon), `warning` badge "Redigováno" (eye-slash icon) |

**Primary visual anchor:** the version table with the newest row's `success` badge "Aktuální" as the first thing the eye lands on. Row actions as icon buttons with tooltips (same pattern as the General list), and **every icon-only button carries an explicit `aria-label` equal to its tooltip copy** ("Zobrazit verzi", "Porovnat s předchozí", and "Další akce" on the overflow trigger): "Zobrazit verzi" (eye), "Porovnat s předchozí" (arrows-right-left; hidden on version 1), and an overflow dropdown holding "Obnovit tuto verzi" (hidden on the current version and on an archived article) and "Redigovat verzi" (danger colour in the dropdown). There is no bulk selection; picking two arbitrary versions happens on the diff page.

### 5. Version view (VER-02; D-08)

Page `versions/{version}`. **Primary visual anchor:** the rendered version body inside `.kokpit-prose` (28px h1 scale, the largest type on the page), with the status callouts directly above it as the secondary focus. Header: back link "Zpět na verze". Meta line (P18 style): "Verze :n · :author · :date" plus badges. Header actions: "Porovnat s předchozí" (gray), "Obnovit tuto verzi" (primary, hidden on the current version and on an archived article), "Redigovat verzi" (outlined `danger`).

Body: the stored title as a 16px/600 Heading line, then the stored body rendered by the one renderer inside `.kokpit-prose` (`KnowledgeMarkdown`, never a second renderer), so a redacted version shows its redacted text. Callouts above the body, at most one of each:
- Old version (info): "Toto je starší verze. Aktuální je verze :current." with a link "Zobrazit aktuální verzi".
- Redacted (warning): "Tato verze byla redigována" / "Část textu, nebo celý text, byl nahrazen značkou [REDIGOVÁNO]."
- Archived article (info): "Článek je archivovaný. Chcete-li verzi obnovit, nejdřív článek obnovte."

### 6. Diff page (VER-04; D-09)

**Primary visual anchor:** the body diff table, with the added and removed tints as the only saturated areas on the page; the summary line and title block are subordinate. Page `versions/compare?from=<n>&to=<m>` (query string, so the comparison is linkable and survives reload). Default: `to` is the version chosen, `from` its predecessor. Two searchable Selects at the top, "Z verze" and "Na verzi", options "Verze :n · :date"; changing either recomputes live (`wire:model.live`, loading indicator shown during the request). Any two versions may be chosen, in either order.

Content, top to bottom:
1. Summary line (Caption): "Přidáno :added, odstraněno :removed řádků" (counts of body lines).
2. **Title block** (title is diffed separately, D-09): if the titles differ, two lines, the old one with a `-` marker on the removed tint and the new one with `+` on the added tint; if equal, a muted line "Název se nezměnil: :title".
3. **Body diff**: unified line diff in one `<table class="kokpit-diff">` with a visually hidden `<caption>` ("Rozdíl mezi verzí :from a verzí :to"). Columns: old line number, new line number, marker (`+`, `-` or blank), text. Added and removed rows carry the tints above and a visually hidden prefix ("Přidáno:" / "Odstraněno:") in the text cell for screen readers. Three lines of context around each change; runs of longer unchanged text collapse into a single separator row "Nezměněných řádků: :count" (Caption, centred, `var(--gray-100)`). The diff never loads or renders anything but the two stored versions.
4. The diff text is plain escaped text, never rendered as Markdown or HTML (a secret or hostile markup in a version must not become live markup).

Limits (default): more than 1,500 diff rows renders the first 1,500 plus the notice "Rozdíl je příliš dlouhý, zobrazeno prvních 1 500 řádků." (a body is capped at 100,000 characters, so the page stays bounded).

States: identical content → "Obě verze mají stejný text." (empty-state style, no table); same version picked on both sides → "Vybrali jste stejnou verzi. Zvolte dvě různé verze."; a version number that does not exist for the article → 404.

Header links: "Zobrazit verzi :to" and "Zpět na verze". Diff library: the contract needs hunks with old and new line numbers; either `sebastian/diff` or `jfcherng/php-diff` satisfies it (planner decides, D-09). Recommendation: `sebastian/diff` 9.0.1 (BSD-3-Clause, see Registry Safety). It sits in `composer.lock` under `packages-dev` only, so it is **not** present in a production install and must be moved to a runtime `require`.

### 7. Restore (VER-03; D-11)

**Primary visual anchor:** the diff area of the current version against the chosen one, above the footer's single primary submit. Trigger: "Obnovit tuto verzi" on the version view and in the Versions row menu (Filament action opening a modal). Hidden for the current version and for an archived article. Modal: width `5xl`, scrollable content, icon arrow-uturn-left, no danger styling (nothing is lost).

1. Heading "Obnovit verzi :from?"; description "Název a text se vrátí na stav verze :from a uloží se jako nová verze :next. Žádná verze se nesmaže."
2. The diff of the **current** version against the chosen one (same `.kokpit-diff` component, `max-height: 60vh`, own scroll), captioned "Změny oproti aktuální verzi :current".
3. Footer: submit "Obnovit jako novou verzi" (primary), cancel "Zrušit".

The confirmed restore calls the same save path as an editor save (stale-save check plus secret guard), so the outcomes are:
- **Success**: modal closes, notification "Verze :from byla obnovena jako verze :next", the page opens the new current version.
- **Content identical to current**: the diff area shows "Tato verze se shoduje s aktuálním textem. Nová verze nevznikne." and the submit button is hidden.
- **Unambiguous secret (refused)**: the modal **stays open**; a `danger` callout (role alert) with "Verzi nelze obnovit, obsahuje tajný údaj" and the finding lines (rule and line number, never the value, same view as P18 `guard-findings`) and the body "Redigujte tajný údaj v této verzi a obnovte ji znovu."; a link action "Redigovat verzi" inside the callout. Nothing is written.
- **Ambiguous finding**: a `warning` callout "Obnovovaná verze může obsahovat tajný údaj" with the finding lines; the submit label becomes "Obnovit i přesto". The acknowledgment covers this one restore only; the article is marked sensitive and the notification states it (P18 wording pattern).
- **Stale (article changed meanwhile)**: `danger` notification "Článek mezitím někdo změnil" / "Aktuální text článku se mezitím změnil. Zavřete okno, znovu otevřete obnovení a zkontrolujte změny."
- Failure of the write: the P18 `write_failed` notification; the modal stays open.

**Open editor versus a redacted latest version (D-13).** Redacting the current version changes the article body without
a version bump, so the contract is: the stale token covers redaction. A save from an editor (or a restore modal) opened
before the redaction is **refused** as stale, nothing is written, and the form keeps the typed text so nothing is lost;
the unredacted text can therefore never be saved back. The notification reuses the stale pattern, `danger`, persistent:
"Text článku byl mezitím změněn nebo redigován" / "Uložení se neprovedlo, aby se do článku nevrátil redigovaný text. Znovu otevřete článek a zkontrolujte změny." The planner chooses the mechanism (for example a revision counter bumped by redaction, or a token over the body hash); the behaviour above is the contract and applies to the restore modal too (its stale notification above is shown).

### 8. Redaction (VER-05; D-12, D-13)

**Primary visual anchor:** the `danger` callout "Redigování nelze vrátit zpět" at the top of the modal (the only filled-tint block above the fold), with the filled `danger` submit as the single action anchor in the footer. Trigger: "Redigovat verzi" (version view header, Versions row menu), available for **any** version including the current one and including on an archived article. Modal width `3xl`, `danger` icon (shield-exclamation), content top to bottom:

1. `danger` callout "Redigování nelze vrátit zpět": "Vybraný text se v uložené verzi nenávratně přepíše značkou [REDIGOVÁNO]. Zobrazení, rozdíl i obnovení této verze pak použijí upravený text."
2. `warning` callout "Skutečné řešení je tajný údaj změnit": "Redigování odstraní jen kopii z Kokpitu. Únik vždy řešte změnou nebo zneplatněním údaje u jeho vydavatele (heslo, klíč, token)." (D-12: the UI states that rotation is the real remedy.)
3. If the version is the current one, an info callout: "Tato verze je aktuální: redigování se projeví i v aktuálním textu článku." (D-13).
4. Read-only **numbered source preview** of the stored Markdown (monospace, line numbers 14px muted, `max-height: 320px`, own scroll) so the line numbers match those the secret guard reports. It is visible to Admin only and never logged.
5. Radio "Rozsah": "Jen vybrané řádky" (default) / "Celý text verze". For the line scope, a text input "Čísla řádků" with helper "Čísla oddělte čárkou, rozsah zapište pomlčkou, například 3, 7-9." Each selected line is replaced by `[REDIGOVÁNO]`; the whole scope replaces the body with that single marker (default; the title is not redacted).
6. Required textarea "Důvod redigování" (max 500 chars) with helper "Do protokolu změn se zapíše jen to, že důvod existuje, ne jeho text. Nepište do něj tajný údaj." The reason text is never echoed back on any screen after submit.
7. Footer: submit "Redigovat verzi" (`danger`, filled), cancel "Zrušit".

Validation messages (inline, under the field): "Vyberte alespoň jeden řádek.", "Řádek :n ve verzi neexistuje.", "Vyplňte důvod redigování." Success: notification "Verze :n byla redigována" and the version view refreshes showing the "Redigováno" badge and callout. The activity log entry carries who, which version and that a reason exists; never the value, the line text or the reason text. Failure: `danger` notification "Verzi se nepodařilo redigovat" / "Nic se nezměnilo. Zkuste to znovu."
