The class docblock states the lock order (article first, then version, the same as RedactVersion and SaveArticle) and why.
- R-19-09-2 (line selection): `final class RedactionLines` with `MAX_INPUT_LENGTH = 1000` and `public static function parse(string $input, int $lineCount): array` returning sorted unique 1-based numbers: empty after trim is a ValidationException on `lines` with `knowledge.redact.errors.lines_required`; input over MAX_INPUT_LENGTH, a token that is neither `\d+` nor `\d+\s*-\s*\d+`, a range whose start is above its end, and 0 are `lines_invalid`; a number above `$lineCount` is `line_missing` with n.
- R-19-09-3 (redaction): `final class RedactVersion` with `public const string MARKER = '[REDIGOVÁNO]'`, `public const int PEM_BLOCK_MAX_LINES = 200`, `public const int MAX_REASON_LENGTH = 500`, private `const string SETTING = 'kokpit.redacting_knowledge_version'`, `__construct(private readonly SecretScanner $scanner)` and `handle(User $actor, KnowledgeArticle $article, int $versionNo, RedactionScope $scope, string $lines, mixed $reason): RedactResult`:
  1. `Gate::forUser($actor)->authorize('update', $article)`; the reason must be a string without a NUL byte (`knowledge.errors.nul_character` on `reason`), non-blank after trim (`redact.errors.reason_required`) and at most MAX_REASON_LENGTH characters (`reason_too_long` with max); only the length of the trimmed text (mb_strlen) is kept, and the text itself is discarded at once: it never reaches the database, the activity log, an exception, the result or a log line (OD-1).
  2. In `try { DB::transaction(...) } catch (PDOException $e) { throw new ArticleWriteFailed(...) }`: lock the article with `withTrashed()` (archived articles can be redacted, UI-SPEC section 8), authorise the locked row, read the version (firstOrFail).
  3. Split the stored body keeping its separators (`preg_split('/(\r\n|\r|\n)/', $body, -1, PREG_SPLIT_DELIM_CAPTURE)`), so the bytes of unselected lines, CRLF inside code blocks included, stay exactly as stored. Whole scope: the new body is MARKER. Lines scope: `RedactionLines::parse($lines, count of lines)`; each selected line that matches the private key header `/-----BEGIN [A-Z0-9 ]{0,100}PRIVATE KEY[A-Z ]{0,20}-----/` extends to the first later line matching `/-----END [A-Z0-9 ]{0,100}PRIVATE KEY[A-Z ]{0,20}-----/` within PEM_BLOCK_MAX_LINES lines, else to the last non-blank line of the contiguous block, capped there too (the extended ranges go into the result); blank lines and lines already equal to MARKER are skipped; nothing left is a ValidationException on `lines` with `nothing_to_redact`; every remaining selected line becomes MARKER.
  4. A new body longer than `KnowledgeArticle::MAX_BODY_LENGTH` is a ValidationException on `lines` with `too_long` and max (Pitfall 11); an unchanged body is `nothing_to_redact`.
  5. Write the redaction row with forceFill (version_id, actor_id, scope, reason_length); `DB::select("select set_config('kokpit.redacting_knowledge_version', 'on', true)")`; `DB::table('knowledge_article_versions')->where('id', ...)->update(['body_md' => $new])`; when the version number equals the locked article's version_no, `DB::table('knowledge_articles')->where('id', ...)->update(['body_md' => $new, 'redaction_no' => $locked->redaction_no + 1])`; then `select set_config('kokpit.redacting_knowledge_version', 'off', true)` right after the updates (Pitfall 9; a failed update aborts the transaction, whose rollback, or the rollback to the savepoint, discards the setting). Query builder only: no model event, no attribute activity.

  7. After the commit, `$this->scanner->scan($new)` gives the remaining findings (rule and line only).
  `RedactResult` (`final readonly`): `int $versionNo`, `bool $current`, `list<int> $redactedLines`, `list<array{from: int, to: int}> $keyRanges`, `list<SecretFinding> $remainingFindings`. The class docblock names RedactVersion as the second reviewed body writer and the only user of the setting.
