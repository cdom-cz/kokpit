Rulings made in this plan (recorded):
- R-19-06-1 (routes, research A5): `getPages()` gains, in this order after `edit`: `'versions' => ListArticleVersions::route('/{record}/versions')`, `'compare' => CompareArticleVersions::route('/{record}/versions/compare')`, `'version' => ViewArticleVersion::route('/{record}/versions/{version}')`. The static compare path is registered before the parameter path, and `ViewArticleVersion::mount()` also answers 404 for a `version` that is not all digits, so the order is not the only guard.
- R-19-06-2 (sub-navigation): `KnowledgeArticleResource::getRecordSubNavigation(Page $page): array` returns `$page->generateNavigationItems([...])` over `ViewKnowledgeArticle::class`, `EditKnowledgeArticle::class` (left out when the page's record is trashed, because the edit URL answers 404 for an archived article) and `ListArticleVersions::class`. Filament's Czech defaults label the first two Zobrazit and Upravit; `ListArticleVersions::getNavigationLabel()` returns `knowledge.versions.navigation`. `ListArticleVersions::getNavigationItemActiveRoutePattern()` returns the route names of the three version pages (`getRouteName()` of each), so Verze stays active on the version view and the compare page.
- R-19-06-3 (versions table): `ListArticleVersions extends ManageRelatedRecords` with `protected static string $resource = KnowledgeArticleResource::class`, `protected static string $relationship = 'versions'`; `mount(int|string $record)` calls `abort_unless(KnowledgeArticleResource::canAccess(), 403)` before `parent::mount($record)`; title `knowledge.versions.title` with the article title. Table: `modifyQueryUsing` with `->reorder()->orderByDesc('version_no')` (the relation has a baked-in ascending order), a select of `id, article_id, version_no, title, author_id, created_at, restored_from_version_no` (never body_md), `->with('author:id,name')`, `->withExists('redactions')`; columns Verze (`knowledge.versions.version_label`, with the success badge `knowledge.versions.badges.current` on the row whose number equals the article's version_no), Autor, Vytvořeno (Europe/Prague, `LocalisationServiceProvider::DATE_TIME_FORMAT`), Značky (gray badge restored_from with the arrow-uturn-left icon, warning badge redacted with the eye-slash icon); 25 rows per page; no bulk action, no create, edit or delete action, no search; record URL to the version view; row actions as icon buttons with tooltip and an explicit `aria-label` equal to the tooltip: view (eye, `knowledge.versions.actions.view`) and compare previous (arrows-right-left, `compare_previous`, hidden on version 1, linking to compare with from n-1 and to n). The restore and redaction actions are added by 19-11 into an overflow group labelled `knowledge.versions.actions.more`.
- R-19-06-4 (version view): `ViewArticleVersion extends Filament\Resources\Pages\Page` with `use InteractsWithRecord`; `mount(int|string $record, string $version)`: the 403 guard first, then `$this->record = $this->resolveRecord($record)` (archived articles open, as their view does), `ctype_digit($version)` or 404, then `KnowledgeArticleVersion::query()->where('article_id', ...)->where('version_no', (int) $version)->firstOrFail()`; the number is kept in a `#[Locked] public int $versionNo`. Title `knowledge.versions.version_label`. Header actions: back link (`knowledge.versions.actions.back`, gray link to the versions page) and compare with previous (gray, hidden on version 1); 19-11 adds restore and redact. The view `filament.knowledge.version-view` renders: the meta line `knowledge.versions.meta` (number, author name, created_at in Europe/Prague) with the same badges as the table, then at most one of each callout (info `versions.callouts.old` with :current and the link `versions.actions.view_current` to the version view of the current number, shown when this is not the current version; warning `redacted_heading` / `redacted_body` when the version has a redaction row; info `archived` when the article is archived), then the stored title as a 16px/600 line, then `KnowledgeMarkdown::render($version->body_md)` inside the existing `filament.knowledge.prose` view. Escaped echo only around the rendered HTML string the prose view already prints.
- R-19-06-5 (compare page): `CompareArticleVersions extends Filament\Resources\Pages\Page` with `use InteractsWithRecord`; `#[Url] public ?string $from = null; #[Url] public ?string $to = null;`; mount: 403 guard, resolve the record, then normalise: missing `to` means the article's current number, missing `from` means `to` minus 1 (or `to` when `to` is 1); every value must be all digits and name an existing version of this article, else 404; the same normalisation runs in `updatedFrom()` and `updatedTo()` (a forged Livewire value is a 404, never a query with a bad cast). The two versions are read as two rows with their bodies, only for this request. The view `filament.knowledge.version-compare` shows two native selects (`x-filament::input.wrapper` + `x-filament::input.select`, `wire:model.live`, labels `knowledge.diff.from` and `knowledge.diff.to`, options `knowledge.diff.option` "Verze :n · :date" newest first) with `wire:loading` on the Filament loading indicator targeting from and to, the header link `knowledge.diff.view_to`, and then either `knowledge.diff.same_version` (from equals to) or the 19-03 component `filament.knowledge.version-diff` with `VersionDiff::compare(fromBody, toBody)`, both titles, caption `knowledge.diff.caption`. Title `knowledge.diff.title`. A Partner never reaches the selects: the mount guard comes first.
- R-19-06-6 (isolation): `tests/Isolation/KnowledgeScreensTest.php` adds the versions, version 1 and compare URLs of an active and of an archived article to `knowledgeScreensUrls()` (so the existing 403, Partner without client and guest cases cover them), plus a case that a Partner asking the compare URL with the canary article shows no canary; `tests/Isolation/RouteWalkTest.php` teaches `walkedUrl()` the parameter `version` of the route `filament.admin.resources.knowledge-articles.version` (the canary article has version 1, so it fills 1) next to the existing parameter cases.
