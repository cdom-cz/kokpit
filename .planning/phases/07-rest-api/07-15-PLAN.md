<objective>
Close gap 3 of 07-VERIFICATION.md (WR-02, batch part): a batch item that fails for any reason other than a validation refusal is reported as a failed item instead of aborting the request, so the answer stays a 2xx whenever earlier items were saved and the Idempotency-Key keeps protecting the retry.

Purpose: roadmap success criterion 3 ("the same idempotency key does not create a duplicate; a batch saves every valid item and reports only the failed ones") breaks today when a late item throws a non-validation exception: earlier items are committed, the request ends in 500, `EnsureIdempotency` releases the key, and the advertised retry with the same key saves those items a second time.
Output: the per-item mapping in `TimeEntryBatchController`, the Czech item message, the documentation, and the batch regression tests (injected fault and bad-range item, each with a same-key retry).
</objective>
