Decisions carried in (locked): D-15 (one optional jsonb `external`, object only, about 4 KB from config, on single create, batch create and update, returned, not in the UI, no unique index, no dedup, not in the activity log allowlist; reversibility costly). The Actions stay the single place for rules: the `external` rule lives in `TimeEntryInput` next to `description()`, additive and backwards compatible (UI callers never send the key).

Decisions made in this plan (recorded):
- Cast `object` (not `array`): `{}` stays an object; nested objects decode as `stdClass`.
- The depth cap is 8 levels (`TimeEntryInput::EXTERNAL_MAX_DEPTH`), checked by `json_encode` with that depth; the size is the byte length of the compact JSON (`JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES`).
- The raw body is decoded once per request with `json_decode($request->getContent(), false)`; only `property_exists` on the decoded object decides whether `external` was sent (absent keeps, null clears).
- The column needs no change to the frozen-row guard: the guard compares `to_jsonb(NEW) - allowed` with OLD, so a new column is frozen on billed rows automatically (Phase 6 migration header).

Fictional data only (external examples such as `{"source": "demo-tracker", "id": "A-1001"}`). Run `scripts/check-sensitive.sh` before every commit; never bypass the hook.
