Decisions made in this plan (recorded):
- The validity choices are the enum `ApiTokenExpiry`; the status column is computed by the enum `ApiTokenStatus` (7-day "Vyprší brzy" threshold fixed, UI-SPEC U-9).
- Identity confirmation is password plus TOTP (UI-SPEC U-5) through `Hash::check` and `AppAuthentication::make()->verifyCode($code, null, shouldPreventCodeReuse: true)`; a recovery code is never accepted here. The attempt limiter is `RateLimiter` key `api-token-confirm:<user id>`, 5 per 60 s.
- Filament validates the required fields of the action form before the handler runs; the handler then checks authorization, throttle, password and code in that order. Nothing is created on any failure, so the visible difference from the UI-SPEC check order is only which error shows first when several are wrong.
- The one-time modal is a second page action (`showToken`) opened from the create handler with `replaceMountedAction`; the plain token lives only in a `#[Locked]` public property of `ListApiTokens` that the modal button clears.
- The "Dokumentace API" link points to `url((string) config('scribe.laravel.docs_url', '/docs'))` and opens in a new tab with `rel="noopener"`, so it works whether or not plan 07-02 has run yet.
- Activity rows (U-12) are written with a manual `activity()` call in the two Actions (event names `api_token.created` and `api_token.revoked`, properties `name` and `abilities` only), so the model allowlist list stays untouched.

Planner assumption (UI-SPEC UI Considerations, the one unresolved row): if the Admin session expires while the create modal is open, the stock Livewire expired-session handling applies (re-login); no token is created and nothing is shown.

Test-file rule: helpers as static methods (extend `Tests\Support\ApiFixtures` only if needed by several files; otherwise private closures in the test), never new global functions (`currentTotpCode()` already exists globally in `tests/Feature/Auth/TwoFactorEnforcementTest.php`). Tests run with `KOKPIT_REQUIRE_ADMIN_2FA=false`, so each test sets a TOTP secret on the Admin itself and computes the code with `PragmaRX\Google2FAQRCode\Google2FA` like that file does.

Fictional data only. Run `scripts/check-sensitive.sh` before every commit; never bypass the hook.
