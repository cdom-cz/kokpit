# Phase 07 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: Phase 7 is an API phase. Its only interactive UI surface is the Admin-only API token management screen in the Filament panel: the token list, the create modal (name, abilities, expiry choice, password and 2FA re-confirmation), the one-time plain-text token modal, and the revoke action. One secondary surface is only specified at the edge: the generated OpenAPI documentation page (`/docs/api`, produced by Scribe at release, no custom UI). A Partner sees nothing of this phase: no navigation item, no page, no string.
>
> Nothing is built yet. Everything below is a target for plans, not a record of built work.

Upstream decisions applied (not re-asked): `07-CONTEXT.md` D-01 to D-05 (token abilities, optional expiry 30 / 90 / 365 days or none with default none, list columns, one-time plain-text modal, password and 2FA re-confirmation before creating, UUID token model), D-17 (docs served only to a logged-in Admin), `06-UI-SPEC.md` (design system, spacing, typography, colour roles, access conventions and copy tone, treated as the locked baseline), `02-UI-SPEC.md` and `05-UI-SPEC.md` through it, `REQUIREMENTS.md` AP-01 and AP-05, and the Czech wording already in `lang/cs/kokpit.php` (navigation group "Správa").

Panel UI copy is Czech; each string below is given in Czech with an English gloss in the right-hand column or in brackets. Only the Czech string is the contract for the plan that builds it.

Contract notes:

- Declared sizes: 14, 16, 24, 30. Declared weights: 400, 600. No other size, no 12px, no weight 500 or 700 in application code.
- The plain-text token uses body size and weight (14px / 400) with the `font-mono` family; it is the only text on this surface not in Inter.
- Secondary text (helper lines, the page subheading, "Nikdy") uses Filament's gray text colour at 14px, never a smaller size and never an opacity below 0.8.
- Dates: `j. n. Y` for dates and `j. n. Y H:i` for date and time; instants stored in UTC, shown in `Europe/Prague`. Empty values show `—`, except where a specific word is given (the "Naposledy použit" column reads "Nikdy", the "Platnost do" column reads "Bez omezení").
- Check at the gate that the Czech diacritics render in Inter: "Oprávnění", "Ověřovací", "Zneplatnit", "Naposledy použit", "Vypršel".

## Access and Visibility Contract

Applies to every new class; the registry and canary tests enforce it.

- `ApiTokenResource` (and any page, action or Livewire component this phase adds) declares `#[AccessRule(AdminOnly, reason)]`. The token model declares `#[NotPartnerScoped]` (it is Admin-only infrastructure, never shown to a Partner) per the Phase 2 conventions.
- The navigation item is absent for a Partner. A Partner opening `/admin/api-tokens` gets the same refusal as any other Admin-only page. A forged Livewire call by a Partner (create, revoke) is refused with 403 and writes nothing.
- The list shows only the tokens of the signed-in Admin. The revoke action re-checks, on the server, that the token belongs to the signed-in Admin before deleting it, not only on render.
- Creating a token is refused unless the user is the Admin and has an active two-factor secret (Admin has it mandatory, `EnsureAdminHasTwoFactor`). If the secret is somehow missing, the create action fails closed with the generic failure toast and writes nothing.
- The plain-text token appears in exactly one place: the open one-time modal (Surface C). It is never in the list, a notification, a toast, the bell, the activity log, a log line, the URL, the session flash, browser storage or the page HTML after the modal closes. Only its hash is stored (Sanctum). The Livewire property that carries it is `#[Locked]` and is cleared when the modal closes.
- The canary harness gets one line for API access (Claude's discretion per CONTEXT); the rendered-HTML check proves a Partner page contains none of the strings under "Never on a Partner surface" in the Copywriting Contract.

## Screens and Interaction Contract

### Visual anchors

| Screen | Primary anchor | Why |
|--------|----------------|-----|
| Token list (A) | The table, led by the Název and Stav columns; "Nový API token" is the only accent element above it | The screen answers "which tokens exist, are they still in use, which expire" |
| Create modal (B) | The Název field first, then the abilities; "Vytvořit token" is the single accent button | Intent first (what for, what may it do), identity confirmation last |
| One-time token modal (C) | The `warning` callout "Zkopírujte si token teď" directly above the token block | The token is gone when the window closes; the notice must be read before the token is copied |
| Revoke confirmation (D) | The heading question "Zneplatnit token?" | Destructive, irreversible, affects running automations |

### Surface A: Token list `/admin/api-tokens` — new (AP-05; D-02, D-03)

- Heading "API tokeny". Subheading (gray, one line): "Tokeny, kterými se externí nástroje přihlašují k API. Plný text tokenu se zobrazí jen při vytvoření." Header actions, left to right: "Dokumentace API" (gray, `OutlinedBookOpen`, a link to `/docs/api` that opens in a new tab with `rel="noopener"`), then "Nový API token" (primary, `OutlinedPlus`) which opens Surface B.
- Columns in order: **Název** (semibold text), **Oprávnění** (one gray badge per ability: "Čtení času" for `time:read`, "Zápis času" for `time:write`; the technical ability id is the badge tooltip), **Vytvořeno** (`j. n. Y H:i`, sortable), **Naposledy použit** (`j. n. Y H:i`, or "Nikdy" in gray when the token was never used; Sanctum `last_used_at`), **Platnost do** (`j. n. Y`, or "Bez omezení" when the token has no expiry), **Stav** (badge, see below). No IP address, user agent or token fragment is shown (D-03).
- Stav rules: "Vypršel" when the expiry date has passed; "Vyprší brzy" when the token expires in 7 days or less; otherwise "Aktivní". "Bez omezení" tokens are always "Aktivní".
- Default sort: Vytvořeno descending. Pagination stock (25 per page); no search, no filters (an Admin has a handful of tokens). No bulk actions.
- Row: not clickable (there is no view or edit page). One row action, shown on every row including expired ones: "Zneplatnit token" (`danger`, `OutlinedNoSymbol`, a labelled button, not hidden in a menu), which opens Surface D.
- After a token is created or revoked the list refreshes in place (no full reload).
- Empty: the empty state in the Copywriting Contract, with "Nový API token" reachable inside it (`OutlinedKey` icon).

### Surface B: Create token modal — new (AP-01, AP-05; D-01, D-02, D-04)

Opened by "Nový API token". Heading "Nový API token", width 512px, stock close button and the footer buttons "Vytvořit token" (primary) and "Nevytvářet token" (gray, set with `modalCancelActionLabel`). Esc and click-away close it as usual; nothing has been created yet.

Form, in order:

1. **Název** (`TextInput`, required, at most 80 characters, autofocus, placeholder "Například import výkazů"). Helper: "Jen pro vaši orientaci, například název nástroje, který token použije."
2. **Oprávnění** (`CheckboxList`, required, at least one, **nothing preselected** so the choice is deliberate; least privilege). Options with a one-line description each: "Čtení času" ("Seznam a detail časových záznamů a vyhledávání klientů, projektů a úkolů.") and "Zápis času" ("Vytváření, úprava a mazání časových záznamů.").
3. **Platnost** (`Select`, not searchable, no empty placeholder, default "Bez omezení"). Options: "Bez omezení", "30 dní", "90 dní", "365 dní". A live helper line under the field: for "Bez omezení" the text "Token platí, dokud ho nezrušíte."; for a limited choice "Token přestane platit :date." with the computed expiry date (`j. n. Y`, the end of that day in `Europe/Prague`).
4. **Potvrzení totožnosti** (a `Section` without collapse, heading "Potvrzení totožnosti", description "Vytvoření tokenu vyžaduje potvrzení heslem a kódem z ověřovací aplikace."):
   - **Heslo** (`TextInput` `password()` and `revealable()`, required, `autocomplete="current-password"`),
   - **Ověřovací kód** (`OneTimeCodeInput`, six digits, required, `autocomplete="one-time-code"`). The code is the current TOTP code of the Admin's authenticator app (the 2FA the Admin already uses); a recovery code is not accepted here. A TOTP code that was already used is refused (replay protection).

Behaviour rules:

- Order of server checks on submit: authorization, throttle, password, code, then field validation of the rest. A wrong password or wrong code leaves the modal **open**, keeps Název, Oprávnění and Platnost, clears Heslo and Ověřovací kód, and shows the field error under the offending field. Nothing is created.
- Attempts at identity confirmation are throttled per user (the limiter value is the planner's, recommended 5 per minute); beyond it the field error under Heslo reads the throttle string and no check runs.
- On success the create modal closes and the one-time token modal (Surface C) opens in the same interaction. There is no toast and no page navigation, because the modal is the feedback.
- The Admin account only ever has its own tokens; the modal has no "owner" field.

### Surface C: One-time token modal — new (D-04)

Opened by the create handler with the freshly issued plain-text token. Heading "Token byl vytvořen", width 512px.

Layout, top to bottom:

1. A `warning` `Callout` with `OutlinedExclamationTriangle`: heading "Zkopírujte si token teď", body "Tento token se zobrazuje jen jednou. Po zavření okna ho už nejde zobrazit. Pokud ho ztratíte, vytvořte nový token a tento zneplatněte."
2. A summary of what was created, three lines of label and value (labels semibold, values body): "Název", "Oprávnění" (the same two gray badges as the list), "Platnost" ("Bez omezení" or "do :date").
3. The **token block**: a read-only, bordered surface (Secondary colour with a 1px ring, 16px padding, `font-mono`, 14px, `break-all`) holding the full plain-text token. One click or focus selects the whole text (`select-all`) so Ctrl/Cmd+C works without the button. The recommended mechanism is a read-only `Textarea` (3 rows); a stock `TextInput` with `copyable()` is an acceptable fallback if it keeps the full token visible in the viewport at 375px. The block is initially focused when the modal opens, with the text selected.
4. Beside or under the block, 8px away, a gray button **"Zkopírovat token"** (`OutlinedClipboard`). It copies the full token to the clipboard and shows the success toast "Token byl zkopírován". It never copies a partial value. If the clipboard API is unavailable (non-secure context), the button does nothing destructive and the selected text remains copyable by hand.
5. One helper line: "V požadavcích ho posílejte v hlavičce Authorization jako Bearer token." followed by the text link "Dokumentace API" (new tab).

Footer: a single primary button **"Token mám uložený"** that closes the modal. There is **no** cancel button, **no** top-right close button, and Esc and click-away are **disabled** (`modalCloseButton(false)`, `closeModalByEscaping(false)`, `closeModalByClickingAway(false)`), so the one-time display cannot be dismissed by a stray click or keystroke. The only exit is the button. If the Admin reloads the page or navigates away with the modal open (browser back, reload, closing the tab), the token is gone for good; this is stated in the callout and is the accepted trade-off of D-04.

On close: the Livewire property holding the token is cleared, the list refreshes and shows the new row (status "Aktivní", "Naposledy použit" = "Nikdy").

### Surface D: Revoke token confirmation — new (AP-05; D-02, D-03)

- Trigger: the row action "Zneplatnit token" on Surface A (`danger`). Confirmation modal with a question heading, a one-sentence consequence and a submit equal to the action name, per the Phase 6 cross-cutting rule.
- Heading "Zneplatnit token?". Body for an active token: "Token :name přestane okamžitě fungovat. Nástroje, které ho používají, dostanou chybu 401 a bude jim potřeba zadat nový token. Tuto akci nelze vrátit." Body for an expired token: "Token :name už vypršel. Odstraní se ze seznamu. Tuto akci nelze vrátit." Submit "Zneplatnit token" (`danger`), cancel "Ponechat token" (gray, set with `modalCancelActionLabel`; it keeps the token working and closes the modal).
- Revoking does **not** ask for the password or a 2FA code (D-04 requires re-confirmation only for creating). It deletes the token row; the next request carrying it receives 401.
- Success toast "Token byl zneplatněn"; the row disappears from the list.
- If the token no longer exists (revoked in another tab): the info toast "Token už byl zneplatněn." and the list refreshes. Nothing else happens.

### Surface E: API documentation page `/docs/api` — specified at the edge only (AP-05; D-17)

No Kokpit-designed UI: the page is the stock Scribe documentation UI (D-17 revised: generated at release, assets served locally, no CDN). The contract is limited to:

- Reached from "Dokumentace API" on Surface A and Surface C; opens in a new tab.
- Visible only to a logged-in Admin (gate or middleware; exact route path set by the plan). A Partner or a guest gets 403; no content, no route list, no spec JSON (the OpenAPI spec route has the same rule).
- Theme follows the operating-system colour mode (Scribe stock theme); no custom CSS, logo, font or colour. Page title "Kokpit API".
- The documentation itself is in English (it documents a machine interface and it is generated from the code at release); it contains fictional example values only (`example.com` addresses, placeholder IDs) and never a real token.
- The page has no navigation back into the panel; the Admin returns by closing the tab.

### Cross-cutting interaction rules (this phase)

- Keyboard: every control works by keyboard alone with the accent focus ring: the header actions, the create modal (Tab order Název, Oprávnění, Platnost, Heslo, Ověřovací kód, then the footer; Enter in the code field submits), the one-time modal (initial focus on the token block, Tab to "Zkopírovat token", Tab to "Token mám uložený"), the revoke confirmation.
- No generic button labels: every modal footer button is a specific verb plus noun. Each cancel button is named for what it declines ("Nevytvářet token", "Ponechat token") through `modalCancelActionLabel`; the stock "Zrušit" is never used in this phase.
- A hidden action is not rendered, not disabled. No control on this surface is ever disabled to explain a rule; errors appear as field errors or toasts.
- Destructive actions use a confirmation modal with a question heading, a one-sentence consequence and a submit label equal to the action name. Creating a token is not destructive and is confirmed by identity, not by a dialog.
- Starting a create, copy or revoke uses Filament's stock in-flight state (disabled submit, spinner) so a double click cannot submit twice; the create handler is also safe against a double submit because a repeated submit would need a fresh one-time code.
- Enum and ability labels live in `lang/cs/kokpit.php` under `kokpit.api_tokens.*`; the ability id to label map is one place so the list badges and the create options never drift.
- No money, rate or price appears anywhere on these surfaces.

This run had no human available. Each item can be overturned without changing the rest of the contract. Ids are prefixed U- to stay apart from the CONTEXT decision ids.

| ID | Decision or assumption | Basis |
|----|------------------------|-------|

| U-2 | The token screen is a Filament Resource with a list page only; creating is a custom header action with a form, not `CreateAction`; revoke is a row action. The outcome (columns, modals, copy) is the contract, the mechanism is a recommendation | CONTEXT D-03 leaves the structure to Claude |
| U-3 | The navigation item sits in the existing group "Správa" at sort 92, between "Nastavení" and "Systém", with the label "API tokeny" | Token management is an administration concern; the group already exists in `lang/cs/kokpit.php` |
| U-4 | The plain-text token is set in `font-mono` (stock Tailwind stack, 14px, 400); the only departure from "Inter only" | A 77 character secret must keep look-alike characters distinguishable; no web font, size or weight is added |
| U-5 | Identity confirmation is the account password **and** a current TOTP code (not a recovery code) in the create modal itself, not a separate step or a redirect | CONTEXT D-04 says "password/2FA"; Admin has mandatory 2FA, so requiring both is the stronger reading and keeps the whole flow in one modal. If only one factor was meant, drop the other field; the rest of the contract is unchanged |
| U-6 | No ability is preselected; at least one is required | Least privilege; CONTEXT D-01 gives no default |
| U-7 | The one-time modal can be closed only by its button (no Esc, no click-away, no close icon); no extra "I have copied it" checkbox | Protects the one-time display from an accidental dismissal without adding friction beyond one deliberate click |
| U-8 | Revoke asks for no password or code, only a confirmation modal | CONTEXT D-04 requires re-confirmation for creating; revoking only reduces access, and the Admin must be able to do it fast if a token leaks |
| U-9 | Status "Vyprší brzy" threshold is 7 days, fixed in the contract (not a config value) | Not stated upstream; a hint only, it changes no behaviour |
| U-10 | An expired token still appears in the list and can be revoked (removed); revoked tokens disappear (no history rows) | CONTEXT D-02 and D-03 mention revoke only; keeping the list limited to rows that exist in the token table |
| U-11 | The documentation page is the stock Scribe UI, English content, opened in a new tab | CONTEXT D-17 fixes the tool and the gate; presentation is not discussed |
| U-12 | Recommended (outside this UI contract): token creation and revocation write an activity log row with the name and abilities only, never the token or its hash | Audit of an access-granting action; the planner decides whether it fits the allowlist pattern from Phase 3 |
