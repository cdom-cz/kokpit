<objective>
The token-secured `/api/v1` skeleton: an Admin's real Sanctum token reads one time entry, every refusal path is a clean 401/403/404 (never 500), and reads and writes are rate limited per token.

Purpose: AP-01 (token-only API with abilities), the read part of AP-02 (entry detail), the rate-limiting part of AP-05. Every later plan of the phase adds routes into the groups created here; the route walk that checks each of them automatically is built in plan 07-03 (wave 2), before any further route is added.
Output: `routes/api.php`, published `config/sanctum.php`, `ApiServiceProvider`, `ApiAbility` (cases and `values()`; its labels follow in plan 07-03), the uuid-guarded token lookup, `TimeEntryController@show`, `TimeEntryResource`, the `api` block of `config/kokpit.php`, `lang/cs/api.php`, the shared test fixture class and two test files.

Decisions made in this plan (recorded):
- The API routes live in `routes/api.php`, loaded by `withRouting(api: ..., apiPrefix: 'api/v1')`, so the existing `shouldRenderJsonWhen` (`$request->is('api/*')`) renders every error as JSON.
- Two route groups: reads (`auth:sanctum`, `abilities:time:read`, `throttle:api-read`) and writes (`auth:sanctum`, `abilities:time:write`, `throttle:api-write`). Ability strings come from `ApiAbility` so they cannot drift.
- Controllers take plain string route parameters (no implicit model binding) and resolve rows themselves; this keeps Scribe's URL-parameter extraction from touching the database later (plan 07-02) and lets every miss answer the same Czech 404 message without the model class name.
- The 404 message is `api.errors.not_found` in a new `lang/cs/api.php` (API-layer strings live there; domain strings stay in `lang/cs/kokpit.php`). API error language: Czech, like the validation messages (UI-SPEC U-13 resolved).
- The time entry JSON is proposed here and confirmed by the owner at the decision checkpoint of plan 07-02 (Task 2) before any further endpoint builds on it (D-09 is one-way; plan 07-02 Task 3 walks through that door and pins the confirmed contract).
- Research A11 (Sanctum `token_prefix` for secret scanners) is not adopted: no decision requires it; it can be added later without breaking tokens already issued.
- Two pieces live in plan 07-03 (wave 2) to keep this plan within the file budget: `HasLabel` on `ApiAbility` with the two Czech ability labels (first shown on the token screen; `EnumLabelsTest` scans only enums that implement `HasLabel`, so the bare enum here needs no label yet), and the route walk `tests/Isolation/ApiAccessTest.php`. No route is added between this plan and wave 3, so the walk still guards every later endpoint by construction.

Research assumptions surfaced here: A1 (`vendor:publish --tag=sanctum-config` exists; if not, copy `vendor/laravel/sanctum/config/sanctum.php` by hand), A2 (`abilities:time:read` parses as one parameter `time:read`; the first 403 test proves it).

Test-file rule: Pest helper functions are global for the whole suite, and `tests/Feature/TimeTracking/TimeEntryActionsTest.php` and `tests/Feature/Auth/TwoFactorEnforcementTest.php` already declare global helpers. New API tests put helpers as static methods on `Tests\Support\ApiFixtures`, never as new global functions.

Fictional data only (example.com, `exampleEmail()`, fragments at runtime). Run `scripts/check-sensitive.sh` before every commit; never bypass the hook. Tests run in DDEV.

| Boundary | Description |
|----------|-------------|
| internet -> /api/v1 | bearer token and path parameters are untrusted |
| browser session -> /api/v1 | a panel cookie must not count as an API credential |
| token row -> request user | the token owner may be a Partner, role-less or deactivated |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Elevation of privilege | Sanctum session guard (TransientToken can every ability) | high | mitigate | `config/sanctum.php` `'guard' => []`; api group has no session middleware; test: web-guard Admin without bearer gets 401 |
| T-07-02 | Information disclosure / DoS | malformed bearer reaching a uuid column (22P02 -> 500) | high | mitigate | `PersonalAccessToken::findToken` refuses a non-uuid id part; `whereUuid('timeEntry')`; 404 message names no class; tests for every malformed shape |
| T-07-03 | Elevation of privilege | token of a Partner, role-less or deactivated user | high | mitigate | `Sanctum::authenticateAccessTokensUsing` accepts only an active Admin; tests for all three |
| T-07-04 | Elevation of privilege | ability bypass on a route | high | mitigate | `abilities:` alias with strings from `ApiAbility`, set on both route groups; 403 tests per direction; the route walk of plan 07-03 (T-07-56) asserts every api/v1 route carries one |
| T-07-05 | Denial of service | request flooding, rate-limit evasion with one token | medium | mitigate | named limiters keyed by token id (IP fallback), Redis-backed in production, set on both route groups; 429 with Retry-After; the route walk of plan 07-03 (T-07-56) forces a throttle on every route |
| T-07-06 | Spoofing | stolen or replayed token | high | mitigate | Sanctum stores only the sha256 hash, compares with hash_equals; per-token expiry and revocation (row delete) checked on every request; tests for expired and revoked tokens |
| T-07-07 | Information disclosure | time entry JSON leaking money or internals | high | mitigate | `TimeEntryResource` lists every key explicitly (no `toArray()` of the model); test pins the exact key list |
| T-07-SC | Tampering | npm/pip/cargo/composer installs | low | accept | no package added in this plan (laravel/sanctum already installed) |
</threat_model>
