<objective>
Give every supplier bank account a stable identity and allow several accounts per currency, so that a document can later reference the account it was told to use instead of deriving it from its currency. This is the tracer of the account half of the phase: settings form -> settings class -> settings table -> reload, with the id surviving every Livewire round trip.

Purpose: P14-03 (several accounts per currency, a stable id per account); D-04 (overrides Phase 3 D-04 "one account per currency"); research Pattern 2, Anti-Patterns "generating account ids on read" and "relying on the Repeater default", Runtime State Inventory (settings payload); owner answer OA-6 (the Repeater `Hidden('id')` round trip is a Wave 0 test).
Output: the id on `BankAccount`, id assignment and lookups on `BankAccountSettings`, the new id rule, the settings migration, the settings form field, and the rewritten settings tests.
</objective>

Rulings made in this plan (recorded):
- R-14-01-1 (identity): `BankAccount` gains `public ?string $id = null` as the LAST constructor parameter, so the eleven positional call sites (tests and fixtures) do not change. `fromArray()` reads `id` (a string, else null), `normalised()` keeps the id unchanged, and a new `withId(string $id): self` returns a copy with the id. `toArray()` stays exactly the Phase 10 shape WITHOUT the id: it is the shape of the bank snapshot copied into the Partner-readable `invoices.bank_snapshot` (through `InvoiceSnapshot`), whose keyed fingerprint `bank_fingerprint` (IN-15) must not change for an unchanged account, and a settings id has no use for a Partner. A new `toStoredArray(): array` returns `['id' => $this->id, ...$this->toArray()]`; it is used by `BankAccountListCast::set()` (the settings payload) and by `BankAccountSettings::toFormState()` (the form state and the list rules). The id is a UUID v7 string from `Str::uuid7()` (the repository already makes every generated UUID version 7, `app/Providers/ModelConventionsServiceProvider.php`).
- R-14-01-2 (assignment): ids are assigned in exactly two places: `BankAccountSettings::save()` (after the per-account validation, every account whose id is null is replaced by `withId((string) Str::uuid7())`, then `parent::save()`), and the settings migration of R-14-01-5. `BankAccountListCast::get()` and `BankAccount::fromArray()` never create an id: a read must return the same id on every request (research Anti-Patterns). `fillFromFormState()` keeps an id that the form state carries.
- R-14-01-3 (rules): `BankAccountSettings::rules()` becomes `['accounts' => ['array', new UniqueAccountIds]]`. The new `App\Domain\Settings\Rules\UniqueAccountIds implements ValidationRule` passes for a list in which every account array has an `id` that `Str::isUuid()` accepts and no id appears twice; it fails with `kokpit.settings.bank.id_invalid` or `kokpit.settings.bank.id_duplicate` (Czech, fictional-data-free). Because `ValidatedSettings::save()` validates `toFormState()` after R-14-01-2 has assigned the missing ids, a list saved from the form always passes and a crafted or hand-written list is checked. The class that refused a second account of one currency is deleted together with its message key, and the class docblock of `BankAccountSettings` no longer says "at most one per currency" (D-04 overrides Phase 3 D-04).
- R-14-01-4 (lookups): `find(string $id): ?BankAccount` (exact id match, null for an unknown id or an account without id) and `firstForCurrency(string $currency): ?BankAccount` (the first account of the currency in list order, compared upper case: the D-05 preselection). The existing currency lookup method stays as a one-line delegate to `firstForCurrency()` for its present callers only (IssueChecks, InvoiceSnapshot, EditInvoice and two tests); its docblock says so, and plan 14-10 deletes it together with the architecture test that keeps it deleted. No new code may call it.
- R-14-01-5 (settings migration): `database/settings/2026_10_24_000100_add_ids_to_bank_accounts.php` returns an anonymous class extending `App\Domain\Settings\SettingsMigration` (its `up()` is final and runs `migrate()` as system). `migrate()` returns early when `bank.accounts` does not exist (`$this->migrator->exists()`), else `$this->migrator->update('bank.accounts', ...)` maps the decoded list: an entry that is an array without a string `id` gets `'id' => (string) Str::uuid7()`, every other entry and key is kept as stored. Running it a second time changes nothing. Precedent: `database/settings/2026_10_17_000200_distinct_proforma_number_pattern.php`.
- R-14-01-6 (form): in `SettingsPage::bankTab()` the Repeater schema starts with `Hidden::make('id')`, so the id of an existing account travels in the form state and comes back on save; a new item has none and gets one in `save()` (the domain, not the form, is the source of truth). The currency `Select` loses `->distinct()` and its comment says that several accounts may share a currency (D-04). The item label stays `label (CUR)`.
