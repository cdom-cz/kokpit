<objective>
Let the Admin change the payment method, the bank account, the card switch and the currency of an open issued document as independent choices, with the Stripe link following. The tracer: an open issued transfer invoice with an active card link is switched to online; the bank snapshot goes, the old link is deactivated as replaced, a pending link for the remaining amount is opened on the same pay URL, and the PDF is replaced.

Output: `DocumentPayment::forIssued()`, the reworked `UpdateIssuedDocument`, `PaymentLinks::deactivateLive()`, `IssuedEditFinisher` with `forceNewLink`, and the rewritten issued-edit and link tests.

Rulings made in this plan (recorded):
- R-14-07-1 (`DocumentPayment::forIssued(Invoice $locked, array $data, string $currency, bool $currencyChanged): array`): for an open issued invoice or proforma (credit notes never reach it: `assertEditable()` refuses them first). Stored values: method M0, Admin-only `bank_account_id` A0, switch S0, token T0, snapshot B0. Computed, in this order:
  1. method M = `method($data['payment_method'])` when the key is present, else M0;
  2. a change to online (M online, M0 not) is refused with `ValidationException` `payment_method` => `online_unavailable` when `onlineUnavailableReason($locked)` is not null;
  3. account A = `accountId($data['bank_account_id'])` when the key is present, else `preselect($currency)` when `$currencyChanged`, else A0;
  4. switch S = true for online; for transfer the strict boolean of `card_payment_enabled` when present (`card_payment_invalid` otherwise), else the client flag when M0 was online (OA-1), else S0; a transfer switch that goes from false to true is refused with `card_payment_enabled` => `card_payment_unavailable` when `CardPaymentSwitch::available()` is false;
  5. snapshot: for online the snapshot becomes null (OA-7); for transfer a new snapshot is taken when M0 was online, when A differs from A0, when `$currencyChanged`, or when `reload_bank` is the boolean true (a non-boolean `reload_bank` keeps the existing `InvalidArgumentException`); the account of the new snapshot is the configured account of A, and when the data did not send `bank_account_id` and A is null or no longer configured, the first account of `$currency` (the D-05 preselection, which also keeps the legacy refill behaviour); no account at all is `ValidationException` `bank_account_id` => `bank_account_required`; otherwise B0 stays (the issued snapshot is authoritative, research Pattern 2);
  6. token: when S is true and T0 is null, `PayToken::generate()` (set once; an existing token is never replaced, plan 14-02 guard).
  Returns `array{payment_method: DocumentPaymentMethod, bank_account_id: ?string, card_payment_enabled: bool, pay_token: ?string, bank_snapshot?: array<string, string|null>|null, method_changed: bool, card_changed: bool, changed: bool}` where `bank_snapshot` is present only when it changes and `changed` is true when anything of the five values differs from the stored ones.
- R-14-07-2 (`saveAdmin()` extended): takes the token as a fourth optional argument `?string $payToken = null` and writes it only when the stored token is null (set once), next to the account and the switch; still writes nothing when nothing differs.
- R-14-07-3 (`UpdateIssuedDocument`): `currencyChange()` no longer looks up a bank account (the refusal `bank_missing` under `currency` is gone; research Pitfall 5) and returns `['currency', 'rate']`; `header()` no longer handles `reload_bank` (moved into `forIssued()`); after `header()` and `currencyChange()` the Action calls `DocumentPayment::forIssued($locked, $data, $currency, $change !== null)`; `payment_method` and `bank_snapshot` (when present) join the header values written on the `invoices` row; `DocumentPayment::saveAdmin($locked, ...)` writes the Admin-only row; the early return "nothing to write" also requires `changed` false. Then, still inside the transaction and before the finisher: a method change calls `PaymentLinks::deactivateLive($locked, PaymentLinkDeactivation::Replaced)` (OA-3); otherwise a switch turned off calls `deactivateLive($locked, PaymentLinkDeactivation::Manual)` (the Admin switched card payment off by hand). The finisher is called with `forceNewLink: method_changed || (card_changed && S) || $change !== null`. A currency change keeps its `AmountChanged` deactivation through `reconcile()` in the finisher. `UpdateIssuedDocument` gains `PaymentLinks` in its constructor. The class docblock lists the new keys, states the T-10.1-24 reversal by OA-1, and drops "bank_missing when the settings hold no account for the new currency".
- R-14-07-4 (`PaymentLinks::deactivateLive(Invoice $locked, PaymentLinkDeactivation $reason): void`): refuses outside a transaction (`LogicException`, like `reconcile()`), locks the live row of the document `FOR UPDATE` and, when there is one, calls the existing `deactivate()` (which queues `DeactivatePaymentLinks` after the commit when a Stripe id exists); nothing when there is no live link. The class docblock names it as the second entry point besides `reconcile()`.
- R-14-07-5 (`IssuedEditFinisher::finish(User $actor, Invoice $locked, array $before, bool $forceNewLink = false)`): the default keeps every existing caller (`AddEntriesToDraft`, `ReleaseEntries`, `AddFixedAmount`) unchanged; with `forceNewLink` true the rule "the newest link was not switched off by hand" is skipped (OA-3, research Pattern 5 item 2); every other condition (issued, not cancelled, switch on, something owed, no live link) stays. Its docblock and the one of `paymentLink()` say so.
