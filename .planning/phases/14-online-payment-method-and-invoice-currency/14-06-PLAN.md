The amount due and the due date stay. No Admin-only row is read here: the method is a column of the Partner-readable `invoices` row (pinned by plan 14-02). The pay button stays the header action of `ViewPartnerInvoice` through `PartnerPayButton` (gated since plan 14-05).
- R-14-06-2 (Admin detail, `ViewInvoice`): the `payment_method` entry shows `$record->payment_method?->getLabel()` instead of `__('invoices.draft.payment_method_value')` (the key itself is removed by plan 14-08 when its last reader goes); the `bank_account` entry is visible only for a non-credit-note with method transfer; the variable symbol stays visible to the Admin (it is frozen and still identifies the document); the card switch entry ("Platba kartou: Ano/Ne") is unchanged.
- R-14-06-3 (test fixture): as in plan 14-05 (same wave as 14-04), an online document is made by issuing through the fixtures and then, as system, `update invoices set payment_method = 'online', bank_snapshot = null where id = ?` plus `update invoice_admin set card_payment_enabled = true, pay_token = ? where invoice_id = ?` on the open document; each test file keeps its own small helper.
