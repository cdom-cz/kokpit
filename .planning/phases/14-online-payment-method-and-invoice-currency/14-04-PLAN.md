<objective>
Make the payment method and the bank account real choices of a draft and carry them through the issue. The tracer: a draft created with the default transfer method and the preselected account is switched to online, issued, and comes out without a bank snapshot, with its card switch on, a pay token and a pending link.

Purpose: P14-01 (domain half), P14-04 (preselection and the transfer blocker), P14-09 (online needs card payment); D-02, D-03 (draft half), D-05, D-06; owner answer OA-1 (switch reset to the client flag on online -> transfer); research Patterns 1 and 2 (resolution rules), Pitfalls 3, 4 and 6.
Output: `DocumentPayment`, the draft Actions, the blockers, the issue pipeline, `InvoiceSnapshot::bankAccount()`, the error copy, the Wave 0 fixtures and the tests.
</objective>

- R-14-04-1 (the one rule): new `App\Domain\Invoicing\Support\DocumentPayment` (`final class`, static methods, settings read through `app(...)` at call time like `IssuedDocumentRules`), with the constant `CLIENT_OFF = 'client_off'` and:
  - `method(mixed $value): DocumentPaymentMethod` — an enum instance or a string `tryFrom`, else `ValidationException` `payment_method` => `invoices.errors.payment_method_invalid`;
  - `accountId(mixed $value): ?string` — null or blank is null; a string that `Str::isUuid()` accepts and `BankAccountSettings::find()` finds is returned; anything else is `ValidationException` `bank_account_id` => `invoices.errors.bank_account_unknown`. The account itself never travels, only the id of a configured account (extends T-10.1-28);
  - `preselect(string $currency): ?string` — `app(BankAccountSettings::class)->firstForCurrency($currency)?->id`; the only application caller of `firstForCurrency()` (assumption-delta decision of plan 14-01);
  - `account(Invoice $document): ?BankAccount` — reads `invoice_admin.bank_account_id` of the document: set and found -> that account; set and no longer configured -> null (never silently re-picked); NULL (a legacy row, or a draft created with no match) -> `firstForCurrency($document->currency)` (research Pattern 2 resolution rules);
  - `onlineUnavailableReason(Invoice $document): ?string` — `CardPaymentSwitch::unavailableReason()` (`settings_off`, `stripe_missing`), else `CLIENT_OFF` when the document's client has `online_payment_enabled` false, else null (D-03);
  - `forDraft(Invoice $lockedDraft, array $data, string $currency): ?array` — null for a credit-note draft that sends none of `payment_method`, `bank_account_id`; for a credit-note draft that sends either key, `ValidationException` under that key => `invoices.errors.credit_note_no_payment` (the `card_payment_enabled` key keeps its existing `card_payment_invalid` refusal); otherwise `array{payment_method: DocumentPaymentMethod, bank_account_id: ?string, card_payment_enabled: bool}` computed as: method = the data value through `method()` or the stored one (transfer when NULL); a change to online from a stored method that is not online is refused with `ValidationException` `payment_method` => `invoices.errors.online_unavailable` when `onlineUnavailableReason()` is not null (an already online draft is not refused on save; the issue blocks it); account = the data value through `accountId()` when the key is present, else `preselect($currency)` when `$currency` differs from the stored currency, else the stored `bank_account_id`; switch = true for online, else the strict boolean of the data key (`card_payment_invalid` when not a boolean, as today), else the client flag (`kind->carriesPayment() && client->online_payment_enabled`) when the stored method was online, else the stored switch;
  - `saveAdmin(Invoice $locked, ?string $bankAccountId, bool $cardPayment): InvoiceAdmin` — locks the Admin-only row `FOR UPDATE`, creates it for a draft that has none (as `UpdateDraft::saveCardPayment()` does), writes the two values only when they differ (a save that changes nothing writes nothing), and returns the row.
