<objective>
Close gap 2 of 14-VERIFICATION.md (WR-01): the card switch of an open issued document must need card payment to be available on every path that turns it on or keeps it on. Today `DocumentPayment::issuedSwitch()` checks availability only when the stored switch was off, so (1) online to transfer while the global setting is off or Stripe is unconfigured keeps the switch on (derived from the client flag), forces a new link that can never be created and prints a pay URL that only says "preparing"; and (2) the online branch forces the switch on during any unrelated save, whatever the availability.

The tracer: an issued online invoice of a client with online payment on, the global setting turned off (and, as a second case, the Stripe secrets cleared), switched back to transfer: the switch is off, the online link is replaced, no new link opens and no pay URL is printed.

Purpose: P14-09 (card payment is offered only while it can work) and P14-07 (the link follows the method change correctly); D-03, D-10, OA-1.
Output: the corrected `issuedSwitch()` with its docblocks and four regression cases (two files).
</objective>

Decisions carried in (locked): D-03 (online forces the card switch on and requires card payment to be available: global setting on, Stripe configured, client flag on; a transfer document keeps the Admin's switch), D-10 (a method change deactivates the live link; a new link only when card payment is still offered), OA-1 (the switch is editable on an open issued transfer document, forced on for online, reset to the client flag on online to transfer).

Rulings made in this plan (recorded):
- R-14-13-1 (transfer branch of `issuedSwitch()`, WR-01 point 1): the switch is computed as today (the explicit boolean, else the client flag when the stored method was online, else the stored switch). When the result is on AND (the stored switch was off OR the stored method was online) AND `CardPaymentSwitch::available()` is false: an explicit `true` is refused with `ValidationException` under `card_payment_enabled` and `invoices.errors.card_payment_unavailable` (the existing key and copy); a derived value falls back to false. A transfer document whose stored method is transfer and whose stored switch is on keeps it on an unrelated save (the switch is not "turned on" there).
- R-14-13-2 (online branch of `issuedSwitch()`, WR-01 point 2): for method online the result is `$storedSwitch || self::onlineUnavailableReason($locked) === null`, the same predicate `forIssued()` uses to allow a change to online (global setting, Stripe and the client flag; P14-09). A change from transfer to online is already refused while unavailable, so it still always gets the switch on; an online document already on stays on; an online document whose stored switch is off stays off until card payment is available to it again. 14-REVIEW.md proposed `CardPaymentSwitch::available()` for this branch; the planner uses `onlineUnavailableReason()` so the online rule matches P14-09 including the client flag (Claude's discretion, recorded here).
- No change to `UpdateIssuedDocument`, `IssuedEditFinisher`, `PaymentLinks` or the Filament page: a degraded switch reaches them as `card_payment_enabled = false`, so the existing lines 204-213 of `UpdateIssuedDocument` deactivate the live link as `replaced` and force no new link.
