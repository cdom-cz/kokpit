<objective>
Print what the payment method promises. A transfer document keeps its bank box; an online document prints only what is needed to pay by card. And every place that prints the stable pay URL asks one gate that reads the card switch with the token, because from this phase a token can outlive a switch-off. The tracer: an open issued CZK invoice switched to online renders a payment box with the amount, the online sentence and the card button, and no bank detail, variable symbol or QR.

Purpose: P14-02; D-01 (what each method prints), D-06 (QR rule and foreign-currency account), D-08 (currency carried to the PDF), D-03/D-10 (card offered only while the switch is on); research Pattern 4, Pitfall 2; owner answer OA-5 (note for Phase 13 that `PayLinkBlock` gates on switch AND token).
Output: the PDF data branch, the gated `PayUrl::forInvoice()`, the PDF copy in Czech and English, and the variant and output tests.
</objective>

Owner answers of 2026-10-23 (planning session, binding, settled; source: the amendments block of 14-CONTEXT.md, section "Owner Amendments", OA-1 to OA-7): OA-5 Phase 13 has only a CONTEXT; this plan records that `PayLinkBlock` gates on "switch AND token", so the Phase 13 e-mail rebuild inherits the gate through `PayLinkBlock::applies()` / `forMail()`.

Phase 13 hand-over (record in the SUMMARY): Phase 13 rebuilds the invoice e-mail around the "Pay by card" button. After this plan, the only correct predicate for that button is `PayLinkBlock::applies()` (switch on AND token AND issued, uncancelled invoice or proforma that still owes money); the Phase 13 planner must not read `pay_token` directly.

Rulings made in this plan (recorded):
- R-14-05-1 (one gate): `PayUrl::forInvoice(Invoice $invoice): ?string` reads `card_payment_enabled` and `pay_token` of the Admin-only row in one query and returns the URL only when the switch is true and the token is a non-empty string; otherwise null. Every printer already calls it (`InvoicePdfData::cardPayment()`, `PayLinkBlock::url()`, `PartnerPayButton::urlFor()`, `PayByCardAction` default URL, `PaymentLinkStatus::for()['url']`), so the gate lives in one place and no caller can bypass it; only the docblocks of `PayUrl` and `PayLinkBlock` change (and the class docblock of `InvoicePdfData`, which says it reads only the token). `PayPageState` keeps resolving a token to its document (the public page still answers a printed URL with its existing information state, D-10, research Pitfall 9).
- R-14-05-2 (payment box): `InvoicePdfData::payment()` branches on `$issued->payment_method`: `DocumentPaymentMethod::Online` returns `['qrDataUri' => null, 'sentence' => <online_sentence with :amount and :due fenced bold like today>, 'facts' => [payment_method => online_payment, amount_due => amount]]` and reads nothing of `bank_snapshot`; transfer (and a legacy null) keeps the existing body unchanged, returning null when `bank_snapshot` is null. `cardPayment()` uses the lead `online_card_lead` for an online document and `card_lead` for transfer. The template `resources/views/pdf/invoice.blade.php` needs no change (it prints a box without QR, its sentence, its facts and the optional card block).
- R-14-05-3 (copy): `lang/cs/invoice_pdf.php` gains `online_sentence` "Prosíme o úhradu částky :amount online platební kartou do :due.", `online_payment` "Online platební kartou", `online_card_lead` "Zaplaťte online kartou:"; `lang/en/invoice_pdf.php` gains `online_sentence` "Please pay :amount online by card by :due.", `online_payment` "Online by card", `online_card_lead` "Pay online by card:". The key sets of the two files stay equal (InvoicePdfTest compares them).
- R-14-05-4 (test fixture): plan 14-04 runs in the same wave, so the tests here make an online document the way the database allows for an open issued document: a file-local helper issues through `InvoiceFixtures::issued()` and then, as system, runs `update invoices set payment_method = 'online', bank_snapshot = null where id = ?` and `update invoice_admin set card_payment_enabled = true, pay_token = ? where invoice_id = ?` with `PayToken::generate()` (accepted since plan 14-02 while the document is open).
