Rulings made in this plan (recorded):
- R-14-09-1 (`ConvertProforma::createDraft()`): the draft copies `payment_method` from the proforma (D-01, OA-2); the Admin-only row copies the proforma's `bank_account_id` when `BankAccountSettings::find()` still finds it, else stays NULL so the issue takes the first account of the currency (a paid proforma must not become unconvertible because an account was renamed away; the Admin cannot pick an account inside the atomic conversion); `card_payment_enabled` is true for an online proforma and false for a transfer one (Phase 11 D-05: a converted transfer invoice gets no card switch). The issue then runs unchanged: an online draft gets `effective(kind, true)` (switch and token when card payment is available, nothing otherwise), no bank snapshot, and a pending link for the total; the `online_unavailable` blocker does not apply to it (plan 14-04, `proforma_id` set).
- R-14-09-2 (`ConvertProforma::handle()`): after the last `RecordPayment::carry()`, still in the transaction, `PaymentLinks::reconcile($issued)` (injected through the constructor) deactivates the link the issue opened (`paid` when nothing is owed, `amount_changed` for a partly carried amount); `RecordPayment::carry()` itself does not reconcile (research Pitfall 7). The class docblock names the inheritance and the reconcile.
- R-14-09-3 (`InvoiceAudit::snapshot()`): two keys join the fixed list: `payment_method` (`$invoice->payment_method?->value`) and `card_payment` (1 or 0 from `invoice_admin.card_payment_enabled`, null when the row is missing); the account stays represented only by `bank_fingerprint`; the token and `bank_account_id` are never read. The class docblock list of audited values names both keys.
- R-14-09-4 (race and unsupported currency, tests only): research Pattern 5 item 4 says `CreatePaymentLink::staleReason()` needs no change because the edit transaction deactivates the pending row and the job takes its stale path; this plan proves it instead of changing the job. If a case fails, the fix goes into `UpdateIssuedDocument`/`PaymentLinks`, never into a Stripe call inside a transaction.
