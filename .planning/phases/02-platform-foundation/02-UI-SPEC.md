# Phase 02 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: Phase 2 ships a foundation, not features. The user-visible surfaces are exactly these seven: the login page, the mandatory Admin two-factor (2FA) set-up screen, the 2FA challenge with recovery-code entry, the profile page, the empty default dashboard, the standard 403/404 error states, and the Admin versus Partner navigation skeleton (no feature screens in it). Screens for clients, projects, tasks, time and invoices belong to later phases and are not specified here.
>
> Design system stance: the design system is stock Filament 5 (components, Tailwind 4 theme precompiled inside the package). This spec records Filament's own tokens as the contract. It adds no custom theme, no custom Vite build (Node is not used in this phase), no custom component library and no shadcn.

Upstream decisions applied (not re-asked): D-06 (Admin is sent to 2FA set-up after login and cannot reach the panel until it is enabled), D-07 (Filament built-in TOTP with one-time recovery codes shown at set-up), Czech default locale with all user-facing text in `lang/cs`, Czech date/number/currency formats, times shown in `Europe/Prague` (FND-03, FND-11), one SPA panel for both roles (FND-01), and the Partner rule that measured time, rates, prices and finance never appear in navigation, widgets or any other surface (FND-06, FND-18).

## Design System

| Property | Value |
|----------|-------|
| Tool | Filament 5 (`filament/filament` 5.10.0, Livewire 4) used stock. shadcn: none (no `components.json`, not applicable) |
| Preset | not applicable |
| Component library | Filament Panels, Forms, Schemas, Actions, Infolists, Tables, Notifications, Widgets, Support (anonymous Blade components `x-filament::*`); Alpine.js and precompiled Tailwind CSS 4 ship inside the packages |
| Icon library | Heroicons through Filament's `Filament\Support\Icons\Heroicon` enum, outline style, stock sizes; no second icon set |
| Font | Inter Variable, Filament's default `LocalFontProvider` (files ship in the package, including the `latin-ext` subset that covers Czech diacritics). Do not call `Panel::font()`: a custom family switches Filament to the Bunny Fonts CDN, which would add a third-party request to every page |

Panel configuration this contract requires (configuration, not a theme):

| Setting | Value | Why |
|---------|-------|-----|
| Panel id and path | `admin`, `/admin` | Already in `app/Providers/Filament/AdminPanelProvider.php`; one panel for both roles |
| Brand | Text brand `Kokpit` taken from `APP_NAME=Kokpit` (set in `.env.example`); no logo file, no favicon file in this phase | The same string is the issuer label inside the authenticator app (Filament reads the panel brand name) |
| Layout | SPA mode on, sidebar navigation, topbar on, breadcrumbs stock, max content width stock (`7xl`) | Stock; keeps later phases free of layout rework |
| Dark mode | Enabled, stock: follows the operating-system setting by default, theme switcher (system, light, dark) in the authenticated user menu | Stock behaviour; the login page has no topbar, so it follows the system setting only |
| Primary colour | `Color::Indigo` (replaces the installer default `Color::Amber`) | See Color: Amber is also Filament's stock warning colour, and a solid amber button has weak label contrast |
| Avatar | Local initials avatar provider registered with `Panel::defaultAvatarProvider()`, producing an inline SVG data URI (neutral gray background, white initials) | Filament's default provider requests `ui-avatars.com` with the user's name, which would send personal data to a third party on every page view |
| Global search | Off in this phase (`globalSearch(false)`) | No searchable resources exist yet; a later phase turns it on per resource together with an explicit Partner rule, because search is a Partner leakage surface |
| Database notifications | Off in this phase (no bell icon) | No notification sources yet; toasts (`Filament\Notifications\Notification`) are enough |
| Password reset and registration | Not enabled in this phase | No public registration ever; password reset arrives with the Partner invitation flow in Phase 4 (see Decisions and Assumptions A-1) |
| Stock widgets | `AccountWidget` and `FilamentInfoWidget` removed; stock `Filament\Pages\Dashboard` replaced by `App\Filament\Pages\Dashboard` | The info widget links to external documentation; both default to visible and carry no access rule |

## Spacing Scale

Declared values (multiples of 4), mapped to Filament's Tailwind 4 spacing (1 unit = 4px):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between icon and badge, inline padding inside badges |
| sm | 8px | Icon-to-label gap in buttons and menu items, gap between recovery codes |
| md | 16px | Vertical gap between stacked controls inside a modal step |
| lg | 24px | Gap between form fields and sections (Filament form grid), section inner padding, card horizontal padding on mobile |
| xl | 32px | Page content horizontal padding from `md` up, gap between page header and content |
| 2xl | 48px | Simple-page card padding from `sm` up (login, set-up-required) |
| 3xl | 64px | Vertical margin of the simple-page card from the viewport edge |

Exceptions:

- 12px (Tailwind `gap-3`, `px-3`) appears inside stock inputs, buttons and menu items. It is a multiple of 4 and is accepted only as Filament-internal control padding; application markup does not use it.
- Interactive targets keep Filament's stock 36px height (inputs, buttons, icon buttons). That meets the WCAG 2.2 AA minimum target size of 24px; the 44px target is not required. No custom sizing is added.
- No custom spacing is authored in this phase: all layout comes from Filament components, so no hand-written spacing classes are expected in `app/` or `resources/views/`.

## Typography

Four sizes, taken from the stock Filament roles:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (inputs, buttons, table cells, helper text, labels, menu items, sidebar items) | 14px (`text-sm`) | 400 regular | 1.43 (20px) |
| Label (field labels, button text, section headings, user name in the menu) | 14px (`text-sm`) | 600 semibold | 1.43 (20px) |
| Heading (section and modal headings; input text below the `sm` breakpoint so mobile browsers do not zoom) | 16px (`text-base`) | 600 semibold | 1.5 (24px) |
| Display (simple-page heading on login and set-up-required: 24px; authenticated page heading: 24px below `sm`, 30px from `sm` up) | 24px / 30px (`text-2xl` / `text-3xl`) | 600 semibold | 1.33 (24px size) / 1.2 (30px size) |

Contract notes:

- Declared sizes: 14, 16, 24, 30. No other size may be introduced by application code.
- Declared weights: 400 and 600. Application code introduces no other weight. Stock Filament itself renders field labels at 500 and page headings at 700; these are framework-rendered, are not overridden (overriding would be a custom theme) and are not a licence to add weights.
- Line heights are Tailwind 4's built-in pairings for each size (1.43, 1.5, 1.33, 1.2); the 1.5 body ratio is not forced because it would require a custom theme.
- Recovery codes and the manual TOTP secret use Filament's stock monospace stack where the stock component applies it; no custom font.
- Czech diacritics (for example ě, š, č, ř, ž, ý, ů, ď, ť, ň) must render in Inter, not a fallback face. Verify at the phase gate by viewing the login page and the 2FA set-up modal.

## Color

Filament's stock semantic roles and neutral scale are the contract. Gray is Zinc. Hex values are the Tailwind 4 palette equivalents of the oklch values Filament emits.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light `#fafafa` (zinc-50) / dark `#09090b` (zinc-950) | Page background (`.fi-body`), the area around the simple-page card |
| Secondary (30%) | Light `#ffffff` / dark `#18181b` (zinc-900), hairline ring zinc-950 at 5% / white at 10% | Sidebar, topbar, simple-page card, sections, modals, dropdowns, empty-state container |
| Accent (10%) | Indigo-600 `#4f46e5` light / indigo-500 `#6366f1` dark | Reserved list below |
| Destructive | Red-600 `#dc2626` light / red-500 `#ef4444` dark | Reserved list below |

Accent reserved for (and nothing else):

1. The single primary submit button on each surface: "Přihlásit se", "Potvrdit přihlášení", "Povolit ověřovací aplikaci", "Pokračovat", "Uložit".
2. The active sidebar item (icon and label), which in this phase is the dashboard item.
3. Text links inside forms and modals (for example "Místo toho použijte obnovovací kód").
4. The keyboard focus ring on every focusable control.
5. The checked state of the "Zapamatovat si mě" checkbox.
6. The icon of the dashboard empty state and the lock icon in the 2FA set-up modal header.
7. The SPA page-transition progress bar.

Semantic colours, each limited to one purpose:

- Destructive (red) is used only for the "Vypnout" (disable authenticator app) action and for validation error text. "Obnovit obnovovací kódy" is not destructive-coloured.
- Success (green) is used only for the "Uloženo" toast and the "Povoleno" badge.
- Warning (amber) and info (blue) are not used in this phase.

Contrast and dark mode requirements:

- Body text on dominant and secondary surfaces meets WCAG AA (4.5:1) in both modes; this is Filament's stock pairing.
- Primary changes from the installer default Amber to Indigo for two reasons: Amber equals Filament's warning role, so primary and warning would be indistinguishable later; and a solid amber button with white label text measures about 3.2:1, below AA for 14px text. Indigo-600 with white text is about 6.3:1. In dark mode indigo-500 with white text is about 4.5:1 (borderline); the phase gate checks the real rendered contrast of the primary button in dark mode and escalates if it measures below 4.5:1.
- Both colour modes ship in this phase. No screen may rely on colour alone: the 2FA status is the badge text "Povoleno" / "Zakázáno", not only a colour.
- No colour values are hard-coded in application code; everything goes through the panel `colors()` roles.

## Screens and Interaction Contract

All seven surfaces use stock Filament markup. The table states what must be true; it is not a request for custom views.

### Surface 1: Login (`/admin/login`)

- Layout: simple-page card (stock width `md`, 64px vertical margin, 24px horizontal padding on mobile, 48px from `sm` up), centered on the dominant background, brand text "Kokpit" above the heading, no topbar.
- Fields in order: e-mail (autofocus, `autocomplete=username`), password (revealable toggle, `autocomplete=current-password`), "Zapamatovat si mě" checkbox, one full-width primary button "Přihlásit se".
- No registration link and no "forgot password" link (A-1).
- Loading: the button shows Filament's spinner and is disabled while the request runs; double submit is impossible.
- Invalid credentials: an inline error under the e-mail field (stock Czech text, quoted in the Copywriting Contract). The message never reveals whether the e-mail exists.
- Rate limit (5 attempts, stock): a toast with the remaining seconds (stock Czech string).
- After valid credentials:
  - Admin with 2FA enabled: the same card swaps to the challenge step (Surface 3).
  - Admin without 2FA and enforcement on: redirect to Surface 2.
  - Partner: straight to the dashboard (Partner 2FA is not required; D-06).

### Surface 2: Set-up-required 2FA screen (Admin only, forced by D-06)

- Layout: simple-page card with the topbar (the user menu with "Odhlásit se" stays reachable, so an Admin who cannot set up can still sign out). Heading, subheading, one compact secondary section containing the authenticator-app row, and a footer action.
- The row shows: label, one-line description, status badge ("Zakázáno" before set-up, "Povoleno" after) and the action button "Nastavit" (after set-up the stock "Obnovit obnovovací kódy" and "Vypnout" actions appear instead).
- "Pokračovat" is hidden until a provider is enabled (stock behaviour), so there is no path to the panel without 2FA. There is no "skip" or "later" control.
- "Nastavit" opens a large modal wizard with the lock icon (accent colour):
  1. Step 1: short description with links to the authenticator apps, the QR code (generated locally as an inline image, with alt text), the manual key as copyable text (a "Zkopírováno" tooltip on copy), the six-digit `OneTimeCodeInput` and the below-field hint. Invalid code shows the inline error; rate limiting shows the rate-limit message.
  2. Step 2 (shown once): the recovery codes in a list with "zkopírovat" and "stáhnout" links (download file name `recovery-codes.txt`) and the instruction that the codes are shown only once. The submit button "Povolit ověřovací aplikaci" is on this step, so the codes are always shown before 2FA becomes active. Closing the modal before submitting leaves 2FA disabled and the codes void.
- After submit: the badge turns to "Povoleno", "Pokračovat" appears; pressing it goes to the intended URL (the dashboard).
- Recovery codes are never shown again after this step; the regenerate action produces a new set and shows it once the same way.

### Surface 3: 2FA challenge and recovery-code entry (login step for Admin)

- Same card as the login. Heading "Ověřte svou identitu" with its stock subheading; a single six-digit `OneTimeCodeInput` (autofocus, `autocomplete=one-time-code`, numeric keypad on mobile); primary button "Potvrdit přihlášení".
- The provider chooser is not rendered because there is exactly one provider.
- A text link "Místo toho použijte obnovovací kód" swaps the field for a recovery-code text input (label "Nebo zadejte obnovovací kód") with the same button; there is no link back requirement beyond reloading the step.
- Errors: "Zadaný kód je neplatný." and "Zadaný obnovovací kód je neplatný." as inline field errors; rate limit as the stock message. A used recovery code is invalid on the next attempt (stock; one-time).
- A device lost and no recovery code: the only route is the CLI reset on the server (D-07); the UI never offers a self-service bypass.

### Surface 4: Profile (`/admin/profile`)

- Layout: authenticated page (sidebar, topbar, breadcrumbs stock, heading "Profil"), content in a stock form with sections.
- Fields: name, e-mail, new password and confirmation (revealable), current password (required only when changing the e-mail or the password, stock). Primary button "Uložit"; success toast "Uloženo".
- Section "Dvoufaktorové ověření (2FA)" holds the authenticator-app row with the same badge and actions as Surface 2. For a Partner the row is available but not required.
- If an Admin disables the authenticator app here, the next request redirects to Surface 2 (the enforcement middleware), so an Admin cannot remain without 2FA.
- Both roles see the same page; it contains no role-specific data and nothing about time, rates, prices or finance.

### Surface 5: Dashboard (empty default)

- `App\Filament\Pages\Dashboard`, declared `PartnerAllowed`, no widgets, no filters.
- Body: one centered `EmptyState` (accent outline-inbox icon, heading, one-sentence description). The description is role-specific: the Admin text mentions that the dashboard fills up as clients, projects and tracked time arrive; the Partner text is neutral and mentions no time, rates, prices or finance. Exact strings are in the Copywriting Contract.
- No call-to-action button: no create screens exist yet, so there is no valid next step to link to (recorded in the Copywriting Contract).
- Loading: no data is fetched, so no skeleton is needed. SPA navigation shows the stock top progress bar in the accent colour.

### Surface 6: Standard 403 and 404 states

- Laravel's default minimal error view (status code, a divider, the Czech status text from the language pack), rendered outside the panel layout. No custom error views in this phase (A-8).
- 403: an authenticated user reaching a page, resource or widget whose `#[AccessRule]` denies them (for example a Partner opening an Admin-only URL). The text is the stock "Zakázáno" with no explanation of which rule failed.
- 404: an unknown URL, and also any record a Partner is not allowed to see. Because the Partner global scope returns no rows, an out-of-scope record is indistinguishable from a missing one; the UI must never confirm that another client's record exists.
- 419 (expired session) and 429 (too many requests) use the same stock view with their Czech status texts.
- Unauthenticated requests to panel routes redirect to the login page, never to a 403.

### Surface 7: Navigation skeleton (Admin versus Partner)

- Sidebar (stock, left, collapses into a drawer with a hamburger button below the `lg` breakpoint, 1024px) and topbar (brand, user menu).
- Navigation items are derived from the registered pages and resources and are shown only when the current user passes `canAccess()`; hidden items are not rendered at all (not disabled). That is the same rule the registry test enforces, so navigation and authorization cannot disagree.
- Phase 2 content: one item for both roles, "Nástěnka" (stock Czech dashboard title, stock home icon, active state in the accent colour). No navigation groups are registered yet, so no group labels or empty groups appear. Later phases add items and groups only together with an `#[AccessRule]`.
- Admin and Partner currently see the same single item. The skeleton's contract is the visibility rule above, which later phases inherit: an Admin-only class is absent from a Partner's sidebar, and nothing in navigation, badges or counters mentions time, rates, prices or finance for a Partner.
- User menu (stock, topbar right): avatar with initials, user name and e-mail as plain text, entries "Profil", the theme switcher (system, light, dark) and "Odhlásit se". No role label is displayed in the menu.

### Cross-cutting interaction rules

- Every screen is usable by keyboard alone; the visible focus ring is the accent colour; the stock "Přeskočit na obsah" skip link is kept.
- Responsive behaviour is Filament's stock: simple-page cards become full width with 24px padding on mobile; modals become full-width sheets on small screens.
- Locale formats (binding for every later screen; no date or number is shown in Phase 2): dates `j. n. Y` (for example `6. 1. 2026`), date and time `j. n. Y H:i`, time `H:i`, number locale `cs` (decimal comma, no-break-space thousands separator), currency `CZK` shown as `1 234,50 Kč`. Instants are stored in UTC and displayed in `Europe/Prague`.
- Enum labels shown anywhere in the UI come from `lang/cs/enums.php`; the role enum labels are "Správce" (Admin) and "Partner".
- No application page makes a request to a third-party host at render time (fonts, avatars, QR codes and icons are all local).
