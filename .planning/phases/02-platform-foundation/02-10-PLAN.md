<objective>
Enforce Partner default-deny in the data layer (D-02): a request-scoped access context, a fail-closed global scope for tenant-scoped models, a deny-all trait for Admin-only package models, an explicit opt-out attribute for the authentication models, and a default-deny policy base, all proven on a test-only tenant model with two fictional clients and runtime canary strings (D-04), plus architecture tests that force every model to declare its isolation.

Purpose: FND-06 (policies and global scopes, not UI hiding) and the data half of FND-18. A Partner is a client account in the same panel (D-01: one client per Partner via `users.client_id`), so every query path must default to nothing.
Output: eight `App\Domain\Shared\Auth` types, `AdminOnlyPolicy`, `AccessServiceProvider`, declarations on eight models, canary support classes and four test files, and the `Isolation` Pest suite.
</objective>
