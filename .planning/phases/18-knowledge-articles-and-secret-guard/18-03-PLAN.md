- R-18-03-2 (KnowledgeMarkdown): `final class App\Domain\Knowledge\Support\KnowledgeMarkdown` with `public const int MAX_INPUT_LENGTH = 100000;`, constructor `__construct(private readonly Closure $translate)` where the closure is `Closure(string $key, array<string, string> $replace = []): string` over relative keys (`code.copy`, `code.copied`, `code.copy_failed`, `code.label`, `code.label_plain`, `task.done`, `task.open`; 18-06 adds `callouts.*`). The constructor builds the `Environment` once with `html_input` `escape`, `allow_unsafe_links` false, `max_nesting_level` 20, `max_delimiters_per_line` 1000; extensions `CommonMarkCoreExtension` and `GithubFlavoredMarkdownExtension`; the `LinkAndImagePolicy` listener on `DocumentParsedEvent`; `CodeBlockRenderer` for `FencedCode` and `IndentedCode` and `TaskListMarkerRenderer` for `TaskListItemMarker`, all at priority 10; a `MarkdownConverter`; one `HtmlSanitizer` with the config of R-18-03-4. `public function render(string $markdown): HtmlString`: a blank input returns an empty `HtmlString`; an input longer than `MAX_INPUT_LENGTH` (mb_strlen) returns `<p class="kokpit-prose__plain">` with the text escaped by `htmlspecialchars(ENT_QUOTES | ENT_SUBSTITUTE)` and no Markdown processing (bounded memory; only an unsaved preview can be that long, because the stored body is capped); otherwise convert, then sanitise. No HTML cache (research Pattern 2). The class never calls `__()` or any Laravel facade, so Unit tests run without the application.
- R-18-03-3 (LinkAndImagePolicy): `final class LinkAndImagePolicy` with `__invoke(DocumentParsedEvent $event): void`; it first collects the `Image` and `Link` nodes of the document, then mutates: an `Image` is replaced by a `Text` node holding the concatenated literals of its `Text` descendants (its alt text); a `Link` whose URL does not match `^(https?://|mailto:)` case-insensitively has its children moved before it and is detached. Autolinks and reference-style links are `Link` nodes and follow the same rule.
- R-18-03-4 (sanitiser): `HtmlSanitizerConfig` built in `KnowledgeMarkdown` only: `allowSafeElements()`, `allowRelativeLinks(false)`, `allowLinkSchemes(['https', 'http', 'mailto'])`, `allowMediaSchemes([])`, `allowRelativeMedias(false)`, `forceAttribute('a', 'rel', 'noopener noreferrer nofollow')`, `dropAttribute('target', 'a')`, `allowElement('input', ['type', 'checked', 'disabled', 'aria-hidden'])`, `allowElement('button', ['type', 'class', 'data-kokpit-copy', 'data-label-copied', 'data-label-failed'])`, `allowElement('pre', ['tabindex', 'aria-label'])`, `allowElement('code', [])`, `allowElement('span', ['class', 'aria-live', 'aria-hidden'])`, `allowElement('div', ['class'])`, `allowElement('p', ['class'])`, `withMaxInputLength(-1)` (the default 20 000 truncates silently, research Pitfall 1). Never Filament's global sanitiser. The author cannot produce a button, a data attribute or a class, because raw HTML is escaped before the sanitiser runs.
- R-18-03-5 (CodeBlockRenderer): `final class CodeBlockRenderer implements NodeRendererInterface` with `__construct(private readonly Highlighter $highlighter, private readonly Closure $translate)` and `public const array LANGUAGES` mapping the accepted lowercase first word of the info string to the Tempest language name, which is also the label: bash (bash, sh, shell, zsh), php, blade, sql, json, yaml (yaml, yml), xml, html, css, scss, javascript (javascript, js), typescript (typescript, ts), diff, dockerfile (dockerfile, docker), ini, dotenv (dotenv, env), nginx, apache, http, python (python, py), go, rust (rust, rs), toml, twig, markdown (markdown, md), terraform (terraform, tf). A value Tempest does not resolve is removed from the map (CodeBlockTest, Task 2). The code text is the node literal minus exactly one trailing newline. The literal never holds a CR: league splits the input on CRLF, CR and LF and joins code lines with LF, so a CR kept inside stored code by the normaliser (18-04 R-18-04-5, D-10 applied literally) shows and copies as an LF line break; an HTML parser would map a CR to LF in `textContent` anyway. The renderer adds no CR handling of its own. With a known language the highlighted HTML (`Highlighter` with the default `CssTheme`, class-only `hl-*` spans) is used only when `html_entity_decode(strip_tags($html), ENT_QUOTES | ENT_HTML5, 'UTF-8')` is identical to the code text; otherwise, and for an unknown language or an indented block, the code is escaped plain text (research Pitfall 2: the `{+ +}`, `{- -}`, `{~ ~}`, `{_ _}` markers). Markup, every attribute value escaped: a `div.kokpit-code` holding a `div.kokpit-code__head` (a `span.kokpit-code__lang` with the label, omitted without a language, then `button.kokpit-code__copy` with `type="button"`, `data-kokpit-copy=""`, `data-label-copied` = translate('code.copied'), `data-label-failed` = translate('code.copy_failed'), wrapping `span.kokpit-code__copy-label` with `aria-live="polite"` and the text translate('code.copy')), then `pre` with `tabindex="0"` and `aria-label` = translate('code.label', ['language' => label]) or translate('code.label_plain'), holding `code` with the code HTML.
