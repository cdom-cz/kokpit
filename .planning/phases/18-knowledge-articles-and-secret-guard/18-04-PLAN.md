- R-18-04-3 (scanner): `final class SecretScanner` with `public function scan(string $body): array` returning `list<SecretFinding>` sorted by line, then rule value, deduplicated per (rule, line). Order of work: invalid UTF-8 (`mb_check_encoding`) returns `[ScanFailed@0]`; split into lines on `\r\n`, `\r` or `\n`; per line remove U+200B, U+200C, U+200D, U+2060 and U+FEFF and fold with `Normalizer::normalize($line, Normalizer::FORM_KC)` (a false result returns `[ScanFailed@0]`); the PEM rule runs over the folded lines joined by `\n` and marks every line of its match as covered; the line rules then run in precedence order aws_access_key, stripe_secret, stripe_test_key, github_token, jwt, url_credentials, password_assignment, high_entropy_string (every Blocking rule before the two Ambiguous ones), and a match that overlaps the span of an earlier reported match on the same line (or lies on a PEM-covered line) is suppressed, so one token never yields two findings. After every `preg_*` call `preg_last_error() !== PREG_NO_ERROR` returns `[ScanFailed@0]` at once: no partial result can read as clean. Line numbers are 1-based and identical to the editor's (folding never adds or removes a newline).
- R-18-04-4 (patterns, bounded quantifiers only; the executor may tighten them but every behaviour in SecretScannerTest must hold): pem_private_key: a header `-----BEGIN ` + optional uppercase words + `PRIVATE KEY` (optionally ` BLOCK`) + `-----`, a newline, then at least two lines of 16 or more base64 characters (a header sentence in prose is not a finding); aws_access_key: word-bounded `A3T` plus one alphanumeric, or `AKIA`, `ASIA`, `ABIA`, `ACCA`, followed by 16 characters of `[A-Z2-7]`, minus the EXAMPLE suffix; stripe_secret: word-bounded `sk` or `rk`, then `_live_`, then 24 to 99 alphanumerics, and `whsec_` plus 24 to 99 alphanumerics; stripe_test_key: word-bounded `sk` or `rk`, then `_test_`, then 24 to 99 alphanumerics (Blocking like `stripe_secret`, R-18-04-1); github_token: `gh` plus one of p, o, u, s, r, an underscore and 36 to 255 alphanumerics, and `github_pat_` plus 22 to 255 of `[A-Za-z0-9_]`; jwt: three dot-separated base64url parts of at least 8 characters whose first two start with `eyJ`; url_credentials: a scheme, `://`, a user of 1 to 128 non-space characters without colon, at sign or slash, a colon, a password of 1 to 256 characters, an at sign and a host, where a placeholder password is not a finding; password_assignment (case-insensitive): one of password, passwd, pwd, secret, token, api key (with or without separator), auth or authorization, an optional quote, `:` or `=`, an optional quote and a value of 6 to 128 characters without whitespace or quotes, where a placeholder value is not a finding; high_entropy_string: maximal runs of `[A-Za-z0-9+/=_-]` found by one linear `preg_match_all` with offsets, length 32 to 256, not hex-only, not UUID-shaped, at least three of the classes lower, upper and digit, Shannon entropy at least 4.2. - R-18-04-5 (normaliser; A3 settled by owner ruling 2026-11-25: D-10 applies literally, the researcher's reading "LF everywhere, also inside code" is rejected, code bytes stay untouched): `final class MarkdownNormaliser` builds its own `Environment` (`CommonMarkCoreExtension`, `GithubFlavoredMarkdownExtension`, `max_nesting_level` 20, the renderer's limit, so both classes agree on what is code) and a `MarkdownParser` once in the constructor; `public function normalise(string $markdown): string` works in five steps:
  1. Remove one leading U+FEFF; an empty text returns ''.
  2. Split the text into lines that each carry their own line ending, with `preg_split` over the alternation CRLF, CR, LF and `PREG_SPLIT_DELIM_CAPTURE`. The separator set and the rule that a final line ending opens no empty last line are exactly those of `MarkdownInput::splitLinesIfNeeded()` in league/commonmark (same alternation, one trailing empty element dropped), so line k of the split is line k of the parser. The last line's ending is the empty string when the text does not end in one.
  3. Parse the same text unchanged (no line-ending conversion before parsing: the parser treats CR, LF and CRLF alike and strips a BOM itself) and mark as code every line from `getStartLine()` to `getEndLine()` of every `FencedCode` and `IndentedCode` node at any depth: fence lines included, fences in quotes and list items, tilde fences, an unclosed fence up to the last line (league closes it there), an indented block up to its last non-blank line (league's `IndentedCodeParser::closeBlock()` already ends it there).
  4. Every line owns the line ending that terminates it. A code line keeps its characters and its own line ending byte for byte (CR, LF or CRLF, trailing spaces and tabs, whitespace-only and empty lines). A prose line loses trailing spaces and tabs, and its line ending becomes LF.
  5. At the end of the text, remove every trailing prose line that is empty after trimming. If the last remaining line is prose, its line ending is removed too; if it is a code line, it keeps its own ending. An unclosed fence therefore stays byte-identical from its opening line through the end of the text, with no blank line removed inside it.
  Mixed line endings at a block border: the line break between a prose line and the block after it belongs to the prose line and becomes LF; the line break after a block's last line (closing fence or last indented line) belongs to that code line and is kept as typed. Idempotence: the parse does not depend on which ending form a line uses, and trimming trailing whitespace of a prose line never turns it into code or out of code (CommonMark block structure does not depend on trailing spaces or tabs, and a whitespace-only line is blank either way). A second run therefore sees the same code lines and changes nothing. This was executed as a prototype on PHP 8.6 against the installed league/commonmark 2.10.7 (planner spike, revision 2): idempotent, and every generated code block byte-identical, over 200 seeded bodies with mixed LF, CR and CRLF.
  Consequences recorded for the owner: a Markdown hard line break made of two trailing spaces on a prose line is removed (D-10 trims trailing spaces; the preview tab shows the same, 18-09 R-18-09-2). A body that differs from the stored one only in line endings or trailing whitespace inside code is a content change and creates a version. A line ending after a final code block is kept as typed. The browser editor (CodeMirror inside EasyMDE) sends LF line breaks itself, so CR bytes inside code arrive only from non-editor callers (tests, a later API or restore). The view and the Copy text show such a CR line ending as an LF line break, because CommonMark reads CR, LF and CRLF as the same line ending and an HTML parser maps CR to LF (18-03 pins this). The class calls no Laravel helper.
