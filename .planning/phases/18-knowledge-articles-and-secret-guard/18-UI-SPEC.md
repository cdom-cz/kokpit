# Phase 18 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: Admin-only Knowledge screens (General knowledge list, view, create, edit), the secret-guard and stale-save feedback, and the rendered Markdown (code blocks, callouts). No Partner screen exists in this phase.
> Language rule: this file is English. Every user-facing string is Czech and lives in `lang/cs` (new file `lang/cs/knowledge.php` or a `knowledge` block in `lang/cs/kokpit.php`, planner's choice). Czech strings quoted here are the target values for those keys.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn does not apply: PHP/Laravel, Filament 5.12 SPA panel, no `components.json`, no Node build, no Vite) |
| Preset | not applicable |
| Component library | Filament 5.12 (Blade components, Schemas, Forms, Tables, Actions), default Filament UI (PROJECT.md: "Custom theme" is out of scope) |
| Icon library | Heroicons through `Filament\Support\Icons\Heroicon` (outlined variants, the convention of every existing resource) |
| Font | Inter (Filament default, served from `public/fonts/filament`); monospace stack for code only |

Rules that follow from the stack (binding for the executor):

- No custom Filament theme and no Tailwind build. Custom Blade views in this repo use Filament Blade components plus inline `style` attributes (see `resources/views/filament/tasks/comment-thread.blade.php`). Arbitrary Tailwind utility classes are NOT available because only Filament's precompiled CSS ships.
- The rendered article (code block chrome, callouts, token colors, table wrapper, task-list items) needs one small hand-written plain CSS file, scoped under a single wrapper class `kokpit-prose`, registered through `FilamentAsset::register()` (no build step). It must use Filament's CSS custom properties (`var(--gray-*)`, `var(--info-*)`, `var(--success-*)`, `var(--warning-*)`, `var(--danger-*)`, `var(--primary-*)`) so light and dark mode both work. Hex values below are reference values only.
- The copy button is behaviour, not markup the Markdown author controls: the renderer wraps each fenced block in a fixed container, and a small Alpine/JS asset adds the click handler. Anything Alpine-shaped inside the article body is stripped by the sanitiser, so the handler must not depend on attributes from the body.
- The Admin panel already uses `->spa()`; links that open a file or a new tab must not rely on SPA fetch (the "Load current version" link uses `target="_blank"` and a plain URL).
- Filament `MarkdownEditor` is EasyMDE-based. Its real toolbar vocabulary in 5.12 is `bold, italic, strike, link, heading, blockquote, codeBlock, bulletList, orderedList, table, attachFiles, undo, redo`. There is no `taskList` button (see Deviations).

## Spacing Scale

Declared values (must be multiples of 4). Filament chrome (page padding, section padding, table cell padding, form field gaps) keeps Filament defaults and is not re-specified. The scale below applies to everything this phase adds: the `kokpit-prose` stylesheet, the code-block and callout chrome, and inline-style layout in custom Blade views.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, inline code padding (vertical), callout label gap |
| sm | 8px | Code-block header padding, badge-to-text gap, list item spacing inside the article |
| md | 16px | Paragraph spacing, callout padding, code-block body padding, table cell padding |
| lg | 24px | Gap between block elements (paragraph to heading, block to block) |
| xl | 32px | Space above a heading level 1 and 2 inside the article |
| 2xl | 48px | Not used inside the article; reserved for page-level breaks |
| 3xl | 64px | Not used in this phase |

Exceptions:

- Callout and quote left border is 4px (an `xs` multiple, a border, not spacing).
- Copy button keeps the Filament `xs` button height (about 28px). It is a secondary, pointer-and-keyboard control on a desktop admin panel; the 44px touch-target rule is not applied, but the button must be reachable by keyboard and have a visible focus ring.
- Article reading width: the rendered body is capped at 768px (`48rem`) inside its section; tables and code blocks scroll horizontally inside their own wrapper instead of widening the page.

## Typography

Exactly 4 sizes and 2 weights for everything this phase adds. Filament chrome (navigation, table cells, form labels, buttons) keeps Filament's own type scale.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (article text, list items, table cells, callout text) | 16px | 400 | 1.5 |
| Label (code-block header, language tag, Copy button label, callout label, version and date meta line, badges) | 14px | 600 | 1.5 |
| Heading (Markdown h2, h3 to h6 inside the article) | 20px for h2, 16px for h3 to h6 | 600 | 1.2 |
| Display (Markdown h1 inside the article; the page heading itself is Filament's) | 28px | 600 | 1.2 |

Additional rules:

- Inline code and code blocks: monospace stack (`ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`), 14px, weight 400, line height 1.5. Never bold-synthesised.
- h3 to h6 share one style (16px / 600); the level is conveyed by document structure and heading semantics, not size. This keeps the declared size count at four.
- Body text uses weight 400; emphasis `**bold**` renders at weight 600. No third weight anywhere (no 500, no 700).
- The page heading on the view screen is the article title in Filament's page heading style; do not restyle it.
- Long unbroken strings (URLs, hashes) in body text wrap with `overflow-wrap: anywhere`; they never widen the page.

## Color

Kokpit uses the default Filament palette with `primary` set to Amber (`AdminPanelProvider`). No new brand colors are introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Filament page background: white `#ffffff` (light), gray-950 `#030712` (dark) | Page background |
| Secondary (30%) | Filament surface: white with gray ring (light), gray-900 `#111827` (dark); code surface gray-100 `#f3f4f6` (light), gray-900 `#111827` over gray-950 page (dark) | Section card around the article, table, sidebar, code-block body, callout tint backgrounds |
| Accent (10%) | Amber (Filament `primary`, `Color::Amber`) | Reserved list below |
| Destructive | Filament `danger` (red) | Blocking secret findings, CAUTION callout, archive confirmation icon only |

Accent reserved for:

1. The primary action of a screen: "Nový článek", "Uložit změny", "Vytvořit článek", "Upravit článek" (one primary button per screen).
2. The active tab indicator (Write / Preview) and the active "Znalosti" navigation item (Filament default behaviour).
3. Links inside the rendered article body and keyboard focus rings.

Accent is NOT used for callouts, badges, code highlighting or table headers.

Semantic colors (each also carries an icon and a text label, never color alone):

| Meaning | Filament color | Used for |
|---------|----------------|----------|
| Sensitive | `warning` | "Citlivý" badge and list indicator, ambiguous-finding Callout |
| Blocked secret | `danger` | Unambiguous-finding Callout |
| Stale save | `warning` | Persistent notification |
| Archived | `gray` | "Archivováno" badge, muted row text |
| Saved | `success` | Save notification |
| No-op save | `info` | "Nothing changed" notification |

Article callouts (Markdown `> [!TYPE]`), five types, each with a 4px left border in the type color, background tint at about 10% of the same color, an icon and a label (label text uses the type color darkened for AA contrast, never lighter than gray-700 on light and gray-200 on dark):

| Type | Czech label | Icon (Heroicon outlined) | Color source |
|------|-------------|--------------------------|--------------|

| CAUTION | Pozor | ShieldExclamation | `var(--danger-600)` |

An unknown type (`> [!FOO]`) renders as an ordinary blockquote: 4px gray-300 left border, 16px left padding, no icon, no label, text color unchanged.

## Screen and Interaction Contract

### Navigation

- New navigation group "Znalosti" (sort position: after the work groups, before "Signal" and "Správa"; planner confirms against the current order). Phase 18 holds one entry: "Obecné znalosti", icon `Heroicon::OutlinedBookOpen`. Group label and entry label come from `lang/cs`, through `getNavigationGroup()` and `getNavigationLabel()` like the existing resources.
- Resource is Admin-only (`#[AccessRule]` and policy). A Partner sees no group and no entry; this is declared in `PartnerMatrix` and `RouteRules` in the same pull request.
- The article resource is not opted into Filament global search (`$isGloballySearchable` stays unset; the panel uses opt-in).

### List screen (General knowledge)

- Page heading "Obecné znalosti". One header action: primary button "Nový článek" (Heroicon `OutlinedPlus`). Primary focal point: the "Nový článek" button in the header (the only accent-filled element on the screen), followed by the title column as the scan target of the table.
- Columns, in order:
  1. Title (`TextColumn`, weight 600, links to the view screen, single line with ellipsis at 1 line and a tooltip with the full title when truncated).
  2. Version ("Verze", right-aligned integer, e.g. `7`, no "v" prefix, no zero padding).
  3. Last edited ("Naposledy upraveno", `isoFormat('L LT')` like the rest of the panel; the timestamp of the current version, so archiving or restoring alone does not move it; this is the default sort, descending).
  4. Sensitive indicator (`IconColumn`, `OutlinedLockClosed`, `warning`, header label "Citlivý", tooltip "Citlivý článek", visually-hidden text "Citlivý" for screen readers; empty cell when not sensitive).
- Default filter: active articles only. A toggle filter "Zobrazit archivované" shows archived ones as well as active; archived rows get muted text (gray-500) plus a gray "Archivováno" badge after the title.
- Row actions: View (row click), Edit (icon button), and either Archive (active row) or Restore (archived row). Every row action is an icon button with an accessible name and a tooltip carrying the same text: "Upravit článek", "Archivovat článek", "Obnovit článek" (Filament `->label()` + `->tooltip()`; the label is the `aria-label` of the icon-only button). The Edit action is hidden for an archived article (restore first). No bulk actions, no table search (search is Phase 22), no folder, tag or client columns (Phase 19).
- Pagination: Filament default (25 per page with options 10, 25, 50).
- Empty state: see Copywriting Contract and UI Considerations.

### View screen

- Primary focal point: the article title (the page heading); the rendered body is the secondary reading area, and "Upravit článek" is the only accent-filled control.
- Page heading: the article title (Filament style). Under it, one meta line in 14px / 600, muted: "Verze 7" and "Naposledy upraveno 25. 11. 2026 14:05", separated by a middle dot; followed by badges "Citlivý" (`warning`, icon `OutlinedLockClosed`) and "Archivováno" (`gray`) when applicable.
- Header actions, left to right: "Upravit článek" (primary, hidden when archived), "Archivovat článek" (gray, outlined, opens confirmation modal) or "Obnovit článek" (gray, no modal), "Zpět na seznam" is NOT added (breadcrumb already does it).
- Body: one Filament `Section` (no heading) containing a `div.kokpit-prose` with the renderer output. Max readable width 768px, left-aligned inside the section; the section itself spans the page.
- Empty body (a title-only article is valid): muted text "Článek zatím nemá žádný text." with a link "Upravit článek" when not archived.
- Rendered Markdown rules:
  - Tables: wrapper `overflow-x: auto`, 1px gray-200 borders, header row weight 600 on gray-50 background, cell padding 8px 16px (sm / md), zebra rows not used.
  - Task lists: rendered as disabled checkboxes (non-interactive, `disabled`, `aria-hidden` on the box, state also readable from the list item text prefix for screen readers through a visually-hidden "Hotovo:" / "Nehotovo:"); no click handler (editing is Markdown only).
  - Links: Amber text (accent), underlined; external links open normally (no `target`), `rel="noopener noreferrer nofollow"`; `javascript:` and other unsafe schemes are dropped to plain text (never an inert anchor).
  - Raw HTML and script tags appear as escaped literal text.
  - Heading anchors: not added in this phase.
  - Images: not supported in this phase; an image Markdown (`![alt](url)`) renders as its alt text in plain text, not as a broken image (Phase 20 introduces images).
- Code block: container with 1px gray-200 border (gray-700 dark), 8px radius (Filament card radius), header strip (gray-200 background light / gray-800 dark, padding 8px 16px) with the language name on the left (14px / 600, muted; omitted when unknown, with the header then holding only the button) and the Copy button on the right; the body is `<pre>` with padding 16px, horizontal scroll, no wrapping, no line numbers. The container is focusable only through the button and, for scroll, `tabindex="0"` on the `<pre>` with an accessible name from the language ("Kód: bash").
- Copy button behaviour (D-14): Filament `xs` gray button with `OutlinedClipboard` icon and label "Kopírovat kód". On click it copies the exact original text of the block (the code text, no highlight markup, no line numbers, no header text, no trailing newline added). Then the label changes to "Zkopírováno" with `OutlinedCheck` icon for 2 seconds and returns to "Kopírovat kód". The label change is announced through an `aria-live="polite"` region on the button text. If the Clipboard API is unavailable or rejected, the label becomes "Kopírování se nezdařilo" for 2 seconds and the code text is selected so the user can copy by hand.
- Callout rendering: block with icon and label on the first line (14px / 600, 4px gap), then the callout's own Markdown content (16px / 400). Callout content may hold paragraphs, lists and inline code; nested callouts render the inner one as a plain blockquote.

### Create and edit screens

- Primary focal point: the "Název" title input on both screens (it receives `autofocus` on create and stays first in tab order on edit). The accent-filled submit button ("Vytvořit článek" / "Uložit změny") is the only filled control in the form action row.
- Layout: single column, Filament form defaults. Order: (1) guard Callout area (empty until a refusal), (2) "Název" text input (required, max 200 characters, `autofocus` on create), (3) Tabs "Psaní" | "Náhled", (4) Toggle "Citlivý článek", (5) form action row.
- Edit and create share one form schema; create does not show the version meta line, edit shows "Verze 7" read-only under the page heading.
- `createAnother` is disabled. "Vytvořit článek" is the only submit on create; "Uložit změny" on edit; the secondary link-button is "Zrušit vytvoření" on create (returns to the list) and "Zrušit úpravy" on edit (returns to the view screen).
- After a successful save (including a no-op save) the user lands on the view screen, with the notification below. Refused saves (secret block, ambiguous finding, stale version) keep the user on the edit screen and keep every typed character.

#### Editor contract

- Tab "Psaní": `MarkdownEditor` with `fileAttachments(false)`, minimum height 384px (24rem), no maximum height, monospace 14px editing font. Toolbar, exactly these buttons in these groups: `[bold, italic, link]`, `[heading]`, `[blockquote, codeBlock, bulletList, orderedList]`, `[table]`, `[undo, redo]`. No `strike`, no `attachFiles`, no built-in preview, no side-by-side, no full-screen (those EasyMDE toggles must not exist in the toolbar).
- Tab "Náhled": renders on the server through the same `KnowledgeMarkdown` renderer and the same `div.kokpit-prose` wrapper as the view screen, from the current unsaved editor state, refreshed each time the tab is opened (a Livewire call, not client-side rendering). While rendering: Filament loading indicator (`x-filament::loading-section` or equivalent) in the tab; no layout jump larger than the editor's minimum height. Empty body: muted text "Není co zobrazit. Napište text na kartě Psaní."
- The preview never runs the secret guard and never writes anything; it is read-only output.
- The preview does not show the sensitive flag or the version line; it shows only the rendered body.
- Leave warning (D-08): when the form has unsaved changes, leaving the screen (link click, SPA navigation, browser close or reload) shows the browser's native confirmation; no custom modal. Implementation note for the planner: Filament's `unsavedChangesAlerts()` is a panel-level setting, so enabling it applies to every form in the panel, which is acceptable; the planner decides between panel-level and a scoped page script and records the choice. The warning must not fire after a successful save, and not on the Preview tab switch.
- Keyboard: Cmd/Ctrl+S is not bound (not in decisions); Tab order is Title, editor tabs, editor, toggle, submit ("Vytvořit článek" / "Uložit změny"), cancel ("Zrušit vytvoření" / "Zrušit úpravy").

#### Secret guard feedback (SEC-01 to SEC-03)

All guard messages name the rule and the line number, never the value, never the surrounding text. The Callout is the first element of the form, so it is visible without scrolling the editor; on a refusal the page scrolls to it and moves focus to its heading, and it has `role="alert"`.

| State | Component | Behaviour |
|-------|-----------|-----------|
| Unambiguous finding (blocks, no override) | Filament `Callout`, color `danger`, icon `OutlinedShieldExclamation`, heading and a bulleted list "Rule name, line N" | The save is refused; no "save anyway" control exists. The list stays until the next save attempt. Nothing is stored. |
| Ambiguous finding (needs acknowledgment) | Filament `Callout`, color `warning`, icon `OutlinedExclamationTriangle`, same list | The first save is refused. The action row then shows an extra button "Uložit článek i přesto" (color `warning`, after the submit button). |
| Both kinds in one body | Two stacked Callouts, danger first | The block wins: no "Uložit článek i přesto" button while an unambiguous finding exists. |
| After the body is edited following a refusal | Callouts removed, "Uložit článek i přesto" hidden | The acknowledgment applies only to the exact refused save (D-03); any further change needs a fresh save attempt. |
| Acknowledged save succeeds | Notification `success` | Article saved and the "Citlivý článek" toggle is set (D-04); copy below. The activity log records the acknowledgment without content. |
| Sensitive flag | Toggle "Citlivý článek", helper text below | Admin can set it by hand without a finding and clear it by hand; a clean save never clears it (D-04). |

Rule names shown to the user (Czech, the finding list is `{rule} — řádek {line}`): "Soukromý klíč (PEM)", "Přístupový klíč AWS", "Token Stripe", "Token GitHub", "Token JWT", "Adresa s přihlašovacími údaji", and for ambiguous findings "Možné heslo (password=)", "Dlouhý náhodný řetězec". The planner may refine the list; every rule needs one stable Czech label.

#### Stale save (KB-08, D-09)

- Persistent warning notification (no auto-dismiss), title "Článek mezitím někdo změnil", body "Váš text zůstal v editoru, aby ho šlo zkopírovat. Načtěte aktuální verzi a změny sloučte ručně.", one action button "Načíst aktuální verzi" that opens the article's view screen in a new tab (`target="_blank"`, `rel="noopener"`). The editor content and the toggle state stay untouched. No "overwrite anyway", no merge UI.
- Pressing "Uložit změny" again while stale is rejected again with the same notice (the version number the form started from is not silently refreshed).

#### No-op save (D-10)

- Redirect to the view screen with an `info` notification "Nic se nezměnilo, nová verze nevznikla."

#### Archive and restore (KB-07)

- Archive: header action on the view screen and row action on the list; confirmation modal with heading "Archivovat článek?" and body "Archivovaný článek zmizí ze seznamu, ale zůstane uložený i s historií. Půjde ho obnovit." Confirm button label "Archivovat článek" (color `danger` is NOT used; the action is reversible, so the modal uses the neutral/primary confirm style and the icon `OutlinedArchiveBox`). Success notification "Článek byl archivován".
- Restore: no confirmation. Success notification "Článek byl obnoven".
- Archiving or restoring does not create a version and does not change the version number.

### Accessibility

- Every state conveyed by color also has an icon and text (sensitive, archived, callout types, guard findings).
- Callout label text and badge text meet 4.5:1 against their tinted backgrounds in both modes.
- Copy button: real `<button type="button">`, visible focus ring (Filament primary focus ring), `aria-live="polite"` label change.
- Tabs (Psaní / Náhled): Filament tabs keyboard behaviour (arrow keys) unchanged.
- Code `<pre>` with horizontal scroll has `tabindex="0"` and an accessible name.
- Rendered task-list checkboxes are non-interactive and do not take focus.
- Preview and view output use identical markup, so there is one accessibility surface to verify.

## Deviations from CONTEXT.md decisions (flag for the planner)

1. **D-07 asks for a task-list toolbar button and a separate "code" button.** Filament 5.12's `MarkdownEditor` exposes no task-list button, and its code control is the single `codeBlock` button (no inline-code button). The contract therefore lists the toolbar as bold, italic, link, heading, blockquote, codeBlock, bulletList, orderedList, table, undo, redo. A task list is typed as `- [ ] item` and renders on the view screen. Building a custom EasyMDE toolbar entry is out of scope for this phase; if the owner wants the button, it is a separate small task.
2. **D-13 "last edited"** is specified as the timestamp of the current version rather than `updated_at`, so that archive and restore do not reorder the list. The planner needs a stored column or accessor for it.
3. **Edit action hidden for archived articles** and **redirect to the view screen after a save or no-op** are defaults chosen here (no upstream decision); they follow the existing task and client screens.
