Serialized after 06-01 (uses `TimeEntry`, `StartTimer`, `TimerClock` and the migration).

Decisions carried in (locked):
- D-02: start stops the running timer; a stop keeps the entry.
- D-03: billable is pre-set false only for a resolved non-billable task (including inherit from the parent task); projects get no non-billable value; a fixed-price project stays billable; the user can override.
- Phase 5 CONTRIBUTING: every project picker and every project check uses `Project::selectable()`; billing values come only from `TaskBillingResolver`.

Decisions made in this plan (recorded):
- Lock order inside `StartTimer`: per-user timer lock, then the task row `FOR SHARE`, the project row `FOR SHARE`, the client row `FOR SHARE`, then the running entry `FOR UPDATE`. `ArchiveTask` takes the board lock then the task row `FOR UPDATE` and never the timer lock, so there is no cycle.
- Field error keys and copy (UI-SPEC Copywriting Contract): unknown or archived task `task_id` "Úkol je archivovaný. Vyberte jiný úkol."; project not selectable `project_id` "Projekt je archivovaný. Vyberte jiný projekt."; missing or archived client `client_id` "Vyberte klienta."; task and project disagree on `task_id`, project and client disagree on `project_id`, both with "Klient, projekt a úkol k sobě nepatří. Vyberte je znovu."
- `StopTimer` also takes the per-user timer lock (inline in this plan, moved to `TimerLock` in plan 06-03), so a start and a stop of one user never interleave.

Fictional data only. Run `scripts/check-sensitive.sh` before every commit; never bypass the hook.
