Decisions made in this plan (recorded):
- The policy cannot hold the billed lock because `KokpitPolicy::before()` admits the Admin for every ability; `TimeEntryResource::canEdit()` and `canDelete()` add the billed (and for delete the running) condition, `EditTimeEntry::mount()` redirects a billed record to the view page before `parent::mount()`, and the Actions plus the trigger stay the real guards (research Pattern 6, Pitfall 4).
- UI-SPEC deviation, recorded: the list gets an "Úkol" filter in addition to Období, Klient, Projekt and Fakturace, because Surface C's task-page link "Zobrazit záznamy" (plan 06-10) needs the list filtered to one task.
- `BillingBadge` is the display enum (`unbilled` info "Nevyfakturováno", `billed` success "Vyfakturováno" with `OutlinedLockClosed`, `non_billable` gray "Nefakturovatelné"), with labels under `enums.time_billing_state.*` as the UI-SPEC names them; the storage enum `BillingState` stays label-free.
- The bulk action closures pass only the selected record keys to the Actions, which re-read the rows under a lock; the selection spans the current page (stock).
- Static builders `TimeEntryResource::tableColumns()` and `TimeEntryResource::billingBulkActions()` are public so the timesheet day view (plan 06-11) and the project entries tab (plan 06-12) reuse the same columns, badges and actions.

Fictional data only. Run `scripts/check-sensitive.sh` before every commit; never bypass the hook.
