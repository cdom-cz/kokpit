- R-20-08-1 (`ArticleImages`, final, `app/Domain/Knowledge/Queries/`): `forBody(string $body, ?string $articleId, ?string $pendingOwnerId = null): ImageContext`. It takes `ImageReferences::in($body)`; an empty list, or both ids null, is `ImageContext::none()` without a query; otherwise one query `KnowledgeArticleImage::query()->whereIn('id', $ids)` constrained to `article_id = $articleId` (when given) or `article_id IS NULL AND uploaded_by = $pendingOwnerId` (when given), selecting id, width and height, and returns `ImageContext::of()` with src `KnowledgeAttachmentController::path($id)`. Only the preview passes `$pendingOwnerId` (the D-13 amendment); every other surface passes the article id alone.
- R-20-08-2 (rendering surfaces): `KnowledgeArticleResource::previewHtml(mixed $body, ?string $articleId = null)` passes `app(ArticleImages::class)->forBody($normalised, $articleId, auth()->id())` to `render()` on the normalised branch (the over-limit branch stays plain, no context); the preview Html component passes the record id (`?Model $record`, null on the create screen); `infolist()` passes `forBody($body, $record->getKey())`; `ViewArticleVersion::getViewData()` passes `forBody($version->body_md, $article->getKey())`. The version diff and the restore modal keep showing Markdown source (they render no img). No other surface renders a knowledge body.
- R-20-08-3 (form): the body MarkdownEditor keeps `->fileAttachments(false)` and its toolbar; `extraAttributes` keeps `data-kokpit-task-list` and adds `data-kokpit-image` (`knowledge.images.editor.insert`), `data-kokpit-image-uploading`, `data-kokpit-image-done`, `data-kokpit-image-error-title` (`knowledge.images.errors.title`), `data-kokpit-image-too-large`, `data-kokpit-image-failed`, `data-kokpit-image-max-bytes` (`(string) ImagePipeline::MAX_UPLOAD_BYTES`) and `data-kokpit-image-accept` (`image/png,image/jpeg,image/webp,image/gif`). Directly before `Toggle::make('sensitive')` a `Callout::make(__('knowledge.images.notice'))` with color warning, icon `Heroicon::OutlinedExclamationTriangle`, `extraAttributes(['role' => 'status', 'data-kokpit-image-notice' => ''])` and `visible(fn (LivewireComponent $livewire): bool => $livewire instanceof ImageUploadForm && $livewire->showsImageNotice())`; no action inside it.
- R-20-08-4 (script, `resources/js/knowledge-editor.js`, same file, same asset registration, same idempotent bind flag and mutation observer): for every field with `data-kokpit-image`, add once a button with class `kokpit-insert-image` after the toolbar's table button (createElement, `type` button, `tabIndex` -1, title and aria-label from the attribute, the photo icon as a CSS mask in the constructed stylesheet), a hidden file input (createElement, `accept` from the attribute, `multiple`) that the button clicks, and a status element (`div`, role status, class `kokpit-image-status`) after the toolbar; bind once per CodeMirror instance (a flag on the instance, because Filament rebuilds the editor) `codemirror.on('paste', ...)` taking only `clipboardData.files` of an image type (a paste without files is left alone) and `codemirror.on('drop', ...)` taking `dataTransfer.files` and moving the cursor to `codemirror.coordsChar` of the drop point; both call `preventDefault()` only when they take files. The queue is strictly serial: a file over `data-kokpit-image-max-bytes` gets the too-large notification and is skipped without upload; otherwise the component (`window.Livewire.find` of the nearest ancestor's `wire:id`) runs `$wire.upload('imageUpload', file, finish, error, progress)` and on finish calls `$wire.storeImageUpload()`; an `ok` reply inserts `reply.reference` inside one `codemirror.operation()` at the cursor (preceded by a newline when the cursor ends a line with text) and selects the alt part; a refusal reply or an upload error shows `new window.FilamentNotification().title(...).body(...).danger().send()` (title and body from the reply or from the data attributes) and inserts nothing; a failure never stops the next file. While the queue runs, the status element shows the uploading text with the `kokpit-image-status--busy` class (a spinner drawn in the constructed stylesheet with the panel primary colour) and every `button[type=submit]` of the component root is disabled, re-applied after each Livewire request through `Livewire.hook('commit', ...)`; when the queue ends the buttons are enabled again and the done text shows for 4 seconds. The script builds nodes with createElement and textContent only, evaluates no string and holds no Czech text; the header comment documents the image flow next to the task-list text.
