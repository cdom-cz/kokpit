# Phase 20 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 20 adds images to the knowledge article the Admin already edits and reads. It introduces no new screen. It touches five existing surfaces and adds one relation manager:

1. The Markdown editor of the create and edit screens (insert button, paste, drop, progress, errors, secret notice).
2. The server-rendered preview tab, the view screen, the version view and restore (one renderer, `<img>` for internal images).
3. The version diff (shows Markdown source, so the reference text appears literally).
4. A new "Obrázky" relation manager on the article view screen (list of images and the Admin delete-for-good action).
5. The guard and refusal messages of a save (foreign image reference).

Sources: every decision below that cites `D-nn` comes from `20-CONTEXT.md`. Everything else is marked "default" and is the researcher's recommendation.

## Typography

No new size or weight is introduced. The scale is the one of `kokpit-prose.css`: four sizes (28, 20, 16, 14), two weights (400, 600).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Where each new text sits:

- Secret notice, upload status line, relation manager cells, table badges, modal helper text: Label (14/400/1.5), muted colour where it is a hint.
- Modal heading and relation manager heading: Filament native (heading role, weight 600).
- Missing-image fallback text inside the article: Body (16/400/1.5), muted colour (see Color).
- Display is not used by any new element; it exists in the scale only because the prose h1 uses it.

## Color

Colours come from Filament custom properties, so light and dark mode follow the panel. The panel primary colour is `Color::Amber`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--gray-50` `#f9fafb` light, `--gray-950` `#030712` dark | Page background |
| Secondary (30%) | white light, `--gray-900` dark | Section cards, the relation manager table, the editor surface |
| Accent (10%) | `--primary-600` `#d97706` light, `--primary-400` `#fbbf24` dark | See reserved list |
| Destructive | `--danger-600` `#dc2626` light, `--danger-400` `#f87171` dark | Delete-for-good action only |

Accent reserved for (this phase):

1. Keyboard focus ring of the insert-image toolbar button (the existing `--kp-focus` token; Filament native focus styling).
2. The upload progress indicator (spinner) in the editor.

Accent is not used for the image itself, the notice, the thumbnails or the badges.

Semantic colours used by the phase, none of them accent: `warning` for the secret notice (same Filament Callout family as the ambiguous-finding guard callout; note that it renders amber like the accent, the contrast comes from the callout chrome, not from a new colour); `success` badge "V aktuálním textu"; `gray` badge "Jen ve starších verzích"; `warning` badge "Nepoužitý".

Image chrome inside the article (`.kokpit-prose img`): `border: 1px solid var(--kp-border)`, no background, no filter in dark mode. Missing-image fallback uses `--kp-muted`.

## Copywriting Contract

All Czech UI text lives in `lang/cs/knowledge.php` under a new `images` array (project rule). Keys below are a recommendation for the planner; the Czech text is the contract. Code and tests stay in English.

### Editor

| Element | Copy |
|---------|------|
| Primary CTA (toolbar button title and aria-label) | Vložit obrázek |
| Upload in progress (status line, `role="status"`) | Nahrávám obrázek… |
| Upload done (status line, cleared after 4 s) | Obrázek byl vložen |
| Secret notice (persistent callout, warning, one line, directly above the "Citlivý článek" toggle, appears after the first successful upload on the screen) | Obrázek může obsahovat tajné údaje a jeho obsah nejde automaticky zkontrolovat. Pokud ano, označte článek jako citlivý. |
| Default alt text | The file name without its extension, inserted as `![file-name](kokpit-attachment:<uuid>)` with the alt part selected so typing replaces it (D-03). An empty alt is allowed. |

### Upload refusals (Filament danger notification; title always the same, body per cause; nothing is inserted into the text on failure)

| Cause | Title | Body |
|-------|-------|------|
| Not a supported image, or does not decode (D-07) | Obrázek nebyl nahrán | Soubor není podporovaný obrázek. Použijte PNG, JPEG, WebP nebo GIF. |
| SVG (D-07) | Obrázek nebyl nahrán | SVG se nenahrává, protože může obsahovat skripty. Použijte PNG, JPEG, WebP nebo GIF. |
| Over 10 MB (D-06) | Obrázek nebyl nahrán | Soubor má více než 10 MB. Zmenšete ho a nahrajte znovu. |
| Too many pixels (D-06) | Obrázek nebyl nahrán | Obrázek má příliš mnoho pixelů. Zmenšete ho a nahrajte znovu. |
| Animated GIF (D-09) | Obrázek nebyl nahrán | Animované GIFy se nepodporují. Nahrajte statický obrázek nebo jeden snímek. |
| Storage or processing failure | Obrázek nebyl nahrán | Obrázek se nepodařilo zpracovat. Zkuste to znovu. |

### Save refusal (D-04)

| Element | Copy |
|---------|------|
| Body field error (the typed text stays in the editor) | Text odkazuje na obrázek jiného článku. Obrázky nejde sdílet mezi články. Nahrajte ho do tohoto článku znovu. |

### Missing image in rendered text (D-04, D-18, D-19)

| Element | Copy |
|---------|------|
| Alt text is not empty | The alt text itself, inside `<span class="kokpit-image-missing">`, muted colour. |
| Alt text is empty | Obrázek není k dispozici |

The restore flow shows no notification, error or warning for a missing image (D-18).

| Element | Copy |
|---------|------|
| Heading | Obrázky |
| Columns | Náhled, Soubor, Rozměry, Velikost, Nahráno, Použití |
| Dimensions cell | `1200 × 800 px` |
| Usage badge: referenced by the current body | V aktuálním textu |
| Usage badge: referenced only by stored versions | Jen ve starších verzích |
| Usage badge: referenced by nothing | Nepoužitý |
| Empty state heading | Článek zatím nemá žádné obrázky |
| Empty state body | Vložte obrázek v editoru tlačítkem, vložením ze schránky nebo přetažením. |
| Row action label | Smazat navždy |

### Destructive: delete an image for good (D-19)

Modal opened by the row action. Heading: **Smazat obrázek navždy?**

| Element | Copy |
|---------|------|
| Irreversible text | Obrázek se okamžitě odstraní z úložiště. Všechny odkazy na něj v aktuálním textu i ve všech verzích se pak zobrazí jen jako popisek. Smazání nelze vrátit zpět. |
| Rotate-the-secret callout (warning) | Smazání odstraní jen kopii z Kokpitu. Pokud obrázek obsahoval tajný údaj, změňte nebo zneplatněte ho i u jeho vydavatele (heslo, klíč, token). |
| Reason label | Důvod smazání |
| Reason helper | Do protokolu změn se zapíše jen to, že důvod existuje, ne jeho text. Nepište do něj tajný údaj. |
| Reason errors | Vyplňte důvod smazání. / Důvod může mít nejvýše :max znaků. |
| Submit (danger) | Smazat obrázek navždy |
| Cancel | Zrušit |
| Success notification | Obrázek byl smazán |
| Failure notification | Obrázek se nepodařilo smazat. Nic se nezměnilo, zkuste to znovu. |

The reason is required, validated and discarded after the action: only the fact that a reason exists reaches the activity log (D-19). The reason text is never stored and never echoed back. Pattern is the Phase 19 redaction modal (`knowledge.redact.*`), kept visually identical so the Admin meets one idiom for both irreversible actions.

## Interaction Contract

### Inserting an image (D-01, D-02)

- Three entry points, one outcome: the toolbar button opens the native file picker; a screenshot pasted from the clipboard and a file dropped on the editor go through the same upload.
- The toolbar button sits in the group with the table button: `['table', 'attachFiles']`. Icon is Filament's native image icon for `attachFiles`. The button has title and aria-label "Vložit obrázek". The existing task-list script pattern (title, aria-label, no inline markup) applies to any label override.
- During an upload the status line below the toolbar shows the progress text with the accent spinner, and the form's submit button is disabled (an upload that is still running must never be saved as a half-inserted placeholder). When the upload ends the button is enabled again.
- On success the reference is inserted at the cursor, on its own line when the cursor sits at the end of a line with text, otherwise in place; the alt part is selected.
- Several files dropped at once upload one after the other; each gets its own reference line. A failure in one does not cancel the others; each failure produces its own notification.
- Leaving the screen with an uploaded but unsaved image is covered by the existing leave warning of Phase 18 (the text changed). The image stays pending and is removed by the cleanup job after 24 hours (D-02). The UI says nothing about this.

### Secret notice (D-05)

A schema Callout (warning, one line) directly above the `Citlivý článek` toggle, hidden until the first successful upload on this screen, then visible until the screen is left. It is a persistent line, not a toast, so it can be read after the upload and is announced once (`role="status"`). No action button inside the callout: the toggle right below is the action.

### Rendering (D-13, D-14)

- One renderer for the preview tab, the view screen, the version view and the restore preview. They all show the same `<img>`.
- `<img>` attributes the renderer emits: `src` (the authorised route `/knowledge/attachments/{uuid}`, no bucket URL), `alt` (from the Markdown), `loading="lazy"`, `decoding="async"`, and `width` and `height` of the stored (re-encoded) image so the layout does not jump while it loads.
- No link wraps the image and no lightbox or zoom exists in this phase. The Admin sees the image at its fitted width.
- External image URLs stay plain alt text, unchanged from Phase 18.

### Stylesheet rules for `.kokpit-prose` (added to `kokpit-prose.css`)

| Rule | Value |
|------|-------|
| `img` | `max-width: 100%`, `height: auto`, `border: 1px solid var(--kp-border)`, `border-radius: 8px`, `vertical-align: middle` |
| `p > img:only-child` (an image alone in its paragraph) | `display: block` so it takes the block rhythm of 24px |
| `img` inside a paragraph with text | `display: inline-block`, vertical margin 4px |
| `.kokpit-image-missing` | `color: var(--kp-muted)`, weight 400 |

The prose container is `max-width: 48rem`, so a 2400px image shows at at most 768px. There is no max-height; a tall screenshot scrolls with the page.

### Obrázky relation manager (D-19)

- Appears on the article view screen, below the body, beside the existing history manager, Admin only. Lists images bound to the article (pending images are not listed because they have no article yet).
- Default sort: newest upload first. No search, no filters, no pagination controls beyond the Filament defaults for a short table (default page size 10).
- The thumbnail is 48 x 48 px, `object-fit: cover`, loaded through the authorised route. A thumbnail whose object is gone shows nothing but the cell stays aligned.
- The single row action is "Smazat navždy", danger colour, with the heading icon `heroicon-o-trash`. It is the only destructive control in the table. The modal follows the Copywriting Contract and uses Filament's modal focus trap and focus return.
- After the action the row disappears and the Filament success notification shows. The article body is not touched.

### Version diff

The diff shows Markdown source, so a reference appears as the literal text `![alt](kokpit-attachment:<uuid>)`. The existing diff cell already wraps long text (`overflow-wrap: anywhere` in the diff stylesheet; the executor confirms it covers a 36-character UUID with no spaces). The diff never renders an `<img>`.

## Accessibility

- The insert button has `title` and `aria-label` "Vložit obrázek". Focus ring is Filament native.
- The upload status line and the secret notice use `role="status"` (polite). Upload refusals use Filament notifications (alert semantics).
- Every rendered `<img>` carries the Markdown alt text; an empty alt becomes `alt=""` (decorative), which is the Admin's choice (D-03: no requirement).
- The delete modal traps focus, returns it to the row action on close and puts initial focus on the reason field.
- Nothing in the phase relies on colour alone: the usage state is a badge with text, the missing image is text.

## Partner and Hygiene Notes for the Planner

- Every new route (`/knowledge/attachments/{uuid}`), relation manager and Livewire component is declared in `PartnerMatrix` and `RouteRules` in the same pull request. A Partner sees no Obrázky manager, no insert button, and gets a refusal (not a redirect to a bucket) on the image route.
- All fixtures are fictional and assembled at runtime: a generated test photo with a GPS position, a renamed non-image, an SVG, an oversized file, an animated GIF. File names in tests use `example`-style names such as `screenshot-example.png`.
- The activity log of the delete-for-good action records who, which article and that a reason exists, never the reason text and never the file name (file names can carry client names).
