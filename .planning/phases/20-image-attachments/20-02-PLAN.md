Rulings made in this plan (recorded):
- R-20-02-1 (library): PHP GD only, as research recommends (present on the host, in DDEV and in the CI extension list; Imagick is DDEV-only). No Composer package is added. The deploy target is covered by the capability check of 20-03.
- R-20-02-2 (limits as constants of `ImagePipeline`): `MAX_UPLOAD_BYTES = 10 * 1024 * 1024`, `MAX_PIXELS = 24_000_000`, `MAX_EDGE = 2400`, `MAX_STORED_BYTES = 32 * 1024 * 1024` (the database bound of R-20-01-1), `JPEG_QUALITY = 85`, `WEBP_QUALITY = 85`, `PNG_COMPRESSION = 9`, `MEMORY_HEADROOM = 16 * 1024 * 1024`. Memory preflight (assumption A3): needed = width x height x 4 + min(width x height, MAX_EDGE squared) x 4 + MEMORY_HEADROOM; refused as TooManyPixels when the memory limit is finite and needed exceeds the limit minus `memory_get_usage(true)`. The limit is a constructor argument `?int $memoryLimitBytes = null`; null reads `ini_get('memory_limit')` (K, M, G suffixes; -1 means no limit), so the Unit test can inject a small one.
- R-20-02-3 (order of `process(string $bytes): ProcessedImage`): 1 empty input is NotAnImage, more than MAX_UPLOAD_BYTES is TooLarge; 2 `ImageFormat::sniff()` by magic bytes (PNG `\x89PNG\r\n\x1a\n`, JPEG `\xFF\xD8\xFF`, GIF `GIF87a` or `GIF89a`, WebP `RIFF` + 4 bytes + `WEBP`); no match is Svg when the input, after an optional UTF-8 BOM and whitespace, starts case-insensitively with `<?xml`, `<svg` or `<!DOCTYPE svg`, or `finfo` reports `image/svg+xml` for the buffer, otherwise NotAnImage; 3 `getimagesizefromstring` must return width and height of at least 1 and the IMAGETYPE of the sniffed format, otherwise NotAnImage; 4 pixel cap and memory preflight (TooManyPixels); 5 `Animation::isAnimated()` (true is Animated, null is NotAnImage); 6 decode with `imagecreatefromstring` (false is NotAnImage); 7 a palette image becomes truecolor with `imagepalettetotruecolor`; 8 for JPEG, `JpegOrientation::apply($image, JpegOrientation::read($bytes))`; 9 a fresh truecolor canvas scaled to fit MAX_EDGE (never up), alpha kept for PNG, WebP and GIF (`imagealphablending` false, `imagesavealpha` true, filled with a fully transparent colour), white background for JPEG; `imagecopyresampled` onto it; 10 encode in the sniffed format through an output buffer (`imagepng` with PNG_COMPRESSION, `imagejpeg` and `imagewebp` with their quality, `imagegif`); an empty or false result is Failed; 11 the output read again with `getimagesizefromstring` gives the stored width and height; more than MAX_STORED_BYTES is TooLarge; 12 `ProcessedImage` with the bytes, format, width, height and `hash('sha256', $output)`.
- R-20-02-4 (warnings): every GD and getimagesize call runs inside a private helper that installs `set_error_handler` turning any warning or notice into an `ErrorException` and restores the previous handler in `finally`; an ErrorException or ValueError while reading or decoding is NotAnImage, while encoding is Failed. No `@` suppression. This makes the behaviour identical in the Unit suite (no Laravel error handler) and in the application. GD's deprecated destroy function is never called (deprecated since PHP 8.5; GD objects are freed by the garbage collector) and the GD scale function is not used (it failed on an alpha WebP in the research probe); the source must not name either function, not even in a comment, because the Unit test scans for both.
- R-20-02-5 (JPEG orientation) `JpegOrientation::read(string $jpeg): int` walks the JPEG markers from offset 2 up to SOS or EOI, bounded by the segment lengths, finds an APP1 segment starting with `Exif\0\0`, reads the TIFF byte order (`II` or `MM`), IFD0 and the SHORT tag 0x0112; anything malformed or missing returns 1. `JpegOrientation::apply(\GdImage $image, int $orientation): \GdImage`: 2 flips horizontally; 3 rotates by 180; 4 flips vertically; 5 rotates by -90 and then flips horizontally; 6 rotates by -90; 7 rotates by 90 and then flips horizontally; 8 rotates by 90 (GD `imagerotate` angles are counter-clockwise; rotations use a fully transparent fill); 1 and unknown values return the image unchanged. ext-exif is not used by production code (smaller attack surface on hostile input); only the tests use `exif_read_data` to prove the strip.
- R-20-02-6 (animation) `Animation::isAnimated(ImageFormat $format, string $bytes): ?bool`: GIF uses the block walker of research Pattern 3 (header and global colour table, extensions skipped by their sub-blocks, image descriptors counted with their local colour table and LZW byte, stop at 2 frames; malformed or truncated returns null; 2 or more is true); PNG walks the chunks from offset 8 (4-byte big-endian length, 4-byte type, data, 4-byte CRC), true when `acTL` appears before the first `IDAT`, false at `IDAT`, null when a chunk runs past the end before `IDAT`; WebP is true when the chunk at offset 12 is `VP8X` and the flag byte at offset 20 has bit 0x02, or when a top-level `ANIM` or `ANMF` chunk exists; JPEG is false.
- R-20-02-7 (types) `enum ImageFormat: string` with `Png = 'image/png'`, `Jpeg = 'image/jpeg'`, `Webp = 'image/webp'`, `Gif = 'image/gif'`, methods `extension()` (png, jpg, webp, gif), `imageType()` (the IMAGETYPE constant) and `static sniff(string $bytes): ?self`. `final readonly class ProcessedImage` (bytes, format, width, height, sha256; `mimeType()` and `size()`). `enum ImageRefusal: string` with `NotAnImage = 'not_an_image'`, `Svg = 'svg'`, `TooLarge = 'too_large'`, `TooManyPixels = 'too_many_pixels'`, `Animated = 'animated'`, `Failed = 'failed'` and `messageKey()` returning `knowledge.images.errors.` followed by the value (the keys are written by 20-04). `final class ImageRefused extends \RuntimeException` with `public readonly ImageRefusal $refusal` and the fixed message 'The image was refused.'; it never carries any byte, name or size of the file.
- R-20-02-8 (accepted tradeoffs, written into the `ImagePipeline` docblock): JPEG re-encode is lossy; ICC profiles are dropped, so a Display P3 screenshot shifts slightly towards sRGB (assumption A6); a resized GIF is re-quantised; a 16-bit PNG becomes 8-bit; GD writes its own creator comment into a JPEG, which carries nothing of the upload.
- A5 (recorded assumption, no checkpoint): the refusal of animated PNG and animated WebP goes beyond D-09, which names GIF only. It is the safe default (otherwise the stored file silently differs from the upload); the owner may relax it by deleting the PNG and WebP branches of `Animation::isAnimated()`, a change local to one class.
