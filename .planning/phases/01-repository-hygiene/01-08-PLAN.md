Facts verified at planning time with gitleaks 8.30.1 (a git wrapper logged the arguments gitleaks passes):
- Default `gitleaks git .` runs `git log -p -U0 --full-history --all --diff-filter=tuxdb`. It missed a fake in a `-diff` file, a fake in a NUL-containing file and a fake added only in a merge commit.
- With `--log-opts="--all --diff-merges=first-parent --text --no-textconv"` gitleaks runs `git log -p -U0` followed by exactly those options and reports all three. It still misses UTF-16 content (the in-house scanner covers that, plan 01-07).
- `gitleaks git --pre-commit --staged` runs `git diff -U0 --no-ext-diff --staged .` with no way to add options. It missed the `-diff` file and the NUL file.
- A `-text` attribute alone does not hide content from `git diff`, so the guard does not reject it.

Rule design decisions:
- The guard is a scanner rule, so it runs in the hook (staged mode), in the CI tree scan (`--all`) and in explicit-file mode. It reuses the allowlist and masking.
- It is skipped for history rows: their line field carries `@sha7` (set by `scripts/lib/diff2tsv.awk`), so no driver change is needed and this plan stays independent of plan 01-07.
- Rejected tokens: `-diff`, `binary` (the macro for `-diff -merge -text`), and any `filter=` attribute. A clean/smudge filter (for example Git LFS) stores something other than the file in git, so the real content reaches the remote without passing either layer. A reviewed allowlist entry (rule `git-attributes`) can exempt a deliberate use later.
- Laravel's default `.gitattributes` (`text=auto`, `eol=lf`, `diff=<language>`, `export-ignore`) passes, so Phase 2 meets no friction.

The CODEOWNERS owner handle is the one already used in the file. Reuse it verbatim; do not resolve or introduce any other identity.

## Flagged assumptions

- **A-HYG-04G (unresolved, edge probe unclassified):**
  - In the pre-commit hook, gitleaks stays blind to NUL-containing content and to UTF-16. The `sensitive-content` job (plan 01-07) covers both, and CI gitleaks covers NUL content.
  - `--no-verify` and `LEFTHOOK=0` still skip the hook, as accepted in A-HYG-04 (01-01-PLAN.md), because CI is the authoritative gate.
  - A developer's local `.git/info/attributes` or textconv config can still blind the local gitleaks job. Both are local-only and never reach CI.
- **A-ATTR-01:** a deliberate future use of Git LFS or another filter needs a reviewed allowlist entry for rule `git-attributes`. Its content would then bypass both layers by design, so the decision belongs to the maintainer.
