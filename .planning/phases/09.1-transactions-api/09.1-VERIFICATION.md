### Gaps Summary

One blocking gap: **CR-01 is a real defect**, reproduced against the running code, not just traced. A PATCH that drops an own rate and supplies the bank CZK figure in the same request silently stores the CNB figure instead, with HTTP 200. That violates D-06(b) ("czk_amount_minor, the real bank figure, `czk_source = manual`") and the project's data-integrity core value, and no test covers the combination (the existing tests cover both nulls, `exchange_rate: null` alone, and `czk_amount_minor` alone). The fix is small and local to `TransactionPayload::cleared()` (see `missing`), plus one regression test; it is suitable for `/gsd-plan-phase 09.1 --gaps`.

Everything else in the phase goal is achieved and evidenced in the code: eight routes under separate `finance:read` / `finance:write` groups, single and bulk create (partial success, 500 limit, idempotency, one write against the rate limit), update and delete through the shared Actions, the `custom` CZK source enforced by DB CHECKs, Partner and guest isolation, and published docs.

WR-01 (boolean accepted as integer; on a currency-change PATCH it can re-denominate a stored amount) is the next most important warning because it can also produce wrong money without a signal; it is not a stated must-have, so it is recorded as a warning and should be considered for the same gap-closure plan. WR-02, WR-03, WR-04 and the three info items (IN-01 scribe `manual` wording, IN-02 frozen manual figure not documented, IN-03 422-before-404 order) remain `open` in 09.1-REVIEW-DISPOSITION.md and do not block the goal.
