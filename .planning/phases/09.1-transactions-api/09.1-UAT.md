## Tests

### 1. Cold Start Smoke Test
expected: Kill any running server/service. Clear ephemeral state. Start the application from scratch (ddev restart) and run the migrations. The app boots without errors, the migrations complete, and the Admin panel (e.g. the transactions list) loads with live data.
result: pass

### 2. Issue a finance token on the token screen
expected: In the Admin panel, the API token create modal offers four abilities (time read/write, "Čtení financí", "Zápis financí") with Czech descriptions. A token created with the two finance abilities is shown once and listed with exactly those abilities.
result: pass

### 3. Create a CZK transaction over the API
expected: POST /api/v1/transactions with a finance:write token and a CZK expense (amount_minor, currency CZK, transaction_date, category_id) answers 201 with a Location header and the 18-key body (id first). The same call with a time-only token answers 403, without a token 401.
result: pass

### 4. Transaction at an own exchange rate
expected: POST of a EUR expense with exchange_rate (e.g. 25.125) answers 201 with czk_source "custom", the stored exchange_rate and czk_minor = amount x rate. The rate does not appear in the CNB exchange rates list.
result: pass

### 5. Admin screen shows the own-rate transaction
expected: In the Admin transactions list the row shows the CZK figure with a separate "vlastní kurz" badge. Its edit page shows the stored rate (not the CNB preview) and no CZK field while amount, date and currency are unchanged.
result: pass

### 6. Sticky own rate on edit, return to CNB
expected: PATCH of only the description leaves czk_minor and rate unchanged. PATCH of a new amount_minor recomputes czk_minor at the stored rate (czk_source stays "custom"). PATCH with exchange_rate null returns the row to the CNB rate (czk_source "cnb"). PATCH with exchange_rate null together with a czk_amount_minor stores it as "manual".
result: pass

### 7. List, filters, pagination and categories
expected: GET /api/v1/transactions returns newest first by transaction date with meta.next_cursor that pages without skips or repeats. filter[czk_source]=custom, filter[type], date_from/date_to narrow it. A malformed filter or cursor answers 422. GET /api/v1/transaction-categories (and /{id}) lists the category UUIDs with an archived flag; no write route exists there.
result: pass

### 8. Batch import with partial success
expected: POST /api/v1/transactions/batch with a mix of valid and invalid items answers 207, saves the valid ones, and lists only the failed items as {index, errors} under API field names (amount_minor, not amount). All valid answers 201; all invalid answers 422; more than 500 items or an empty list answers 422 and saves nothing.
result: pass

### 9. Idempotency-Key on creates
expected: Repeating POST /api/v1/transactions with the same Idempotency-Key and body returns the same response with an Idempotent-Replayed header and creates no second row. The same key with a different body answers 422 idempotency_key_reused.
result: pass

### 10. Delete a transaction
expected: DELETE /api/v1/transactions/{id} answers 204 and the transaction (with its receipts) is gone; a following GET answers 404 in Czech. A transaction that the database refuses to delete answers 409 transaction_in_use.
result: pass

### 11. Invalid input is refused with clear errors
expected: JSON booleans in amount_minor, czk_amount_minor or exchange_unit_amount answer 422 with the panel messages. A CZK figure together with an exchange_rate on create answers 422. Nothing is written in any of these cases.
result: pass

### 12. Partner and guest isolation
expected: A Partner account cannot obtain or use a token to reach any transaction or category endpoint (401), and finance data never shows on Partner pages. API docs (/docs) describe the finance endpoints, the four abilities and the custom source.
result: pass
