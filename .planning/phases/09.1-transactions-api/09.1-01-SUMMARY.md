# Phase 9.1 Plan 01: Own exchange rate (custom CZK source) Summary

**A transaction can be booked at an exchange rate of its own: a new `custom` CZK source, one conversion through `Money::convert`, and a database that refuses a custom figure without the rate snapshot that produced it.**

## Performance

- **Duration:** ~30 min
- **Completed:** 2026-10-16
- **Tasks:** 2 (a tracer and one auto/TDD task)
- **Files modified:** 11

## Accomplishments

- Migration `2026_10_16_000600_add_custom_czk_source_to_transactions.php` replaces the two CHECKs by name (`custom` joins the snapshot-requiring sources); `down()` rewrites custom rows to manual with an empty snapshot before restoring the originals. The identity CHECK is untouched and a schema test proves it still refuses custom on a CZK row.
- `CzkSource::Custom` with the Czech label "Vlastní kurz", the `CustomRate` value object and the custom branch of `TransactionCzk::resolve()` (new optional fourth parameter, so existing callers are unchanged).
- `TransactionInput` parses and checks `exchange_rate` (comma or dot, at most 10 integer and 10 fraction digits, not zero) and `exchange_unit_amount` (1..2147483647, default 1), refuses a rate together with a typed CZK figure, and accepts a known ISO currency without CNB rows when a rate or a CZK figure is given.
- `RecordTransaction` passes the rate through; the own rate wins over a stored CNB list of the same currency and day and is never written to `exchange_rates`.
