# Phase 9.1 Plan 04: Edit rule of a custom transaction and the Admin screen Summary

**Owner decision A1 (sticky own rate) implemented once in the shared `UpdateTransaction`, plus an own-rate badge and a kept-own-rate edit state in the Filament transactions screen, so a description edit can no longer move a figure booked at an own rate.**

## Performance

- **Duration:** 10 min
- **Started:** 2026-10-16T22:15:19Z
- **Completed:** 2026-10-16T22:25:34Z
- **Tasks:** 3 (a tracer and two auto/TDD tasks)
- **Files modified:** 5

## Accomplishments

- `UpdateTransaction::figure()` keeps the own rate on a changed amount (recompute at the stored rate and unit amount, stored rate date kept), falls back to CNB or identity on a changed currency, leaves figure and snapshot on a date-only or text-only change, and turns a custom row back to CNB when the data names `exchange_rate` null (with `czk_manual` false from the API). A CNB row and a manual row are not touched by the cleared rate alone.
- A typed own rate makes any transaction custom with the transaction date as rate date; a typed CZK figure makes it manual. The Phase 9 branches behave as before (all `TransactionCzkTest` cases still pass).
- The Admin list shows the CZK figure of a custom row with a separate "vlastní kurz" badge (info colour, manual keeps its warning badge).
- The Admin edit page of a custom row shows the stored rate instead of the CNB preview and no CZK field while amount, date and currency are unchanged, also for a currency without any CNB row (ISK test). Changing any of the three shows the CNB preview again and stores cnb. Turning the manual switch on prefills the stored CZK figure.
