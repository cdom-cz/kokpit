Decisions made in this plan (recorded):
- Only `transactions_czk_source_check` and `transactions_snapshot_check` are replaced. `transactions_identity_check` (`(amount_currency = 'CZK') = (czk_source = 'identity')`) already refuses custom on a CZK row and accepts it on a foreign row, so it stays as it is and a schema test pins that (RESEARCH Pattern 4).
- The rate date of a new own rate is always the transaction date; the API accepts no separate rate date (D-06 "defaults to the transaction date"; no request field for it is named in D-06).
- `TransactionInput` exposes `customRateCleared` (the data names `exchange_rate` with null) for plan 09.1-04, which turns it into "drop the own rate and compute through CNB"; `RecordTransaction` ignores it.
- A CZK amount with a rate stays identity in the domain (the rate is ignored, as a typed CZK figure already is); the API refuses that combination in its own layer (plan 09.1-06).
- `exchange_unit_amount` is not added to the activity allowlist: `exchange_rate` and `czk_minor` are already logged, so the effect of a unit change is audited (owner left this to the planner).
- Phase 10 plans 10-06, 10-16, 10-19 edit `TransactionTablesTest`, `RecordTransaction` and `UpdateTransaction`. Every change here is additive: a new optional fourth parameter of `TransactionCzk::resolve()`, new optional data keys, new tests in a new describe block, no rename, no removed key, no signature change of `handle()`.
