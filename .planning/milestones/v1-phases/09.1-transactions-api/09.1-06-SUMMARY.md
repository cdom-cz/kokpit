# Phase 9.1 Plan 06: Single transaction writes over the API Summary

**Create, edit and delete a transaction over the REST API through the three Phase 9 Actions, with minor-unit amounts mapped to the Actions' strings, the D-06 rate options, error keys under API field names and a refused delete answered as 409 transaction_in_use.**

- **Tasks:** 3 (a tracer and two auto/TDD tasks)

## Accomplishments

- `POST /api/v1/transactions` records through `RecordTransaction` and answers 201 with the D-07 body and a `Location` header; it carries the optional `Idempotency-Key` like the time entry creates, and the docs and the docs test list it as the third create.
- `TransactionPayload` is the one mapping place: shape rules only, allow-listed Action keys, `Money::ofMinor()->toMajor()` for `amount_minor` and `czk_amount_minor`, the CZK guard (RESEARCH A5) and `remap()` of `amount`/`czk_amount` to `amount_minor`/`czk_amount_minor`.
- `PATCH` follows "absent keeps, null clears" and the null matrix of the rate and the bank figure (owner decision A1); `currency` without `amount_minor` is refused under `amount_minor`.
- `DELETE` removes the transaction with its receipts; a database refusal (23503 or KP001) answers 409 `transaction_in_use` with exactly `{message, code}`, anything else stays a 500.
- `ApiDocs::statusCodes()` takes the controller: a controller that declares `CONFLICT_METHODS` owes a 409 only for the listed methods; controllers without the constant are checked as before.
