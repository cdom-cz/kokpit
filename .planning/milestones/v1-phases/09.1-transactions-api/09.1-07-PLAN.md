- Request key `transactions`, item-level error key `transaction`, config key `api.transaction_batch_max_items` (RESEARCH A8; the time batch uses `entries` / `entry`).
- An item that is not an array, or is a non-empty JSON list, fails under `transaction` with `api.errors.batch_item_not_object`; transactions carry no `external` object, so the raw body is not needed.
- The 500-item timing is measured in the test (`hrtime` around the request) and written to STDERR as one line; the test asserts counts only, so its pass or fail never depends on the speed of the machine (plan check: automated checks stay deterministic). - The production PHP request time limit is not visible in the repository (RESEARCH A4); the SUMMARY records it as an open item for the owner.
- The docs tell an importer to deduplicate on its side (a transaction has no `external` field; `document_number`, date and counterparty are its natural keys) and to list the period before resending a batch under a new key.
