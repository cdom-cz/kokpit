# Phase 09.1 Plan 05: Transaction List and Category Tree Summary

**Cursor-paginated GET /api/v1/transactions with eight filters and three sorts (amount ordered by the CZK figure), plus a read-only transaction category list and detail with an archived flag, behind finance:read**

## Performance

- **Duration:** about 45 min
- **Completed:** 2026-10-16
- **Tasks:** 3
- **Files modified:** 15 (6 created, 9 modified)

## Accomplishments

- The transaction list answers newest first by transaction date with the id as tiebreaker in the direction of the sort, 50 per page by default and 200 at most, and `meta.next_cursor` never skips or repeats a row under any of the six sort expressions.
- `ApiCursor` learned a `date` kind (`Y-m-d` or the `Y-m-d 00:00:00` form the paginator writes for a date cast) and an `integer` kind (a JSON integer only). A forged or mixed-up cursor of any sort answers 422 instead of a PostgreSQL 500.
- Filters `type`, `category` (a parent includes its children), `client`, `project` (UUID or key), inclusive `date_from` and `date_to`, `currency` and `czk_source` narrow the list; unknown keys and malformed values answer 422.
- `GET /api/v1/transaction-categories` and `/{category}` give an importer the category UUIDs: keys `id`, `parent_id`, `name`, `type`, `archived`, sorted by name, filterable by `type` and `archived`. `archived` is true for an archived category and for a child of an archived parent.
- No write route exists under `transaction-categories`; a route-table test and 405 checks pin it.
- The docs carry the endpoint descriptions, every filter as a query parameter, and example payloads whose cursors the API accepts with a 200. The route walk, the pin and the per_page count (6) cover the new routes, and two Admin canary controls make the guest and Partner 401 proofs non-vacuous for the finance lists.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] PHPStan return type of two existing requests**
- **Found during:** Task 1 (after adding the `date` and `integer` cursor kinds)
- **Issue:** `ListLookupsRequest::cursorColumns()` and `ListTimeEntriesRequest::cursorColumns()` declared the kind union `'uuid'|'instant'|'text'`, which the widened `ApiCursor::kindOf()` no longer fits.
- **Fix:** Widened the phpdoc return union in both files; no behavior change.
- **Files modified:** `app/Http/Requests/Api/V1/ListLookupsRequest.php`, `app/Http/Requests/Api/V1/ListTimeEntriesRequest.php`
- **Verification:** PHPStan clean, full suite green
- **Committed in:** `f800f48`

**2. [Rule 1 - Bug] Scribe URL parameter name of the category detail**
- **Found during:** Task 3
- **Issue:** The plan said to name the `#[UrlParam]` as the generated spec names it. Scribe renames `{transaction}` to `{id}` but leaves `{category}` as it is, so the `id` name from the client precedent would not match the documented path.
- **Fix:** `#[UrlParam('category', ...)]`; the spec path is `/api/v1/transaction-categories/{category}`.
- **Files modified:** `app/Http/Controllers/Api/V1/TransactionCategoryController.php`
- **Verification:** documentation tests green
- **Committed in:** `1b72ba4`
