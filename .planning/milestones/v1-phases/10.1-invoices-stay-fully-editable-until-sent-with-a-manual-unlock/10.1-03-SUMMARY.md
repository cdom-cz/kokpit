# Phase 10.1 Plan 03: Time link and payment link follow the lock Summary

**Tracked time can now be added to and released from an issued invoice or proforma until it is sent, and a card payment link no longer pins the currency of an open document, all enforced in PostgreSQL for raw SQL too.**

## Performance

- **Duration:** about 40 min
- **Tasks:** 3 (the third is a database push with no file change)
- **Files modified:** 5

## Accomplishments

- Migration `2026_10_22_000200_follow_invoice_lock_in_time_entry_link.php`: `kokpit_invoice_accepts_time_changes(uuid)` (true for a draft, or an issued open invoice/proforma that no issued storno cancels and no invoice names as its proforma; false for a locked document, a credit note and a missing document) and `kokpit_guard_time_entry_link()` rewritten in place. Only two branches changed: a reservation needs the helper, and an unbilling is accepted after an issued storno (unchanged) or while the helper says yes. The INSERT branch stays draft only, billing still needs the document issued, the proforma-to-invoice move and the frozen snapshot are unchanged. `down()` restores the Phase 10 body verbatim.
- Migration `2026_10_22_000300_relax_payment_link_currency_key.php`: `payment_links_invoice_currency_fk` becomes `payment_links_invoice_fk (invoice_id)`; the insert branch of `kokpit_guard_payment_link()` refuses a link in any currency but the document's (KP001, 'a payment link is created in the currency of its document'). `invoice_payments_invoice_currency_fk` is untouched. `down()` refuses with a RuntimeException while a link names a currency its document no longer has, otherwise restores the composite key and the previous body.
- Tests: new "following the lock" block in `TimeEntryInvoiceLinkTest` (open reserve/bill/release for invoice and proforma, locked refusals, credit note / cancelled invoice / converted proforma, partial credit note, helper truth table, down/up), an open-versus-locked twin in `BillingLockTest`, and four payment-link tests (currency change of an open document with an old link row, refused link in the old currency, payment keeps the key, down refusal and round trip).
- Schema gate: `migrate` applied the three 2026_10_22 migrations to the DDEV development database; `migrate:status` lists all three as Ran and a second run prints "Nothing to migrate".

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A link of a missing document would have answered KP001, not the plain key's 23503**
- **Found during:** Task 2 (writing the behavior test "a link of a document that does not exist is refused with 23503")
- **Issue:** The Phase 11 insert branch raised KP001 for a missing document (state read as NULL) before the foreign key could answer, so the plan's expected 23503 was unreachable.
- **Fix:** The insert branch returns NEW when the document row is not found, leaving the refusal to `payment_links_invoice_fk` (23503). Every document that exists is guarded exactly as before.
- **Files modified:** `database/migrations/2026_10_22_000300_relax_payment_link_currency_key.php`
- **Commit:** 6502f3d

**2. [Rule 3 - Blocking] Test fixture for an EUR document needs a CNB rate**
- **Found during:** Task 2 (first run of the currency-change tests)
- **Issue:** Issuing an EUR document through the real pipeline requires a stored CNB rate for the day.
- **Fix:** The test helper stores one with `InvoiceFixtures::cnbRate()` before issuing.
- **Files modified:** `tests/Feature/Payments/PaymentLinkRecordTest.php`
- **Commit:** 6502f3d
