## Shared Patterns

### Row lock first, Gate first
**Source:** `UpdateDraft.php` 104-107, `DeletePayment.php` 60-63, `RegeneratePaymentLink.php` 44-47, `RegeneratePdf.php` 50-53.
**Apply to:** `UpdateIssuedDocument`, `UnlockInvoice`, add/release time actions, `ReplaceIssuedPdf`, the lock step of `SendInvoiceEmail`, `QueueInvoiceEmail`.
```php
Gate::forUser($actor)->authorize('update', $invoice);
DB::transaction(function () use ($invoice) {
    $locked = Invoice::query()->whereKey($invoice->getKey())->lockForUpdate()->firstOrFail();
```
Lock order: invoice, then children (admin, payments, links). A row lock fires no UPDATE trigger.

### Guard error convention
**Source:** `..._000500` and `Immutability` builders. SQLSTATE `KP001` via `RAISE EXCEPTION ... USING ERRCODE = 'KP001'`. Actions pre-check and throw `ValidationException::withMessages([...__('invoices.errors.*')])` (fixed cs/en messages in `lang/cs/invoices.php`, `lang/en/invoices.php`; parity enforced by `tests/Feature/Localisation`), so KP001 is only a backstop.

### Transaction-local sanctioned-path flag
**Source:** `DeletePayment.php` 81 and 93 plus `tests/Arch/PaymentDeletionPathTest.php`. **Apply to:** `UnlockInvoice` only.

### No touch / no bulk update on a locked invoice
Locked rows refuse `updated_at`-only writes (see `InvoiceEmail` docblock: no `$touches`). Use model saves, never `Invoice::query()->update()` for lock/unlock (no activity row).

### Money
One `HALF_UP` rounding per line through `DraftTotals::lineTotal()` / `DraftTotals::for()`; payload validation through `InvoiceItemInput::list()`; CNB through `ExchangeRateConverter`.

### Partner exposure
New `invoices` column must be added to the pinned list in `tests/Isolation/PartnerSafeColumnsTest.php` (lines ~159-186). Put no unlock reason or lock timestamp on `invoices`.
