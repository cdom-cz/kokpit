<objective>
Make document numbering configurable without breaking the gap-free contract: token patterns for invoices, proformas and credit notes with a bounded grammar and per-kind limits, a fixed `KEY-N` task number, a read-only preview that never consumes a number, and one numbering entry point that maps the pattern onto the Phase 2 allocator's scope key (D-05).

Purpose: FND-07 numbering patterns. Phase 10 allocates invoice, proforma and credit-note numbers at issue and Phase 5 allocates task numbers; both must go through this entry point so a pattern change can never rewrite or duplicate a number. The editing UI on the settings page is plan 03-09.
Output: numbering value objects and service, `peek()`, `NumberPatternRule`, `NumberingSettings` with its migration, unit and feature tests.
</objective>

Uses from Phase 2: `SequenceAllocator` (`KEY_PATTERN`, `next()` inside the caller's transaction, `scopeKeyForYear()` in Europe/Prague; counter contract: `next_value` is the NEXT number). Uses from 03-03 and 03-04: `ValidatedSettings`, `SettingsMigration`, explicit class list in `config/settings.php`.

Resolved decision (open question 2, not re-asked): pattern editing covers invoice, proforma and credit note; defaults are `{YYYY}{NNNN}` for all three with separate counters (kinds `invoice`, `proforma`, `credit_note`); the task number stays `KEY-N` per project and is not freely editable: `task_pattern` is stored as `{KEY}-{N}` and the rule accepts only that value. Whether proformas also need digits-only numbers (variable symbol) is a Phase 10 decision and is recorded as an open item in the summary. Rating: reversible, the grammar sits in one class.

Grammar (planner decision, documented here and in the class docblock): tokens `{YYYY}`, `{YY}`, `{MM}`, `{N}` to `{NNNNNNNNNN}` (pad width 1 to 10, the counter is never truncated), `{KEY}` (task kind only); literal characters `A-Z a-z 0-9 . _ / -` (invoice kind: digits only); exactly one counter token; each date token at most once; `{MM}` only together with `{YYYY}` or `{YY}`; maximum pattern length 32; the parser is a linear scan, no regular expression with nested quantifiers runs on user input. `{YYYY}` and `{YY}` give the same yearly scope, so switching between them keeps the counter.

`NumberingSettings` is registered in `config/settings.php` here; plan 03-09 adds it to `SettingsPage::SETTINGS` and renders the numbering section of the invoicing tab. The peek cases live in `tests/Feature/Operations/NumberingTest.php`; the Phase 2 allocator tests (`tests/Feature/Sequences`, `tests/Concurrency`) are run unchanged as regression checks.

Fictional data only; `scripts/check-sensitive.sh` before every commit (write dates in tests with separators, never as one 8-digit run, because the company-ID rule flags 8-digit numbers); never bypass the hook.
