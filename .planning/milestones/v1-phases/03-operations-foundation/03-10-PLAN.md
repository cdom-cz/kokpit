No content dependency on 03-03 to 03-09; serialized only because every application plan runs Pest against the shared `kokpit_test` database.

Verified in vendor before planning (activitylog 5.1.1): `LogActivityAction::execute()` calls the protected `beforeActivityLogged(Model $activity)` before saving, and the action class is resolved from `activitylog.actions.log_activity`, so one override covers model events and manual `activity()` calls. The package's own `beforeActivityLogged` forwards to the subject; the override must call the parent first.

Source label resolution order (planner decision): explicit `ActivitySource::as()` wrapper, else inside a queue job (depth counter set by queue events), else console when the injected console detector says so, else web. `ActivitySource` is a container singleton with an injected `Closure(): bool` console detector, so tests can simulate a web request (the test runner itself is always a console process). Queue events: `JobProcessing` enters; `JobProcessed` and `JobExceptionOccurred` leave (one of them always follows processing, for success, retry and final failure); the depth never goes below zero.

The probe model lives in `tests/Support/Probes`, creates its table inside the test transaction (pattern of `Canary::createTable()`), merges its morph alias at runtime and restores `MorphMap::MAP` afterwards (pattern of `PackageProbe`).

`OperationsServiceProvider` is created here; plans 03-13, 03-15 and 03-16 add their listeners and bindings to it.

Fictional data only; `scripts/check-sensitive.sh` before every commit; never bypass the hook.
