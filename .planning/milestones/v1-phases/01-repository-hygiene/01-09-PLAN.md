<objective>
Close gap 2 (01-VERIFICATION.md gap 2, review CR-02) by making the documented contract true: "Czech diacritics folded, so a term written with diacritics matches the same text without them". Take the two cheap neighbours in the same code with it: WR-01 (the denylist stage skips the five exempt paths) and WR-08 (silent degrade when the UTF-8 C locale is missing).

Purpose: client names typed without diacritics (slugs, file names, e-mail local parts) are how names usually appear in code and test data, so the denylist (HYG-03) must catch them. Folding is done by a small locale-free awk program applied to both sides, so the behaviour is the same on macOS, on Ubuntu and in a minimal container.

Decision recorded (VERIFICATION offers "fold both sides, or correct the docs to case-insensitive only"): fold. CONTEXT.md D-06 does not lock the matching method beyond "case-insensitive fixed strings", and the phase goal is a guarantee, so the stronger behaviour is implemented. `iconv` transliteration was rejected: glibc and macOS libiconv transliterate differently, so results would differ between a developer machine and CI.

Output: `scripts/lib/fold.awk`, the reworked denylist stage and header text in `scripts/check-sensitive.sh`, and new cases in `scripts/tests/test-denylist.sh`. CONTRIBUTING.md is updated in plan 01-11.

## Flagged assumptions

- **A-HYG-03G (unresolved, edge probe unclassified):** folding covers UTF-8 text. Accented letters stored as UTF-16 or in a legacy single-byte encoding (Windows-1250, ISO-8859-2) are not folded. Only their ASCII letters match. A client name with diacritics inside a UTF-16 or Windows-1250 file is therefore found only through its ASCII letters, which full names with diacritics rarely are. Letters outside U+00C0 to U+017F (Greek, Cyrillic, Vietnamese extended Latin) are compared exactly as written, including their case. The owner should confirm this scope. Widening it later is local to `scripts/lib/fold.awk`.
