Facts verified at planning time on this machine (git 2.56, BWK awk, bash 3.2 and 5.3) and in ubuntu:24.04 (mawk 1.3.4, GNU tr):
- `git diff --cached --text --no-textconv -U0` prints the content of a `-diff`-attributed file, a NUL-containing file and a UTF-16 file; the default diff prints "Binary files ... differ" for all three. A `-text` attribute alone does not hide content.
- macOS `tr` aborts with "Illegal byte sequence" on such bytes unless it runs under `LC_ALL=C`.
- After NUL removal the existing scanner reports a fake key inside a UTF-16 file (BOM included).
- `git hash-object -t tree /dev/null` prints the empty tree id without writing an object; `git diff --cached <that id>` lists every tracked line as added, with real line numbers.
- `git log --all -p --diff-merges=first-parent --format='commit %H'` emits one `commit <hash>` line per commit, including merges, followed by standard hunks; `scripts/lib/diff2tsv.awk` reported a fake added only in a merge commit at the merge's sha7 without any change.
- Scanning 1 MiB of random bytes takes about 0.2 s; random data can produce a rare `email` false positive, which a path-scoped allowlist entry handles (documented in plan 01-11).

Decision recorded (VERIFICATION offers "scan NUL content, or exit 2 on content that cannot be scanned"): scan it. Refusing every NUL-containing file would block every image, font or PDF commit, and refusing only UTF-16 would need per-file detection that the diff stream cannot provide. Reading NUL content twice (as a space and removed) makes every rule shape visible, because all generic rule shapes are ASCII.

Decision recorded for merge commits: `--diff-merges=first-parent` instead of `-m`. Every line of a merge result is either in the first parent (scanned through that parent's history) or appears as added in the first-parent diff, so coverage is complete; `-m` would also re-diff the merge against every other parent, which repeats the whole mainline since the branch point, and its meaning depends on the `log.diffMerges` config.

Staging discipline: stage only the files named in the task's files element (`git add <path>`). Never stage `.planning/` (commit_docs is false) or the untracked `.claude/` framework tree. Every commit goes through the installed lefthook hook; never bypass it.
