Argument parser in `scripts/check-sensitive.sh`:
- Accept `--staged`, `--all`, `--history`, `--help` and `--`. After `--`, everything is a file operand.
- Before `--`, any other argument starting with a dash exits 2 with usage.
- Two mode flags, or a mode flag with file operands, exit 2.

Explicit-file mode:
- Before changing to the repository root, capture `git rev-parse --show-prefix`.
- Convert each relative operand to a repository-relative path by prefixing it. Convert absolute operands inside the physical repository root by stripping the root. Leave absolute operands outside the repository as given.
- Each operand must be a readable regular file; otherwise exit 2.
- Empty files contribute no rows. Files that `grep -Iq .` classifies as binary are skipped with a stderr notice.
- Produce rows with `LC_ALL=C awk` printing FILENAME, FNR and the line, tab-separated. Pass operands as `./`-prefixed relative paths so a leading dash is never read as an option. Strip the `./` prefix from the reported path inside awk.
- The D-05 exclusions and the denylist stage apply as in other modes.

History mode:
- Use `git -c core.quotepath=off log --all -p -U0 --no-color --no-ext-diff --src-prefix=a/ --dst-prefix=b/ --diff-filter=ACMR --format='commit %H'` piped through `diff2tsv.awk` (01-RESEARCH.md line 224).
- Extend `diff2tsv.awk`: only outside hunks (when both hunk counters are zero), a line matching `commit` plus a 40-hex hash sets `sha` to the first 7 characters and resets `path`. When `sha` is non-empty, each emitted row's line field is `line@sha`. Staged and explicit modes never see commit lines, so their output is unchanged.
- Merge commits are not diffed by `git log -p`; this is flagged in 01-05 as assumption A-HYG-05.

## Flagged assumptions

- **A-HYG-03 (unresolved, edge probe unclassified):** Denylist terms are fixed strings matched case-insensitively under `LC_ALL=C.UTF-8`, which folds Czech diacritics. They are not Unicode-normalised: a term typed in NFC does not match content stored in NFD. Very short terms (one or two characters) will produce noise, and the docs recommend terms of at least 3 characters. On systems without a `C.UTF-8` locale, diacritic folding degrades to ASCII-only folding. The owner should confirm these semantics are acceptable for real client names and IDs.
