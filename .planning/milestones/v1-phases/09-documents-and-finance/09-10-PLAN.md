Decisions carried in (locked): D-05 (owner decision, widens Phase 5 A10; reversibility costly: Partner uploads only on tasks and non-internal comments they authored in visible projects of their own client, when creating a task and in their own comments; visible at once, flag not changeable by the Partner; delete only own files while the task is open; Admin may delete anything; Admin bell on every Partner upload, no e-mail), D-06 (same limits, untrusted content), Phase 5 D-15 (Admin notifications for Partner activity are bell only).

Decisions made in this plan (recorded):
- "Task is open" means not archived and status not `done` (owner decision D-19, research A2).
- The Partner description editor keeps `fileAttachments(false)` (D-22); files arrive only through the separate `files` field.
- Tests fill the `files` field per file through Filament's `fillForm` (one upload per file, like the browser); the suite runs the production temporary-disk setting of plan 09-24, under which Livewire refuses a list of files in one call.
- "Authored" for a task means the Partner is its requester (`CreateTask` always makes the Partner the requester); for a comment, its author.
- Upload surfaces are exactly the create-task form (this plan) and the own comment form (plan 09-12); there is no later upload control on an existing task (research A3), although the policy would allow an own open task.
- One bell per submission with the file count (research A18); the notification is a non-queued database notification sent with `notifyNow()` inside the upload transaction, so a rolled-back upload sends nothing (pattern of `ReportExportReadyNotification`). Values are escaped once with `e()`.
- `DocumentNotifier` reads the active Admins as system with the same query as `TaskNotifier::admins()` (copied, because that method is private to the tasks module).
