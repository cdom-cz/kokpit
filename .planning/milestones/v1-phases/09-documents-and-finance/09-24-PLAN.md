Decisions made in this plan (recorded):
- The temporary disk defaults to `s3` explicitly (`env('LIVEWIRE_TEMPORARY_FILE_UPLOAD_DISK', 's3')`) instead of following `FILESYSTEM_DISK`, so the suite (which pins `FILESYSTEM_DISK=local`) and production use the same temporary-upload branch.
- DDEV takes the documented alternative of D-18 (dev and test path in CONTRIBUTING) instead of publishing RustFS through the DDEV router: `.ddev/docker-compose.rustfs.yaml` only exposes 9000 inside the DDEV network, a browser-reachable endpoint would need a second presign endpoint and a CORS setup that the repository cannot verify, and `tests/Feature/Repo/DdevConfigTest.php` pins `web_environment` to an empty list. So `.env.example` (the DDEV template, which already carries `S3_ENDPOINT=http://rustfs:9000`) sets `LIVEWIRE_TEMPORARY_FILE_UPLOAD_DISK=local` with a comment. Production does not read `.env.example`; `ProductionConfigGuard` refuses the value there, so the override fails closed. The browser-to-bucket path is verified by the deploy rehearsal (plan 09-20).
- `phpunit.xml` pins `LIVEWIRE_TEMPORARY_FILE_UPLOAD_DISK` to `s3` (like `FILESYSTEM_DISK` and `MEDIA_DISK`), so a developer's `.env` cannot change what the suite tests. Livewire never contacts the bucket under tests: `FileUploadConfiguration::disk()` returns its faked `tmp-for-tests` disk and `GenerateSignedUploadUrl::forS3()` is swapped for a stub (vendor SupportFileUploads::provide).
- `preview_mimes` is an empty list: Filament previews a chosen file in the browser from the local File object and never asks Livewire for a temporary URL (vendor BaseFileUpload::getUploadedFiles returns null for a `TemporaryUploadedFile`), so nothing is lost; on the bucket `TemporaryUploadedFile::temporaryUrl()` would hand out a presigned read URL valid until the end of the next day. This keeps and tightens the earlier SVG restriction (T-09-67).
- Filament sends every file of a `multiple()` field with its own `$wire.upload('<statePath>.<fileKey>')` (vendor/filament/forms/src/Components/FileUpload.php:991), so Livewire's refusal of a multiple upload on S3 (`S3DoesntSupportMultipleFileUploads`) never hits the forms of this phase; tests mirror that by filling file fields per file (Filament `fillForm` / action data flatten the list and upload each file).
- The presigned PUT lives `max_upload_time` (5 minutes, vendor default kept) and carries `ACL private`; the uploaded object sits under `livewire-tmp/` on the private bucket until the Action of plan 09-02 deletes it after storing.
- No Content-Security-Policy restricts `connect-src` today (grep of app, config and resources found none); CONTRIBUTING notes that a CSP added later must allow the bucket origin for uploads.
