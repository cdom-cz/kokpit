Decisions made in this plan (recorded):
- Translations of the documents module live in a new `lang/cs/documents.php` (precedent `lang/cs/work_report.php`), so documents and finance plans can run in parallel waves without editing one shared file; activity labels stay in `lang/cs/kokpit.php`.
- The Action accepts `Illuminate\Http\UploadedFile` instances (Livewire's `TemporaryUploadedFile` is one); every other value is refused, because a Filament string state is a client-controlled path (research Pattern 3, BaseFileUpload.php:1006-1013).
- One DB transaction per submit; on any exception the objects written in this call are deleted as system before rethrowing (research Pitfall 4).
- Temporary uploads (owner decision D-18, supersedes research A4): production keeps Livewire temporary uploads on the private bucket, because more than one web container serves requests; plan 09-24 configures that, the production guard and the DDEV path. This plan makes the Action independent of where the temporary file lives: one byte-level path for every upload. On the bucket the browser uploads through a presigned PUT and sets the object's Content-Type itself, so the Action never reads `getMimeType()` of a temporary upload or the storage metadata: it copies the bytes (after a size check by the stored size) into a `tempnam(sys_get_temp_dir(), 'kokpit-upload-')` file, runs `finfo` (`FILEINFO_MIME_TYPE`) on the copy, takes `filesize()` of the copy, hands the copy to medialibrary with `addMedia()` (which moves it) and unlinks it in `finally` if it is still there.
- The temporary object is deleted after the DB transaction committed (`TemporaryUploadedFile::delete()`, best effort, failures reported without the file name); a refused or failed submit keeps it so the user can submit again, and leftovers expire through the bucket lifecycle rule (plan 09-24, Livewire skips its own cleanup on S3).
- Tests fill file fields one file at a time, like the browser: Filament sends every file of a `multiple()` field with its own `$wire.upload('<statePath>.<fileKey>')` (vendor/filament/forms/src/Components/FileUpload.php:991), and Livewire's S3 variant refuses a multiple upload call (`S3DoesntSupportMultipleFileUploads`). From plan 09-24 on the suite runs the production temporary-disk setting, so a test that sets an array of files on one property fails loudly.
