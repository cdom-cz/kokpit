Decisions carried in (locked): the Actions are the single place for rules; D-09 (refuse what the UI refuses), D-13 (uuid or key, never a name), OD-1 (owner: `duration_seconds` accepted instead of `ended_at`, mapped in the request layer, Actions and UI unchanged), OD-2 (owner: running UI-timer entries refused like in the UI: PATCH may not set `ended_at` -> 422; DELETE of a running entry -> 409 through `TimeEntry::isRunning()` in the controller), Phase 6 D-03 (billable default) and D-04 (overlaps allowed).

Decisions made in this plan (recorded):
- Request rules check shape only (types, uuid or key syntax, ISO 8601 with offset, exactly one of `ended_at` / `duration_seconds`, the integer bound); every business rule stays in the Actions.
- The interval bound is the column limit 2147483647 seconds (the `integer` generated `duration_seconds`), not a product cap, so the API refuses nothing the UI accepts except what would crash the database (research Pitfall 7, planner's call recorded).
- 409 answers carry a stable machine `code` next to the Czech `message`, so n8n can branch without parsing text; 422 keeps Laravel's `{message, errors}` shape with the Action field keys.
- `DomainException` is caught only around `UpdateTimeEntry` / `DeleteTimeEntry` in the controller (no global handler: the class is too generic).
- `ApiError` lives in `app/Http/Responses/`.

Fictional data only. Run `scripts/check-sensitive.sh` before every commit; never bypass the hook.
