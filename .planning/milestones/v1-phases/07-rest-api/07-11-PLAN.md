Decisions carried in (locked): D-14 (up to 100, partial success, own transaction per item through `CreateTimeEntry`, only failed items listed with index and errors plus counts, replay-safe retry; status codes and layout were Claude's discretion and are confirmed at the 07-02 checkpoint; reversibility costly), D-15, OD-1, OD-3.

Decisions made in this plan (recorded):
- The form request validates only the envelope (`entries` a list of 1..100); each item is validated in the controller with `Validator::make($item, TimeEntryPayload::rules(true))`, so one bad item never fails the whole batch.
- An unexpected exception (not a `ValidationException`) is not swallowed: the request fails with 500, items saved before it stay, and the idempotency key is released; D-15 makes the caller responsible for deduplicating (residual risk documented in the docs intro).
- Item fields are documented with `#[BodyParam('entries[].<field>', ...)]` attributes, because the form request has no per-item rules for Scribe to read.
