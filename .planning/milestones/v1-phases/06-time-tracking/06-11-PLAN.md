Serialized after 06-10.

Decisions carried in (locked): D-05 (daily list with total, weekly grid client / project / task by Monday to Sunday with row and day totals and week switching, durations in hours and minutes, exact seconds stored), D-04 (overlap warning, never blocking). UI-SPEC Surface G and U-18 (grid as a Filament table; the outcome is the contract).

Decisions made in this plan (recorded):
- Research Pattern 9 and Pitfall 9: the day view is a query-backed table (reusing `TimeEntryResource::tableColumns()` without Datum); the week grid is `Table::records()` over arrays from one grouped query plus one name lookup, each row carrying a unique `key`, `paginated(false)`; the footer row of the grid is a `contentFooter` view because array records have no summarizers.
- Every control change navigates to the page URL with the new `view` and `date`, so the table is built once per request.
- Scope: the signed-in user's entries (research A6). An entry spanning midnight belongs to the day it started (research A5); a test pins it, and the owner reviews the rule in the phase summary.
- The elapsed time of a running entry is bound to `TimerClock::now()` (no SQL `now()`), so frozen clocks work in tests.

Fictional data only. Run `scripts/check-sensitive.sh` before every commit; never bypass the hook.
</context>
