# Phase 06 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: Phase 6 ships the time surfaces. All of them are Admin only; a Partner sees no time, rates or prices anywhere and gets no new navigation item, widget, action, notification or string. Surfaces: the top bar timer (compact state plus quick start), the hideable right-hand "Poslední záznamy" side panel with the detailed timer, start and stop affordances on the task page, task list and board cards, the "Časové záznamy" list with billed locking and the bulk billing actions, the entry create, edit and view pages, the "Výkaz" timesheet (day and week), the Admin-only project time overview (PR-05) on the project page, and the forgotten-timer state and bell notification.
>
> Nothing is built yet. Everything below is a target for plans, not a record of built work. Where Phase 5 left a flag that touches this phase, it is restated under "Carried Flags".

Upstream decisions applied (not re-asked): `06-CONTEXT.md` D-01 to D-08 (timer in the top bar, auto-stop on start, client-only start, right-hand side panel, billable default, overlaps allowed with a warning, daily and weekly timesheet, manual billed locking with unlock action, forgotten timer threshold and bell), `02-UI-SPEC.md` (project design system, treated as locked), `05-UI-SPEC.md` (Task surfaces, board card, notification and copywriting conventions, flags F-1 to F-9), `REQUIREMENTS.md` TI-01 to TI-09 and PR-05, and the Czech wording already in `lang/cs/kokpit.php` and `lang/cs/enums.php`.

## Spacing Scale

Inherited from 02 and 05: declared values are multiples of 4, mapped to Filament's Tailwind 4 spacing (1 unit = 4px).

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon-to-text gap in the top bar pill, gap between a badge and its icon, gap between the two text lines of a panel row |
| sm | 8px | Gap between rows in the side panel list, gap between adjacent icon buttons, gap between a day heading and its first row, gap between the start field and the client select |
| md | 16px | Side panel padding, dropdown panel padding, gap between the timer block and the list, vertical gap between stacked controls |
| lg | 24px | Gap between day groups in the side panel, gap between form sections and fields (Filament form grid) |
| xl | 32px | Page content horizontal padding, gap between page header and content |
| 2xl | 48px | Not used by time surfaces |
| 3xl | 64px | Not used by time surfaces |

Component sizes that are not spacing tokens (all multiples of 4): side panel width 320px (20rem); top bar dropdown panel width 320px, never wider than the viewport minus 32px; top bar description truncation width 192px (12rem).

Exceptions and rules:

- Interactive targets keep Filament's stock 36px height. Icon-only buttons added by this phase (stop in the bar, start on a card, panel toggle, panel close) have a hit area of at least 24 x 24px (WCAG 2.2 AA 2.5.8) and at least 8px between two adjacent icon targets. The board card carries up to three icon targets (open, preview, start) in its header: 3 x 24px plus 2 x 8px = 88px, right aligned; the reference text on the left wraps before it overlaps them (carried flag F-3).
- The side panel and the top bar item use only the tokens above, written in rem as 0.25, 0.5, 1, 1.5, 2. No 0.75rem, no fractional value (05 flag F-2 must not be copied).
- Everything else (forms, tables, infolists, relation managers, modals) comes from Filament components with stock spacing and no hand-written spacing.
- Docked side panel breakpoint: from `xl` (1280px) up the panel docks; below `xl` it is an overlay sheet (see Surface B).

## Typography

Inherited from 02 and 05. Four sizes and two weights; application code introduces no other.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (table cells, inputs, panel rows, meta text, helper text, bar elapsed time) | 14px (`text-sm`) | 400 regular | 1.43 (20px) |
| Label (field labels, button text, column titles, panel task title link, day heading, day total, badge text, bar elapsed time while running) | 14px | 600 semibold | 1.43 (20px) |
| Heading (panel heading, dropdown heading, modal and callout headings) | 16px (`text-base`) | 600 semibold | 1.5 (24px) |
| Display (page headings; the large timer readout in the side panel) | 24px below `sm`, 30px from `sm` up for page headings (`text-2xl` / `text-3xl`); the panel readout is fixed at 30px | 600 semibold | 1.33 / 1.2 |

Contract notes:

- Declared sizes: 14, 16, 24, 30. Declared weights: 400, 600. No other size, no 12px, no weight 500 or 700 in application code.
- Secondary text (client name under a task title, day heading date part, meta) uses Filament's gray text colour at 14px, never a smaller size and never an opacity below 0.8.
- The running readout is `H:MM:SS` with `tabular-nums`; list durations are `H:MM` (see Duration display below).
- Czech diacritics render in Inter. Check the weekday names "Úterý", "Čtvrtek", "Pátek", the labels "Nevyfakturováno" and "Zahájení" at the gate.

Duration display (single rule, one helper used by every surface so the formats never drift):

| Context | Format | Example | Rule |
|---------|--------|---------|------|
| Running readout (bar, panel) | `H:MM:SS` | `0:07:42`, `12:05:09` | Hours unbounded, minutes and seconds two digits; ticks every second from the stored start instant on the client |
| Entry view page | `H:MM:SS` | `1:25:30` | Exact stored seconds |
| Lists, panel rows, totals, week grid, stats | `H:MM` | `1:25`, `38:05`, `0:00` | Computed from exact seconds, then truncated to whole minutes (never rounded up); a sum is formed from seconds first and formatted once, so a total may differ by a minute from the sum of the displayed rows. Under one minute shows `0:00` |
| Storage | whole seconds (TI-08) | | Display rules never feed back into stored values |

Dates: `j. n. Y`; date and time `j. n. Y H:i`; times of day `H:i`; instants stored in UTC, shown in `Europe/Prague`; weekday headings Czech (`Po`, `Út`, `St`, `Čt`, `Pá`, `So`, `Ne` in the grid; full names in panel day headings). Empty values show `—`.

Accent reserved for (and nothing else):

1. The single primary submit of each surface and modal: "Uložit záznam" (entry form and "Doplnit záznam" modal), "Spustit časovač" (the start button in the bar dropdown and in the side panel idle block), "Označit jako vyfakturované" (bulk modal submit), and "Nový záznam" (list header action).
2. The active sidebar item (Časové záznamy, Výkaz).
3. Text links: the task key and title in panel rows, task links in tables and the grid, "Zobrazit všechny záznamy", "Načíst starší záznamy", the day heading links in the week grid.
4. The keyboard focus ring on every focusable control including icon buttons.
5. Checked state of the "Fakturovatelné" toggle and the table row checkboxes.
6. The SPA progress bar.

Badges and the running state are never in this list.

Semantic colour map for this phase (every badge and state also carries its text label or an icon, so colour is never the only carrier):

| Meaning | Colour role | Where |
|---------|-------------|-------|

## Access and Visibility Contract

Applies to every new class; the registry and canary tests enforce it.

- Every Resource, Page, Widget, relation manager and cluster declares `#[AccessRule(AdminOnly, reason)]`. Every new model declares `#[NotPartnerScoped]` or the Partner scope per the Phase 2 conventions (time entries are Admin only).
- The timer bar item and the side panel are plain Livewire components outside the Filament registry. They are public endpoints (`/livewire/update`), so each must (a) render nothing for a user who is not the Admin and (b) re-check the Admin on **every** action method (start, stop, complete, toggle panel, load older days), not only on mount. A forged Livewire call by a Partner is refused with 403 and writes nothing.
- A Partner never receives time, rate or price markup in HTML, in Livewire state snapshots, in page props, in notifications, in the bell, in the activity log view or in global search. Time entries are not searchable.
- The canary harness gets one time-entry fixture per client; the route walk and a rendered-HTML check prove a Partner page contains none of the time strings below (Copywriting Contract, "Never on a Partner surface").

## Screens and Interaction Contract

### Visual anchors

| Screen | Primary anchor | Why |
|--------|----------------|-----|
| Top bar timer (A) | The elapsed time while running; the "Spustit časovač" button while idle | The only state the user needs at a glance on every page; stop is one click away |
| Side panel (B) | The 30px timer readout at the top of the panel, with its start or stop button | The panel exists for the running timer; the day list is secondary |
| Time entries list (D) | The table, led by the Datum and Od–Do columns; "Nový záznam" is the only accent element above it | The list is for finding and correcting entries |
| Entry form (E) | The "Záznam" section (Klient, then Projekt and Úkol) with "Uložit záznam" as the single accent button | Context before time; billing is last |
| Timesheet (G) | The totals: the day total line in the day view, the Celkem row and column in the week grid | The timesheet answers "how much, when" |
| Project time overview (H) | The four stats row (Odhad, Odpracováno, Vyfakturováno, Nevyfakturováno) | Estimate against actual, billed against unbilled is the whole question of PR-05 |

### Surface A: Top bar timer — new (TI-01, TI-07, TI-09; D-01, D-02, D-07, D-08)

Position: the persisted end region of the top bar, directly before the bell. Admin only. Contains, left to right: the timer item, then the panel toggle icon button.

States:

1. **Idle.** A gray button with `OutlinedPlay` and the label "Spustit časovač" (label hidden below `sm`, icon only with the label as accessible name and tooltip). Click opens a dropdown panel (`x-filament::dropdown`, 320px): heading "Spustit časovač"; native select "Klient" (required; option groups "Naposledy použití" with up to five clients ordered by their most recent entry, then "Všichni klienti" alphabetical in Czech collation; archived clients are never offered; the client of the user's most recent entry is preselected); input "Popis" (optional, placeholder "Na čem pracujete?"); primary button "Spustit časovač". Enter in the Popis field submits. Starting needs only a client (D-02, TI-03). Zero active clients: the dropdown shows only the text "Nejdřív vytvořte klienta, ke kterému se bude čas zapisovat." and a text link "Klienti"; there is no start button.
2. **Running.** One pill: `OutlinedClock`, the elapsed time `H:MM:SS` (semibold, tabular-nums), from `lg` up the description cut to 192px with an ellipsis (the full text is the tooltip), then the stop icon button (`OutlinedStop`, accessible name and tooltip "Zastavit časovač"). The whole pill is in the `warning` colour. Clicking the elapsed region opens a dropdown with the detail of the running entry: heading `KEY-N · title` as a link (or the client name when there is no task), lines Klient and Začátek (`H:i`, plus the date if it is not today), the full description, and two actions "Doplnit záznam" (opens the modal of Surface B) and "Zastavit časovač". Stopping is never behind a confirmation (D-02 spirit; stopping keeps the entry).
3. **Running too long** (elapsed ≥ `kokpit.time.long_running_hours`, default 12 h, D-07). The pill turns `danger`, the clock icon becomes `OutlinedExclamationTriangle`, the tooltip reads "Časovač běží déle než :hours h. Zkontrolujte, jestli ho nemáte zastavit." The timer is never stopped automatically. The state is computed from the stored start instant on every render and every poll, so it appears without a page load.

Behaviour rules:

- Clock: Alpine ticks once per second from the stored start instant (ISO, UTC); the server value is re-read on every Livewire refresh, on the events `timer-started`, `timer-stopped`, `time-entry-saved`, and by a 60 s `wire:poll.visible`. The readout has `role="timer"` and `aria-live="off"`; start and stop are announced by the toast.
- Starting while another timer runs stops it and keeps its entry in the same transaction (D-02). The toast then reads "Časovač byl spuštěn" with the body "Předchozí záznam (:duration) byl zastaven a uložen." There is no confirmation dialog.
- Only one running timer ever exists per user. If two starts race, the loser sees the toast "Časovač se nepodařilo spustit, protože se současně změnil jiný. Zkuste to znovu." and the bar re-reads the state.
- A stop issued from a stale view (nothing runs any more) shows the info toast "Žádný časovač neběží." and the bar refreshes.
- Below `sm` the pill drops the description and the label; the elapsed time and the stop button stay.

### Surface B: Right-hand side panel "Poslední záznamy" — new (D-08)

- Placement and size: rendered at `LAYOUT_END` as an `<aside aria-label="Poslední záznamy">`, 320px wide, full height below the top bar (sticky, scrolls inside itself), background Secondary, 1px ring on its left edge. From `xl` up it is docked and shrinks the main content; below `xl` it is an overlay sheet on the right edge (width 320px, at most 100vw), closed by the toggle, the close button, the Esc key or a click on the backdrop. Admin only. No custom look.
- Toggle: the icon button `OutlinedBars3BottomRight` in the bar (accessible name and tooltip "Zobrazit poslední záznamy" or "Skrýt poslední záznamy" according to state) and an `OutlinedChevronDoubleRight` close button in the panel header with the name "Skrýt poslední záznamy". The choice is stored **on the server per user** (not in the browser) and applied in the first render so there is no flash. Default for a user who never chose: open from `xl` up, closed below. The overlay form on small screens always starts closed and its state is not remembered.
- Header: heading "Poslední záznamy" (16px/600) and the close button.
- **Timer block (top of the panel).**
  - Idle: the same two inputs as the bar dropdown (native select "Klient" with the same ordering and preselection, input "Popis" with the placeholder "Na čem pracujete?"), the readout `0:00:00` at 30px/600 in gray, and the primary button "Spustit časovač" (`OutlinedPlay`). D-08's `00:00` is read as zero in the same format as the running readout.
  - Running: line 1 the task key and title as a link, or the client name when there is no task; line 2 the description (up to two lines, full text as tooltip) or `—`; the readout `H:MM:SS` at 30px/600 in the running colour (`warning`, or `danger` when too long); the button "Zastavit časovač" (`OutlinedStop`, same colour, full width); a gray icon button `OutlinedPencilSquare` named "Doplnit záznam". When the timer is too long, a `danger` callout sits above the readout: heading "Časovač běží příliš dlouho", body "Běží déle než :hours h. Zkontrolujte, jestli ho nemáte zastavit."
  - "Doplnit záznam" opens a modal "Doplnit běžící záznam" with the fields Klient, Projekt, Úkol, Popis, Začátek and the toggle Fakturovatelné, using the same cascade, consistency and overlap rules as Surface E, and the submit "Uložit záznam". Project, task and description are the ones that D-02 lets the user fill in later.
  - There is no pause (TI-07): only start and stop.
- **Entry list (below the timer block).** Entries grouped by day, newest day first, newest entry first within a day. The running entry is shown only in the timer block, not repeated here, and the day totals count finished entries only (so the "Dnes" total changes when the timer stops).
  - Day heading: "Dnes", otherwise the full Czech weekday and date, for example "Pondělí 5. 10." (with the year when it is not the current year). The day total `H:MM` sits on the right, semibold.
  - Row: line 1 the task key and title as a link to the task page (`KEY-N · title`, one line, ellipsis), or the client name when the entry has no task; line 2 the client name in gray (when line 1 is the client name, line 2 is the project name, else the start of the description, else nothing); the duration `H:MM` on the right. The row (outside the link) opens the entry's view page. Billed state is not marked here (D-08: no billed check marks); the view page shows the lock.
  - Loading: the most recent 7 days that contain finished entries; a gray text button "Načíst starší záznamy" appends the next 7 days that contain entries and disappears when none are left. No infinite scroll.
  - Footer: the text link "Zobrazit všechny záznamy" to the entries list.
  - Empty: the empty state in the Copywriting Contract. It contains no "Log time" link (D-08).
- Refresh: the panel re-renders on the events `timer-started`, `timer-stopped`, `time-entry-saved`, `time-entry-deleted`, and by a 60 s `wire:poll.visible`. Panel timer and bar timer are two views of the same single running entry.

### Surface C: Start and stop affordances on tasks — new (TI-01)

At most two clicks; every task affordance below is exactly one.

- Task page and task edit page header: action "Spustit časovač" (gray, `OutlinedPlay`). While this task is the running one the same slot reads "Zastavit časovač" (`warning`, `OutlinedStop`). Hidden for an archived task. The new entry gets the task's project and client, an empty description, and `billable` per Surface E.
- Task list (Admin): a row action icon button "Spustit časovač" (tooltip, `OutlinedPlay`), outside any action group so it stays one click; it becomes the stop icon for the running task. Not on archived rows.
- Board card (global and project board): an icon button "Spustit časovač" in the card header cluster, inside the card's `wire:sort:ignore` wrapper, with a 24 x 24px minimum hit area and 8px from its neighbours (carried flag F-3); it becomes the stop icon while the card's task runs. It never carries `wire:navigate` and never starts a drag.
- Starting from any of these auto-stops a running timer (D-02) and shows the toast of Surface A.

### Surface E: Entry create, edit and view pages — new (TI-02, TI-03, TI-04, TI-07, TI-08; D-03, D-04)

1. ### Surface F: Bulk billing actions — new (TI-05; D-06)

### Surface I: Forgotten-timer notification — new (TI-09; D-07)

- A scheduled job (one `KokpitJob`, idempotent) finds running entries past the threshold that were not yet announced and creates **one** database (bell) notification per running entry, addressed to the entry's owner, who is the Admin. It is not repeated while the entry keeps running, and it sends no e-mail (e-mail is deferred). It never stops the timer.
- Bell entry: title "Časovač běží příliš dlouho", body "Časovač u klienta :client běží už :duration. Zkontrolujte ho a případně zastavte.", one action button "Otevřít záznam" to the entry view page. The body contains the client name and the duration only: no description, no task title, no amount. Every value is escaped once, like the 05-19 task notifications.
- The profile page gets no new switch for this notification (the bell always delivers it; the e-mail channel is a deferred idea). The profile notification section of 05 is unchanged.
- The threshold is `kokpit.time.long_running_hours` in `config/kokpit.php` (default 12). The bar pill, the panel callout and the notification all read the same value.

### Cross-cutting interaction rules (this phase)

- Keyboard: every control works by keyboard alone with the accent focus ring: the bar dropdown (Enter submits, Esc closes), the panel (the close button, rows, links), the forms, the bulk modals. The timer start and stop need no pointer.
- A hidden action is not rendered, not disabled, except the billed-row lock icon, which explains why edit and delete are absent.
- Destructive or hard-to-undo actions use a confirmation modal with a question heading, a one-sentence consequence and a submit label equal to the action name. Starting and stopping a timer are never confirmed.
- Time entries never show a currency amount in this phase.
- Enum labels come from `lang/cs/enums.php`; new labels go to `lang/cs/kokpit.php` under `kokpit.time.*` and enums under `enums.time_billing_state.*`.
