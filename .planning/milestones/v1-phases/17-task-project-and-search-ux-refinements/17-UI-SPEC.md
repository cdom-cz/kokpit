# Phase 17 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds no new screens and no new design language. It is ten refinements inside an existing Filament 5 admin panel (plus the Partner panel for rich text, files and the project picker). The contract therefore says, for each refinement, which existing Filament primitive to use, where it sits, how it behaves in every state, and what the Czech copy is. Everything not mentioned here keeps the current look.

Sources: D-01..D-12 and the plan-phase clarifications from 17-CONTEXT.md; 17-RESEARCH.md for stack and seams; the live code (`resources/views/livewire/signal/day.blade.php`, `TaskResource::timerAction()`, `ViewTask`, `ViewProject`) for existing conventions.

Amended at plan-phase on 2026-10-29 to match the plans (popup-blocked toast removed, rich-text links keep their forced new tab, reused copy keys); every change is listed under "Plan-phase Amendments" at the end.

## Design System

| Property | Value |

Panel colors: `primary` = Amber (set in `AdminPanelProvider`); `gray`, `danger`, `warning`, `success`, `info` are Filament defaults.

## Spacing Scale

Declared values (multiples of 4 only; Filament and Tailwind use a 4px base unit, and inline Blade uses the rem equivalent):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (0.25rem) | Gap between adjacent icon buttons in a Signal row; gap inside a suggestion item between code and project |
| sm | 8px (0.5rem) | Row inner gap (existing), padding inside a suggestion item, gap between a Section's header actions |
| md | 16px (1rem) | Default gap between form fields and Signal groups (existing), lightbox body padding |
| lg | 24px (1.5rem) | Section padding (Filament default), modal body padding |
| xl | 32px (2rem) | Minimum interactive hit size of `icon-button size="sm"` |
| 2xl | 48px (3rem) | Not used in this phase |
| 3xl | 64px (4rem) | Not used in this phase |

Exceptions:
- The existing Signal row uses `padding: 0.375rem 0.5rem` (6px vertical). Leave it unchanged; do not copy 6px into any new element.
- The type-ahead suggestion rows have a minimum height of 40px (touch target above the 32px icon-button size), which is not a scale token; it is a size, not a spacing value.
- Lightbox image: `max-height: 80vh` (viewport-relative, not a spacing token).

## Typography

Phase 17 introduces no new text styles. It reuses the Filament scale that the panel already renders. Declared for the new elements:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (inputs, suggestion title, signal title, prose paragraphs) | 14px (`text-sm`) | 400 | 1.5 |
| Label / caption (suggestion project name, group labels, helper text) | 12px (`text-xs`) | 400 | 1.5 |
| Heading (modal headings, e.g. "Přidat čas k úkolu"; the lightbox file name is this role and only this role) | 16px (`text-base`) | 600 | 1.2 |
| Display (page title, unchanged, inherited) | 24px (`text-2xl`) | 600 | 1.2 |

Weights: exactly two are introduced by this phase, 400 (regular) and 600 (semibold). The suggestion item's task code is 600 at 12px. Filament-owned components (form labels, buttons) keep their built-in weights; do not override them.

Rich text (`fi-prose`) heading levels inside a description follow the Filament prose stylesheet (`public/css/filament/filament/app.css`); do not restyle them. These rendered sizes (h1–h6) are inherited from Filament and are explicitly outside the 4-size / 2-weight contract above; no new heading style is introduced by this phase. Do not add a custom font size for descriptions: prose body stays 14px.

## Interaction Contracts

### 1. Checklist card full width (P17-1)
- The "Kontrolní seznam" `Section` on the task form spans both grid columns (`columnSpanFull()`), like `main` and the ViewTask checklist section. Position in the form order is unchanged. Repeater schema, labels and the "Přidat položku" button are unchanged; in the wider card the item text input takes all remaining width and the "Hotovo" toggle stays at the row end.
- At narrow viewport widths the form is single-column and the card is unchanged.

### 2. Rich text read-only (P17-2, D-09)
- Wrap every read-only rich-text output in the `fi-prose` class: the Admin and Partner description `TextEntry` (`->prose()`), the board task-preview partial (`<div class="fi-prose">`, keeps `overflow-x: auto; overflow-wrap: anywhere`), and comments (already `fi-prose`, verify unchanged).
- Rendered formatting that must be visible: bold, italic, underline, strike, bullet and numbered lists with markers and indentation, headings, blockquote with a left border, links (primary color; they keep the `target="_blank"` and `rel="noopener noreferrer nofollow"` that `RichText::render()` forces, so they open in a new tab), inline code and code blocks, tables with borders (horizontally scrollable, never widening the page).
- Keep `RichText::render()` as the only sanitiser. No `style`, `class` or data attributes pass through. Images are not part of rich text in this phase.
- Light and dark themes both verified; prose uses Filament's own theme-aware colors, no overrides.
- E-mails and PDFs are untouched.

### 3. New task from project detail (P17-3, D-07, D-11)
- Header action on the project view, gray, icon `Heroicon::OutlinedPlus`, label "Nový úkol". Position: directly after "Nástěnka" (board) and before `EditAction`, so Edit and Archive keep their right-hand cluster.
- Opens the existing quick-create modal. The "Projekt" select is shown, pre-filled with the current project and disabled, with the helper "Projekt je daný detailem projektu.". The client is not asked. The only editable field remains the title; submit "Vytvořit úkol" redirects to the task edit page, as today.
- Not offered (hidden, not disabled) when the project is Dokončeno (`done`) or archived.
- Project pickers on the task create forms (Admin quick-create and the Partner create form) list only projects that are not Dokončeno. The project list filter on the task list keeps all projects.

### 4. Add time from a task (P17-5, D-06)
- Header action on the task view, gray, icon `Heroicon::OutlinedClock`, label "Přidat čas". Hidden for archived tasks and for users who cannot create time entries.
- Modal uses the standard time-entry field set. Client, Projekt and Úkol are shown pre-filled and disabled with the helper "Klient, projekt a úkol jsou dané úkolem." Fillable: start, end (both required), description, billable (default from the existing billable default for the task).
- Start and end default to now minus one hour and now, in the panel timezone (so the common case is one click on "Uložit záznam"); both stay editable.
- On success: close the modal, success toast "Záznam byl uložen", refresh the page's worked-time figures and the timer side panel. On a domain rejection: modal stays open, danger toast "Záznam se nepodařilo uložit" with the message (locked fields cannot carry inline errors); field errors on start/end are shown inline as usual.
- No new rules: billed-immutability, overlap and duration limits are enforced by the existing Action.

### 5. Hide from kanban board (P17-6, D-04, D-05)
- A `Checkbox` "Skrýt na nástěnce" with helper text, at the end of the "Stav" section of the task edit form (next to status and priority, because it controls where the task shows). Default unchecked (shown). Admin only: the Partner panel has no task edit form and no board, so nothing is rendered there.
- No visual badge on lists or the task view for a hidden task in this phase (D-04: lists and detail unaffected).
- A hidden task is offered in the Signal type-ahead (D-03).

### 6. Search ordering (P17-4, D-10)
- No visual change. Within each global-search category (tasks, projects) results with a state other than Dokončeno come first, then Dokončeno ones. Category order and result row display (title, details, URL) are unchanged. No separator, label or badge is added between the two groups.

### 7. Project status change (P17-10, D-12)
- Header action on the project view, gray, icon `Heroicon::OutlinedArrowsRightLeft`, label "Změnit stav", mirroring `ViewTask::changeStatus`. Modal heading "Změnit stav projektu"; one required, non-native `Select` of the six project states pre-filled with the current one; submit "Uložit stav". Success toast "Stav projektu byl změněn". Hidden for archived projects and for users without edit permission.
- Header action order on the project view: Nástěnka, Nový úkol, Změnit stav, Upravit, Archivovat / Obnovit.

### 8. Signal: pick a task by type-ahead (P17-7, D-01..D-03)

Layout (the add form of `signal/day.blade.php`; edit mode is unchanged and has no type-ahead):
- The existing input keeps its place and width (`flex: 1 1 14rem`). Its wrapper gets `position: relative` so the suggestion list anchors to it.
- **Idle / free text:** plain input, no prefix, no suffix. Typing fewer than 2 characters shows no list.
- **Searching:** from 2 characters, debounce 250 ms; a `x-filament::loading-indicator` (16px) shows in the suffix slot while the request is pending. Matches task code, task name and project (name or key); only unfinished, non-archived tasks are offered (archived and done tasks never appear), at most 10.
- **Suggestion list:** an absolutely positioned panel directly under the input wrapper (top offset 4px), same width as the wrapper, `max-height` showing all 10 rows (10 x 40px) with vertical scroll beyond, rounded to match the input, 1px border in the Signal row border color, surface color per Color section, `z-index` above the Signal rows but below modals. Each row is a `<button type="button">` 40px high, 8px horizontal padding: first line the task name (14px/400, single line, ellipsis), second line the task code (12px/600) followed by " · " and the project name (12px/400, muted at 70% opacity). The keyboard-highlighted row and the hovered row use the gray-100/gray-800 hover surface; the keyboard-active row also gets the primary focus ring.
- **Keyboard:** ArrowDown/ArrowUp move the active row; Enter picks the active row (when a row is active), otherwise Enter submits the form as free text; Escape closes the list without clearing the text; Tab closes the list and moves on. ARIA: input `role="combobox"` with `aria-expanded`, `aria-controls` and `aria-activedescendant`; list `role="listbox"`; rows `role="option"`.
- **Picked:** the input shows the composed text `{PROJECT}: {task name} [{task code}]` (project name, server-built, truncated to 255 characters), is `readonly`, shows a `heroicon-m-link` prefix icon (gray, 16px) to signal the link, and a gray `x-filament::icon-button` cross (`heroicon-m-x-mark`, `size="sm"`, label "Zrušit výběr úkolu") in the suffix slot. The list closes. The category select and the "Přidat" button are unchanged.
- **Cross:** clears the pick and the text, restores a writable empty input, returns focus to it. Free text can be typed immediately. No confirmation.
- **Submit:** with a pick, the signal is saved linked; without, as plain text. After success the input resets to idle.
- **No-match:** when the query yields no tasks, the list simply closes (no "nothing found" row); the typed text remains usable as free text.

### 9. Signal listing: linked task (P17-7, D-01, D-02)
- Row structure (left to right): drag handle, done circle, title (plain text, never a link), recurring icon, then a right-hand cluster of 4px-spaced `icon-button size="sm"` controls: **timer**, **open task**, edit, delete.
- **Timer control:** `heroicon-m-play` gray when idle, `heroicon-m-stop` with `color="warning"` when this task is the user's running one; `aria-pressed` reflects running. Tooltip and label "Spustit časovač" / "Zastavit časovač". It is the shared task timer: starting it stops a timer running elsewhere with the same toast the timer bar shows. It is hidden (not disabled) when the linked task is completed or archived. State refreshes on `timer-started` / `timer-stopped` / `time-entry-saved` / `time-entry-deleted`, so today and tomorrow panels and the top bar never disagree.
- **Open-task control:** an `<a>` styled as a gray `icon-button size="sm"` with `heroicon-m-arrow-top-right-on-square`, label "Otevřít úkol", opening the task detail in the same tab (SPA navigation). It stays while the task exists, including when completed or archived. If the link was cleared (task deleted), neither control renders and the row looks like any plain signal.
- The timer and open controls are independent of the lock state of the day: they do not edit the signal, so they render even on a locked past day (inside their own `wire:sort:ignore` container). Edit and delete keep their existing `can_edit` condition.
- Done signals (strike-through, 60% opacity) keep the controls at full opacity so they remain usable.
- Narrow widths: the title wraps (`overflow-wrap: anywhere`, existing), the control cluster does not shrink or wrap below the title.

### 10. Files: lightbox and new window (P17-8, D-08)
- The explicit "Zobrazit" action stays in every file list and in comment attachments, in both panels. Its behaviour depends on the file type:
  - **Image** (`image/png`, `image/jpeg`, `image/gif`, `image/webp`; never SVG): opens a Filament modal, width 5xl, heading = file name (16px/600, ellipsis, with the standard close X), body = the image centered, `max-width: 100%`, `max-height: 80vh`, `object-fit: contain`, `alt` = file name, 16px body padding, no submit button, footer with one gray "Zavřít" button. ESC, close X and backdrop click close it. No previous/next, no zoom, no thumbnails strip. While the image loads, show a centered `loading-indicator`; if it errors, replace it with the "Náhled se nepodařilo načíst..." message. The image URL is minted when the modal renders and never appears in list HTML.
  - **Non-image inline file** (PDF): "Zobrazit" is a real link (`<a href target="_blank">`, no opener) that opens the file in a new browser tab; its signed, user-bound link is rendered with the row (owner decision "Signed PDF link exception", 17-CONTEXT.md). A real link click is not intercepted by popup blockers, so there is no blocked state and no toast. A page left open longer than the 120 s link lifetime opens a 403 in the new tab until the list renders again (accepted by the owner). The current page stays where it is.
  - **Every other type** (outside the inline allowlist, SVG included): no "Zobrazit"; the existing download action stays, and a download is an attachment that never replaces the page.
- The Partner panel shows the same behaviour only for files the Partner may already see; no new affordance appears for hidden files.

## Accessibility Notes

- Every icon-only control (timer, open task, clear pick, lightbox close) has a tooltip and an identical `aria-label`.
- The timer control exposes `aria-pressed`; the type-ahead exposes the combobox/listbox roles listed above.
- Hit targets: icon buttons use Filament `size="sm"` (32px); suggestion rows are 40px high.
- Focus order in the Signal add form: input, (clear cross when picked), category select, "Přidat". After picking a task focus returns to the input; after clearing, focus is in the input.
- The lightbox traps focus and restores it to the "Zobrazit" trigger on close (Filament modal default).
- Color is never the only signal: the running timer changes icon (play to stop) as well as color; the link state adds an icon.
