- R-17-04-3 (query class): new `App\Domain\Signal\Queries\LinkableTasks`, `final class`, the one place that decides which tasks a signal may link (D-03) and how the text reads (D-01):
  `public const int LIMIT = 10;` and `public const int MIN_TERM = 2;`;
  `search(string $term): array` returning `list<array{id: string, reference: string, title: string, project: string}>`: `[]` when `mb_strlen(trim($term)) < self::MIN_TERM`; otherwise the linkable query narrowed by a nested OR of `tasks.reference`, `tasks.title` and, through `whereHas('project', ...)`, `projects.key` and `projects.name`, each compared with `'ilike'` to the bound value `'%'.addcslashes(trim($term), '\\%_').'%'` (a typed `%` or `_` is a plain character); eager-loads `project` with `id`, `key`, `name`; ordered by the project key (a `Project::query()->select('projects.key')->whereColumn('projects.id', 'tasks.project_id')` subquery), then `tasks.number`, then `tasks.id`; limited to `LIMIT`; scalars only;
  `find(string $id): ?Task`: null unless `Str::isUuid($id)`; otherwise the linkable query `->with('project')->whereKey($id)->first()`;
  `private static function linkable(): Builder` (Builder of Task): `Task::query()` with the soft-delete scope on (archived tasks never appear), `->where('tasks.status', '!=', ProjectStatus::Done->value)`, `->whereIn('tasks.project_id', Project::query()->selectable()->select('projects.id'))`; `hidden_on_board` is deliberately not filtered (D-03);
  `public static function label(Task $task): string`: `{project name}: {task title} [{reference}]`; when longer than `SignalRules::MAX_TITLE_LENGTH`, the task title is shortened with a trailing "…" so the prefix and the `[reference]` suffix fit, and the whole string is cut to the limit with `mb_substr` as the last resort. Its only caller is `SignalDay::pickTask()`, once per pick: the label is the D-01 snapshot taken at pick time. The class docblock names D-01, D-03, what "unfinished" means and that the label is composed at pick time, never at save.
