UI-SPEC Surface B1 to B3 and B5, U-2 (split adds rows below each task), U-4 (the Částka columns cover all billable hourly entries of a row, billed and unbilled), Pitfall 11 (no Node build: Filament components and inline styles only; Filament's `ComponentAttributeBag::grid()` produces `fi-grid` classes that are in the precompiled CSS).

Decisions made in this plan (recorded):
- Amounts are computed per entry and rounded once, then summed (research Pattern 5).
- The effective type and rate are resolved set-based in the reader's SQL (`COALESCE` over task, parent task, project, client; zero is a value, only null defers); both minor units and currency come from the same level; `TimeEntryRateResolver` and `TaskBillingResolver` stay the specification and the parity test pins the SQL to them. The global default never applies in SQL because every client stores a rate.
- An entry carries an amount only when its own billable flag is set, its effective type is not `fixed_price` (whether from the project, a task or a parent override; assumption A7: task-level fixed prices show hours only) and it has a rate.
- Billed entries are priced with the current rate until Phase 10 snapshots them, and the page says so (research Pitfall 7).
- The reader refuses any caller that is neither the Admin nor a system run (its joins bypass the Partner scope of the joined tables). Archived clients, projects and tasks stay in the report. Entries of every user are included (the "Podle uživatelů" split of D-06 needs them); dashboard hours of plan 08-15 are the signed-in Admin's own (UI-SPEC U-8).
- Filters live in the URL and are re-validated on every request like `TimesheetPage`; no maximum range is imposed (UI-SPEC defines no range limit; the row cap of plan 08-14 bounds the HTML).
- `split` (none, day, user) is parsed and validated here so the filter contract is complete; the "Rozpad" control and the child rows are plan 08-14.
- The whole `kokpit.report.*` copy (including the effective-rate block, the row-cap notice, the export menu labels and the PDF error toast used by plans 08-14, 08-16, 08-19 and 08-21) lands here, because other areas edit `lang/cs/kokpit.php` in wave 5; UI-SPEC requires that namespace. The row cap is `config('kokpit.report.max_rendered_rows')` = 1000 (UI-SPEC U-16).

Fictional data only: clients, rates and CNB rates in tests are invented. Run `scripts/check-sensitive.sh` before every commit; never bypass the hook.
