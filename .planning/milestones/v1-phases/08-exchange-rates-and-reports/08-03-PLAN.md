Every dependency must be AGPL-3.0-compatible (CLAUDE.md, PROJECT.md), so compatibility comes first, tooling second. `composer licenses` reports `dompdf/dompdf` as `LGPL-2.1`, an id SPDX deprecated and defines as the "only" form, so the ruling is on the stricter reading. With -or-later the library may be taken under LGPL-3.0, which combines with GPL-3.0 and, through section 13 of GPL-3.0 and AGPL-3.0, with an AGPL-3.0 work. With -only that route is closed; what remains is that LGPL-2.1 lets a work that only uses the library carry its own licence while the library's terms are honoured (library source and its modifications under LGPL, the user can replace the library; section 6), and section 3 lets a copy of the library be converted to GPL version 2 or a later GPL version, which reaches GPL-3.0 and hence the AGPL-3.0 combination. Kokpit uses Dompdf unmodified as a Composer dependency distributed as source, so the library stays separately replaceable. Planner's screen: both readings look compatible, the -only one through LGPL-2.1 sections 3 and 6; `scripts/check-licenses.php` already allows both `LGPL-2.1-only` and `LGPL-2.1-or-later`. Nothing is installed before this answer. Undo cost: a release published with the dependency cannot be recalled, so the ruling binds every later release (and Phase 10 reuses the engine).
