Rulings made in this plan (recorded):
- R11-14-1 (UI-SPEC Surface K, the `UnsentInvoiceEmailsIndicator` analog): `UnprocessedWebhooksIndicator` reads, as system, one aggregate over `webhook_calls` with name `stripe` and `processed_at` null: the count, the count with `failed_at`, and the oldest `created_at`. Zero: Ok, value "0". Any failed: Error. Oldest older than `kokpit.health.unprocessed_webhook_warning_after` (900 s, `max(1, ...)`): Warning. Otherwise Ok with the count and the waiting detail. The age is a Czech relative duration as the other indicators format it. No payload, header or exception text is read.
- R11-14-2 (U-14): `HealthSlot::Stripe = 'stripe'` directly after `UnprocessedWebhooks`, label "Stripe" in `lang/cs/enums.php`; `StripeConfigIndicator` reads `StripeConfig::hasSecretKey()`, `hasWebhookSecret()` and, as system, `PaymentSettings::online_payments_enabled`, and answers per the UI-SPEC table; `HealthRegistryTest` lists seven slots.
- R11-14-3 (D-17, "Don't Hand-Roll"): `WebhookCall::prunable()` returns the rows with name `stripe`, `processed_at` not null, `failed_at` null and `processed_at` older than `config('webhook-client.delete_after_days')` days (90). `PruneProcessedWebhookCalls extends KokpitJob` (`#[Idempotent(how: 'deletes only processed events past the retention; a second run finds nothing more to delete')]`) calls `(new WebhookCall)->pruneAll()` in the system context of the job middleware (the model is Partner-scoped, so a console command outside the system context would see nothing). Scheduled `Schedule::job(new PruneProcessedWebhookCalls)->daily()->name('kokpit-webhook-prune')->onOneServer()`.
