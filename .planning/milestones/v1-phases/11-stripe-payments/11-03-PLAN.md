Rulings made in this plan (recorded):
- R11-03-1 (research A8, D-06): the client flag is the default of the draft switch; the switch itself is the third operand. Effective value at issue = kind carries payment AND draft switch AND `PaymentSettings::online_payments_enabled` AND `StripeConfig::isConfigured()` (UI-SPEC U-4). An Admin override to on for a client that is off therefore takes effect; this reading is recorded as an assumption for the owner.
- R11-03-2 (Pattern 1, A5, D-01): `invoice_admin` gains `card_payment_enabled boolean NOT NULL DEFAULT false` and `pay_token varchar(32) NULL` with `UNIQUE (pay_token)` (`invoice_admin_pay_token_unique`), `invoice_admin_pay_token_check CHECK (pay_token IS NULL OR (card_payment_enabled AND pay_token ~ '^[A-Za-z0-9]{32}$'))`. The existing child guard already freezes every column but the note, its marker, the PDF link and updated_at once the invoice is issued, so both new columns are frozen with no trigger change. No expiry (research Open Question 5, adopted): the page answers "paid" or "cancelled" for old documents indefinitely.
- R11-03-3 (Pitfall 9, UI-SPEC Surface B): `PayUrl::for(string $token)` returns `rtrim(config('app.url'), '/').'/pay/'.$token`; the 32-character token keeps the URL at 37 characters plus the host, inside the 80-character cap of Surface B for any host up to 43 characters. The path `/pay/{token}` is fixed here; plan 11-08 registers the route at this path.
- R11-03-4: `PayUrl::forInvoice(Invoice $invoice): ?string` reads the token of an invoice its caller has already loaded through the caller's own scope, as system (the `InvoicePdfController` precedent), and returns null when there is none; it never decides access.
- R11-03-5: `UpdateDraft` accepts data key `card_payment_enabled` (a strict boolean) on an invoice or proforma draft and writes the draft's `invoice_admin` row under the draft lock (creating it when missing, as `UpdateInternalNote` does); on a credit-note draft or with a non-boolean it is refused with `invoices.errors.card_payment_invalid` under `card_payment_enabled`. `CreateDraft` writes the client's `online_payment_enabled` for an invoice or proforma, false for a credit note.
- R11-03-6 (T-11-09): `card_payment_enabled` joins the activity allowlist of `InvoiceAdmin`; `pay_token` does not (a bearer value; the sensitive-name rule of plan 03-11 refuses "token" names anyway).
