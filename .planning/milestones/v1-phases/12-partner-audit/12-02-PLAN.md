Rulings made in this plan (recorded):
- R-12-02-1 (status set): a refusal is status 401, status 403, or a redirection (3xx) whose Location header ends with `/admin/login`. Everything else fails, explicitly 200, 419 and 500. The request is `$this->call(RouteInventory::method($route), RouteInventory::path($route))` with no headers, after `Auth::forgetGuards()` (research Pitfall 9), never `->json(...)`, which hides defect 1 (research Pitfall 1).
- R-12-02-2 (defect 1 fix, research A1): in `bootstrap/app.php` inside `withMiddleware`, `$middleware->redirectGuestsTo(...)` with a closure returning `route('filament.admin.auth.login')`, next to a comment: Kokpit has no route named `login`; the framework default callback calls `route('login')` and turns every unauthenticated non-JSON request behind `auth` into a 500; for `api/*` the existing `shouldRenderJsonWhen` makes the handler answer JSON 401. If the regression test still sees 500, the closure returns null for a request matching `api/*` and the login route otherwise; record which variant was needed in the SUMMARY.
- R-12-02-3 (defect 2 fix, research A2 and Open Question 5): in `AccessServiceProvider::boot()` two explicit binders, `Route::bind('export', ...)` and `Route::bind('import', ...)`, each a static closure that calls `abort(404)`, under a comment: Kokpit uses no Filament export or import action, the vendor routes stay registered by filament/actions, and an explicit binder runs before implicit model binding (Router::substituteBindings), so the unused routes answer 404 without querying the absent `exports` and `imports` tables; Filament's own migrations are not published because they create integer keys against the UUID v7 convention. The closed entries of RouteRules (plan 12-01) already declare status 404. Presented to the owner in plan 12-08 (Open Question 5).
