Rulings made in this plan (recorded; R-13-04-1 and R-13-04-2 were R-13-01-6 and R-13-01-9 before the owner-approved split of plan 13-01):
- R-13-04-1 (logo): `DocumentImage::contents(string $path): ?string` is a public read of a stored document image that reuses the private path-pattern check and returns null for a foreign path or a missing object. `App\Domain\Notifications\Mail\MailLogo::fromPng(string $png): ?array{png: string, width: int, height: int}` decodes with GD, scales down (never up) to fit 360 x 120 px keeping alpha, re-encodes as PNG and returns the display size that fits 180 x 60 (never enlarged); any GD failure returns null. `MailBrand::read()` fills `logoPng`, `logoWidth` and `logoHeight` (declared null by plan 13-01) from `logo_path` through both, inside its existing system-context read and fallback. The HTML header in `message.blade.php` emits `<img src="cid:kokpit-logo.png" alt="{name}" width height>` only when `hasLogo()`, otherwise the name as text (plan 13-01's branch). `App\Domain\Notifications\Mail\EmbedMailLogo::handle(MessageSending $event): void` embeds the same memoised bytes with `$event->message->embed($png, MailBrand::LOGO_NAME, 'image/png')` only when the HTML body is a string containing the cid reference; it returns nothing (a false return would cancel the send). Registered in `AppServiceProvider::boot()` with `Event::listen(MessageSending::class, EmbedMailLogo::class)` (domain folders are not auto-discovered). No route, no hosted URL, no data URI (research: T-10-07 and the Phase 12 public-route audit).
- R-13-04-2 (escaping): `App\Domain\Notifications\Mail\MailText::escapeMarkdown(string $text): string` is the body of the current private helper of `TaskNotification`, moved unchanged (whitespace collapsed, backslash, backtick, asterisk, underscore, brackets, parentheses, hash, pipe, tilde and exclamation mark escaped). `MailText::unescapeMarkdown(string $text): string` removes exactly one backslash in front of exactly those characters. The published text layout runs the stripped header, slot, subcopy and footer through `unescapeMarkdown()`, so the plain-text part reads as written (research Pitfall 5). `TaskNotification` calls `MailText::escapeMarkdown()` and keeps no copy of its own.
- R-13-04-3 (text views): re-run `ddev exec php artisan vendor:publish --tag=laravel-mail` without `--force` (existing files are kept, so the customised html files of plan 13-01 stay), keep `text/layout`, `text/message` and `text/header`, and delete again every other copy the publish brings back (the text button, panel, subcopy, table and footer, and the html button, panel, subcopy, table and `themes/default.css` that plan 13-01 removed), so the kept set is exactly R-13-01-1 plus these three. `text/message` mirrors the html header and footer lines from `MailBrand::current()` with the `mail_layout` labels, each line only when it has content; `text/header` prints the slot, and the URL only when one is given; `text/layout` passes the stripped header, slot, subcopy and footer through `MailText::unescapeMarkdown()`.
- R-13-04-4 (logo fixture): `Tests\Support\MailFixtures::storeLogo(int $width, int $height): string` draws a PNG with GD at runtime, uploads it through `DocumentFixtures::upload()` and `DocumentImage::store(..., 'logo')` as the system, saves it as `SupplierSettings::logo_path`, then calls `app()->forgetScopedInstances()`, and returns the stored path. No binary in git.
