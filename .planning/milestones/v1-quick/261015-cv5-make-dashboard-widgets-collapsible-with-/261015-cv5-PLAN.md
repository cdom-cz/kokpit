<objective>
Make every dashboard widget card collapsible on its own, with the state stored per user in the database the moment it is toggled. This implements the todo `2026-10-15-collapsible-dashboard-widgets-persisted-in-db.md` with the locked decisions of `261015-cv5-CONTEXT.md`:

- Collapsed look: the title plus one key figure.
- The Partner widgets get the same shared wrapper, and a Partner may store state only for widgets a Partner can see. This is enforced server side.
- Storage is a dedicated table. It has a UUID v7 key, a FK to users, a unique pair (user, widget key) and a DB check on the allowed keys.
- A toggle is written immediately through a Livewire action authorised for the signed-in user only. The UI is optimistic, silent on success, and shows a small error toast on failure. New users start expanded.

Purpose: the owner wants to fold away the cards he does not need right now, and keep that choice across reloads and devices. A Partner gets the same comfort without any new way to reach Admin data.

Output: the preference table, the Dashboard domain (enum, model, policy, Action, query), the shared Livewire trait and Blade card, all six widgets moved onto the card, the tests, the CONTRIBUTING note, and the todo moved to completed.
</objective>

- Versions: Filament 5.10.2, Livewire 4.4.7, Laravel 13. Livewire runs trait hooks named after the trait: `boot<Trait>` on every request and `mount<Trait>` on the first one. `#[Livewire\Attributes\Renderless]` skips the re-render but still returns the value to `$wire.method()` and still sends dispatched effects, including Filament notifications. `#[Livewire\Attributes\Locked]` refuses client writes to a property. Tests have `->assertReturned($value)` (Livewire) and `->assertNotified($title)` (Filament).
- `EnforcesWidgetAccessRule::bootEnforcesWidgetAccessRule()` aborts 403 before mount and before any method call on every request. So a Partner never reaches the mount hook or the store method of an Admin widget. The two Partner widgets also refuse the Admin in `canView()`.
- Widget views: `Widget::render()` returns `view($this->view, $this->getViewData())`, and `protected string $view` can be overridden on every widget, `TableWidget` and `StatsOverviewWidget` included. - PITFALL: `TableWidget::makeTable()` sets a fallback heading made from the class name ("Unbilled Per Client") whenever `getTableHeading()` is null. A table that should show no heading of its own must call `->heading(null)` explicitly in `table()`. Simply dropping the `->heading(...)` call brings the English class-name heading back.

- `widget_key` string(64).
- `collapsed` boolean, not null, no default.
- `timestampsTz()`.
- A named unique constraint `dashboard_widget_preferences_user_widget_unique` on (user_id, widget_key). It also serves as the index of the FK.
- A named CHECK `dashboard_widget_preferences_widget_key_check` that limits widget_key to exactly `hours_stats`, `today_plan`, `unbilled_per_client`, `upcoming_deadlines`, `partner_tasks` and `partner_projects`.
