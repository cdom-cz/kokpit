## Decisions taken in this plan (there is no CONTEXT.md; the review left these open)

- CR-01: refuse the deletion instead of storing a tombstone. A tombstone needs a new table or column (a
  migration, a model, a canary fixture, isolation tests); the refusal needs none and fully removes the
  resurrection. The refusal applies only while the template still fires today; a switched-off or deleted
  template, a past day and every ordinary task stay deletable. The user's way to skip a recurring task
  today is to switch the template off in the settings.
- WR-07: do not refuse the template save. The invariant "at most three main and three medium tasks a day"
  is enforced where rows are created: Add and Update (with reserved slots) and now Materialize (count the
  day under the day lock; an overflowing template task becomes grey instead of a fourth coloured task).
- WR-05: save the changed recap on navigation instead of asking for confirmation; the save is idempotent
  and a refused save keeps the user on the week with the text intact.
- IN-02: the limit is 5000 characters, enforced in the Action and as `maxlength`; no database CHECK,
  because that would be a migration.
- WR-03 test: a lock probe from a second connection instead of a multi-process race test, because the
  property to prove is "the Action takes the lock", which the probe shows deterministically and in one
  process.
- No migration is needed for any finding. The migrations stay unchanged.
