<objective>
Add an hourly safety net to the scheduler: an artisan command that ends every running time entry which has run
longer than 48 hours. Owner request: "Add a safety net to the scheduler: a command, every hour. A running entry that
runs longer than 48h gets ended. Such entries will only ever be inserted manually."

Settled design (all points of the request brief):
1. The threshold is config only: `kokpit.time.max_running_hours` = 48, next to the sibling `long_running_hours`
   (which has no env either). No magic number in code.
2. An overrun entry is ended at `started_at + threshold`, NOT at now. So the stored duration is exactly the threshold
   (172800 s) and the generated integer column `duration_seconds` cannot overflow (SQLSTATE 22003 above
   2147483647 s). The Action does not reuse StopTimer, whose `max(now, started_at)` end would overflow for an entry
   decades old. Because the start is more than the threshold before now, `started_at + threshold` is always before
   now and always after the start, so `time_entries_end_check` holds.
3. Immutability: only rows with `ended_at IS NULL` are written. A billed entry cannot be running
   (`time_entries_billed_finished_check`), and the Action also filters `billing_state = unbilled` in its locked
   re-read, so it can never reach the frozen-row guard (KP001).
4. Idempotent and safe under repeated and concurrent runs: `onOneServer` on the schedule, then one transaction per
   entry that takes the owner's `TimerLock` first (the documented lock order: timer lock, then the running entry
   FOR UPDATE) and re-reads the row with `ended_at IS NULL`, `billing_state = unbilled` and the start still before
   the cutoff. A row stopped, edited or ended by anyone in between is skipped.
5. Trace: the end is written by a model save (`forceFill` plus `save`, exactly like StopTimer). `TimeEntry` logs
   `ended_at` through its activity allowlist, so each ended entry gets one `updated` activity row with source
   `console`. That is the existing convention for ended_at changes. The command prints one line with the threshold
   and the count only.
6. Scheduled hourly in `routes/console.php` with `->name('kokpit-end-overrun-timers')` and `->onOneServer()`.
7. Pest feature tests with a frozen clock (the LongRunningTimerTest pattern).

This narrows Phase 06 D-07 ("the timer is never stopped automatically") on the owner's explicit request. The
12-hour bell notice (NotifyLongRunningTimers, TI-09) stays exactly as it is and still never stops a timer. Only an
entry running more than 48 hours is ended, by the separate safety net.

Purpose: a forgotten or hand-inserted running entry can no longer run for ever, inflate unbilled time, or overflow
the duration column.
Output: `EndOverrunTimers` Action, `kokpit:time:end-overrun` command, the hourly schedule entry, config key, Czech
summary line, `EndOverrunTimersTest`, and updated docs plus a STATE.md decision.
</objective>
